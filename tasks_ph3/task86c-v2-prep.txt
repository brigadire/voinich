Task86C-v2-prep — G1-v2 Distributed Execution and Evidence
Infrastructure Readiness


PURPOSE

Implement and validate the computational infrastructure required
to execute the frozen Task86C-v2 blind scientific experiment.

Task86C-v2-prep is an ENGINEERING / EXECUTION-READINESS task.

It must transform the frozen Task85b execution design into a
working distributed system capable of executing the future
Task86C-v2 scientific manifest without modifying the scientific
contract during the blind experiment.

The task must:

1. implement the G1-v2 scientific-manifest / DAG adapter;

2. integrate it with the existing Phase-I mTLS lease executor;

3. implement the immutable evidence-bundle/result layer;

4. implement the evidence-only decision-path verifier;

5. validate cross-node deterministic execution;

6. validate restart/resume/retry semantics;

7. validate duplicate/conflict/corruption handling;

8. benchmark horizontal scalability;

9. estimate practical compute capacity for Task86C-v2;

10. prove that the resulting infrastructure is ready for the
    large blind scientific computation.

Task86C-v2-prep MUST NOT execute the Task86C-v2 blind scientific
control experiment.

Primary terminal question:

    Can the frozen G1-v2 experiment now be executed as a
    large distributed computation without changing its
    scientific definitions, evidence contract, or execution
    semantics?

======================================================================

    PREDICTIVE
    GENERATION
    STRUCTURAL
    AGGREGATION

plus any frozen reachability/evidence jobs required by Task85b.

======================================================================
7. SCIENTIFIC MANIFEST IS CANONICAL
======================================================================

The scientific manifest is the sole authority for:

    which jobs exist;
    job dependencies;
    inputs;
    code/config hashes;
    seeds;
    expected outputs;
    scientific reachability.

The executor may decide:

    where;
    when;
    in what order

a ready job runs.

It may NOT decide:

    whether a scientific job should exist;
    whether a model passes;
    whether a downstream scientific stage is relevant.


======================================================================
8. DETERMINISTIC JOB IDENTITY
======================================================================

Implement the Task85b JobID contract.

Scientific JobID must depend only on the frozen scientific job
configuration and its dependencies.

It must NOT depend on:

    worker hostname;
    IP address;
    worker certificate identity;
    lease ID;
    attempt number;
    execution time;
    scheduling order.

The identical scientific job submitted to different workers must
have the identical JobID.


======================================================================
9. IMMUTABLE JOB BUNDLE
======================================================================

Each leased job must receive an immutable bundle containing at
minimum:

    job_id;
    experiment/protocol version;
    stage;
    corpus/input IDs;
    model/candidate identity;
    scale/replicate where applicable;
    seed where applicable;
    input hashes;
    dependency hashes;
    executable/code hash;
    scientific config hash;
    expected output schema.

Worker must validate the bundle before execution.


======================================================================
10. WORKER SCIENTIFIC ISOLATION
======================================================================

Workers are execution engines.

Workers MUST NOT:

    alter scientific configuration;
    derive thresholds;
    select candidates;
    modify seeds;
    modify corpus splits;
    apply final scientific gates;
    choose a preferred duplicate result.

Workers return facts/evidence.

Scientific decisions belong to the frozen verifier/aggregator.


======================================================================
11. EVIDENCE BUNDLE IMPLEMENTATION
======================================================================

Implement the Task85b immutable evidence bundle.

Every result must contain or reference:

    producing JobID;
    input hashes;
    dependency hashes;
    code hash;
    config hash;
    seed;
    schema version;
    scientific status;
    produced artifact hashes.

Evidence must be content-addressed.

Publication must be atomic:

    temporary output
        ↓
    schema/hash validation
        ↓
    content-addressed publication
        ↓
    verified JobID index.

======================================================================
13. NOT_REACHED SUPPORT
======================================================================

Every planned downstream scientific cell must be representable as:

    result evidence

or:

    NOT_REACHED
        reason
        upstream gate/job
        dependency hash.

Missing output is not equivalent to NOT_REACHED.

Executor interruption must not produce NOT_REACHED.

Only frozen scientific reachability rules may do so.


======================================================================
14. EVIDENCE-ONLY VERIFIER
======================================================================

Implement the production evidence-only verifier specified by
Task85b.

The verifier must consume frozen evidence records and registries.

It MUST NOT invoke:

    fitting;
    induction;
    corpus generation;
    model execution.

It must reconstruct:

    individual PM gates;
    PredictiveAdequacy;
    F2 metric/family/scale gates;
    StructuralAdequacy;
    complexity/minimality;
    final verdict.

15. VERDICT REGENERATION

    originally aggregated verdict

    evidence-only regenerated verdict.

======================================================================
23. RESUME TEST
======================================================================

Create a representative multi-stage engineering manifest.

Run part of it.

Interrupt the coordinator.

Restart.

Required:

    verified jobs are not recomputed;
    unfinished jobs resume/requeue;
    dependency state is reconstructed;
    final result is identical to uninterrupted execution.


======================================================================
24. WORKER LOSS TEST
======================================================================

Terminate/disconnect a worker while it owns a lease.

Verify:

    lease expires;
    identical JobID becomes available;
    another worker executes it;
    no scientific failure is recorded merely because worker died;
    no duplicate scientific job identity is created.


======================================================================
25. INFRASTRUCTURE RETRY
======================================================================

Infrastructure failures may retry.

Examples:

    worker lost;
    SSH/network interruption;
    process killed externally;
    result transfer interrupted;
    temporary storage failure.

Retry must use the identical JobID and scientific bundle.


======================================================================
26. SCIENTIFIC FAILURE NO-RETRY
======================================================================

Engineering fixtures must demonstrate that statuses representing
scientific outcomes are not automatically retried merely to obtain
a different result.

Examples:

    TRAINING_FAILED;
    INDUCTION_LIMIT_REACHED;
    CONVERGENCE_FAILED;
    NUMERICALLY_UNSTABLE;
    METRIC_UNAVAILABLE.

They are evidence, not infrastructure errors.


======================================================================
27. DUPLICATE EXECUTION
======================================================================

    accept one scientific result identity;
    preserve provenance for all copies;
    record reproducibility confirmation.

Do not discard duplicate provenance.
