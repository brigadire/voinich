Task85c-a — A17 Evidence Schema Status Enforcement Repair
and Controlled Contract Refreeze


PURPOSE

Repair the machine-enforceable A17 scientific evidence schemas after
Task86C-v2-scientific-impl-R demonstrated that the frozen Task85c
schemas admit status/evidence combinations forbidden by the normative
G1-v2 scientific contract.

This is a:

    CONTRACT DEFECT CORRECTION
    SCHEMA ENFORCEMENT REPAIR
    EXHAUSTIVE CONFORMANCE AUDIT
    CONTROLLED REFREEZE

task.

It is NOT:

    a G1-v2 redesign;
    a model redesign;
    a status-semantics redesign;
    a reachability redesign;
    a DAG redesign;
    threshold tuning;
    implementation of production handlers;
    scientific execution;
    blind execution;
    natural-language confirmatory execution;
    Voynich evaluation.


======================================================================
1. DEFECT BEING REPAIRED
======================================================================

Task86C-v2-scientific-impl-R stopped with:

    CONTRACT_DEFECT =
        A17_STATUS_SCHEMA_CONTRADICTION

    TASK86C_V2_SCIENTIFIC_EXECUTION_READY =
        NOT_SUPPORTED

    TERMINAL_MARKER =
        TASK86C_V2_TASK85C_CONTRACT_DEFECT

The demonstrated defect is that the frozen A17 evidence schemas do
not enforce the normative status semantics.

Known reproductions include:

    not_reached.schema.json
        accepts status = PASS

    fit.schema.json
        accepts status = FAIL

and:

    x-status-rules

is not a standard JSON Schema enforcement keyword.

Therefore two implementations can differ:

    implementation A:
        treats x-status-rules as normative custom validation

    implementation B:
        uses a standard JSON Schema validator and accepts documents
        forbidden by the scientific contract.

This violates independent implementability.

======================================================================
11. STANDARD JSON SCHEMA ENFORCEMENT
======================================================================

Scientifically normative restrictions MUST be expressible through
standard validation semantics of the selected JSON Schema dialect.

Do not rely on unknown extension keywords such as:

    x-status-rules

for enforcement.

Custom annotation keywords may remain for documentation only if they
have no normative enforcement role.


======================================================================
12. JSON SCHEMA DIALECT
======================================================================

Freeze the exact JSON Schema dialect used by G1-v2 evidence.

Every schema must declare the appropriate:

    $schema

and, where appropriate:

    $id.

The validator must verify dialect identity.

Do not leave validator behavior dependent on library defaults.


======================================================================
13. STANDARD KEYWORDS
======================================================================

Use standard schema mechanisms such as, where appropriate:

    const
    enum
    oneOf
    anyOf
    allOf
    not
    if
    then
    else
    required
    properties
    additionalProperties
    unevaluatedProperties
    dependentRequired

according to the frozen dialect.

Do not introduce custom scientific validation semantics where
standard JSON Schema can express the rule.


======================================================================
14. STATUS-SPECIFIC BRANCHES
======================================================================

For evidence types supporting multiple statuses, encode the allowed
status-specific document shapes explicitly.

Conceptually:

    oneOf:
        status PASS shape
        status FAIL shape
        status NOT_ASSESSABLE shape
        ...

where applicable.

A document must not validate against a branch representing a
scientifically different status.


======================================================================
15. SINGLE-STATUS EVIDENCE TYPES
======================================================================

Evidence types that scientifically permit only one status must
enforce that status with a standard keyword such as:

    const

or an equivalent standard construct.

For example, if the normative contract permits only:

    NOT_REACHED

for `not_reached` evidence, then:

    status = PASS

must be rejected by the schema itself.


======================================================================
16. REQUIRED/FORBIDDEN FIELD SEMANTICS
======================================================================

Status enforcement is not limited to the `status` field.

For every allowed status verify the associated payload.

Examples of defects to search for:

    PASS without required metric value;
    FAIL without required comparison evidence;
    NOT_ASSESSABLE carrying a forbidden PASS result;
    NOT_REACHED carrying computed scientific outputs;
    scientific failure carrying ordinary adequacy evidence;
    final verdict containing incompatible reason/status fields.

Do not freeze schemas that validate semantically impossible hybrids.


======================================================================
17. NULL VS ABSENT
======================================================================

Preserve Task85c canonical null/absence rules.

Do not repair schemas by making every field nullable.

For each status-specific field determine whether it must be:

    PRESENT with value;
    PRESENT as null;
    ABSENT.

Encode the frozen distinction.


======================================================================
18. ADDITIONAL PROPERTIES
======================================================================

Audit whether schemas currently allow undeclared fields that can
carry contradictory scientific information.

Where required for canonical evidence closure, reject scientifically
undefined properties using the selected standard schema mechanism.

Do not allow a document to smuggle a second scientific outcome
through an unvalidated property.

    every evidence schema
        ×

======================================================================

if the audit discovers another contradiction that cannot be repaired
as enforcement of already frozen semantics.

    TASK85C_A_SCIENTIFIC_CHANGE_REQUIRED

if resolving A17 requires changing scientific meaning.

    TASK85C_A_SCHEMA_REPAIR_INVALID

if standard JSON Schema cannot enforce the frozen matrix as designed,
tests fail, or closure is incomplete.

Do not silently broaden the repair.

======================================================================

validator, without knowledge of custom x-status-rules, necessarily
accepts every and only the evidence/status representations permitted
by the frozen G1-v2 scientific semantics.
