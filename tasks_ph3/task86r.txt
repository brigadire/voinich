Task86R — G1 Token-Formation Grammar Confirmatory Execution

Цель

Выполнить заново G1-эксперимент Phase III по полностью
замороженному executable contract Task85-v1.1 и получить
confirmatory ответ на вопрос:

    Какой минимальный класс формальной генеративной модели
    достаточен для объяснения TOKEN FORMATION Voynichese?

Task86R является:

    CONFIRMATORY EXECUTION TASK.

Task86R НЕ является:

    design task;
    exploratory model-development task;
    hyperparameter-search design task;
    metric-development task.

Все algorithms, grids, thresholds, calibration procedures,
seeds, stability rules, adequacy gates и verdict mappings
должны наследоваться из Task85 + Task85a без изменений.

Основные возможные научные результаты:

    G1_MINIMAL_CLASS =
        M0 / M1 / M2 / M3 / M4 / M5
        / INCONCLUSIVE / NONE

    TOKEN_FORMATION_DEPTH =
        FREQUENCY_ONLY
        / LOCAL_MARKOV
        / VARIABLE_MEMORY
        / FINITE_STATE
        / EXPLICIT_RULE_SYSTEM
        / NOT_IDENTIFIABLE

    EXPLICIT_RULE_GRAMMAR_REQUIRED =
        SUPPORTED
        / NOT_SUPPORTED
        / INCONCLUSIVE.

Финальный experiment marker:

    TOKEN_GRAMMAR_FROZEN

если confirmatory experiment валиден и завершён.

Если выполнение невозможно без изменения frozen
scientific contract:

    TASK86R_EXPERIMENT_BLOCKED.

execution:

23. PM5
======================================================================

Использовать frozen top-label ECE.

Ten bins:

    [0,.1]
    (.1,.2]
    ...
    (.9,1.0].

Для каждого scored event:

    confidence =
        maximum predictive probability;

    predicted label =
        code-point-order tie-break;

    correctness =
        1 iff predicted == observed.

Вычислить ровно frozen PM5 functional.

Никакого adaptive binning.

======================================================================
25. PM6
======================================================================

Score whole TOKEN:

    log P(TOKEN | fitted G1).

Compute occurrence-weighted pooled ROC AUC:

    AUC =
      (wins + 0.5*ties)
      /
      (N_positive * N_negative).

Не агрегировать TOKEN types.
Не удалять duplicates.

Использовать frozen matched-pair bootstrap
только для reporting uncertainty.

======================================================================
32. CONVERGENCE
======================================================================

Начиная с checkpoint 8,
для каждой applicable metric/scale сравнить
median с предыдущим checkpoint.

Pass iff:

    abs(current - previous)
        <=
    1e-4
        +
    0.01 * max(abs(current), abs(previous)).

Stop после двух consecutive passing comparisons.

Earliest stop:

    16.

Если к 32 convergence отсутствует:

    NON_CONVERGED
        →
    NUMERICALLY_UNSTABLE.


======================================================================
33. RUN VARIATION
======================================================================

На 32 replicates вычислить frozen CV.

Если:

    mean != 0:
        sample_sd / abs(mean)

иначе:

        sample_sd.

Value > 0.25:

    excessive run variation

с последствиями согласно frozen failure contract.

======================================================================
38. CROSS-TRANSCRIPTION STABILITY
======================================================================

Для effect e относительно baseline:

    D =
      abs(e_ZL3b - e_IT2a)
      /
      max(
        abs(e_ZL3b),
        abs(e_IT2a),
        1e-12
      ).

Classify exactly:

TRANSCRIPTION_STABLE:

    direction agrees
    AND
    D <= 0.20.

DIRECTION_STABLE:

    nonzero direction agrees
    AND
    D > 0.20.

TRANSCRIPTION_SENSITIVE:

    direction differs
    OR
    either value nonfinite
    OR
    exactly one value zero.

40. MINIMALITY
======================================================================

Minimality вычислить отдельно
для ZL3b и IT2a.

Рассматривать только candidates,
прошедшие обе adequacy gates.

Primary quantity:

    Complexity(G).

Candidates equivalent when:

    abs(C_a - C_b)
        <=
    max(
        1 bit,
        1e-6 * min(C_a,C_b)

Within equivalent set prefer:

    lower model rank M0...M5

then:

    candidate id.

Не объединять complexity
двух transcriptions.

42. MODEL LADDER
======================================================================

    M2 → M3
    M2 → M4

======================================================================
43. FINITE-STATE PARENT
======================================================================

M3 и M4 сравнить согласно
frozen minimality rule.

Если оба adequate:

    использовать adequate result
    с меньшей transcription-specific
    description length.

Если neither adequate:

    сравнить M5 с M2

и явно записать skipped finite-state edge.

Не создавать новый intermediate model.


======================================================================
44. REPRESENTATIONAL GAIN
======================================================================

`REPRESENTATIONAL_GAIN = SUPPORTED`
только если child:

    passes both adequacy gates;

    lowers total description length
    beyond maximum applicable MFC q0.95
    improvement threshold;

    does so on both transcriptions;

    is at least direction-stable;

    regresses no structural family.

Exact equality:

    NOT SUPPORTED.

Missing/nonfinite required measurement:

    INCONCLUSIVE.


======================================================================
45. TOKEN FORMATION DEPTH
======================================================================

Применить frozen mapping:

    M0 → FREQUENCY_ONLY
    M1 → LOCAL_MARKOV
    M2 → VARIABLE_MEMORY
    M3/M4 → FINITE_STATE
    M5 → EXPLICIT_RULE_SYSTEM.

Return:

    NOT_IDENTIFIABLE

если:

    no adequate candidate;
    transcription classes differ;
    required ladder edge is INCONCLUSIVE;
    selected-class gain over parent
        is unsupported.


======================================================================
46. EXPLICIT RULE GRAMMAR
======================================================================

Set:

    EXPLICIT_RULE_GRAMMAR_REQUIRED = SUPPORTED

только если M5:

    passes both adequacy gates

AND

    beats every adequate M0–M4 candidate
    under frozen gain rule.

Set:

    NOT_SUPPORTED

если существует adequate M0–M4 candidate
и ни один M5 не превосходит его
по frozen rule.

Иначе:

    INCONCLUSIVE.


======================================================================
47. INTERPRETATION BOUNDARY
======================================================================

Даже:

    EXPLICIT_RULE_GRAMMAR_REQUIRED = SUPPORTED

НЕ означает:

    Voynichese is natural language;
    COMPONENT = morpheme;
    M5 rules = linguistic grammar;
    manuscript contains plaintext;
    manuscript contains semantics.

Это означает только:

    simpler frozen G1 model classes
    were insufficient to explain the
    preregistered TOKEN-formation evidence.

58. TASK87 READINESS
======================================================================

TASK87_READY может быть SUPPORTED,
если Task86R experiment валиден и существует
научно корректный frozen G1 result,
включая допустимый frozen viable set.

`INCONCLUSIVE` не обязательно блокирует Task87,
если Task85 nested-model contract позволяет
продолжить со всем equivalence set.

Но если:

    no usable G1 representation exists

или:

    experiment BLOCKED/INVALID,

то:

    TASK87_READY = NOT_SUPPORTED.

59. FINAL MARKER
======================================================================

Если confirmatory experiment полностью выполнен,
provenance/firewalls сохранены и результат frozen:

    TOKEN_GRAMMAR_FROZEN.

Этот marker допустим также для корректного
отрицательного/неидентифицирующего научного результата,
если frozen contract позволяет передать его дальше.

Если execution остановлен до получения
scientific evidence из-за невозможности
исполнить contract:

    TASK86R_EXPERIMENT_BLOCKED.

Если confirmatory integrity нарушена:

    TASK86R_EXPERIMENT_INVALID.

Не использовать BLOCKED/INVALID
как scientific verdict о Voynichese.
