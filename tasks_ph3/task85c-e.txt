Task85c-e — G1-v2 Blind Control Identity Boundary Resolution
and Execution-Identity Decoupling


PURPOSE

Resolve the execution-identity defect:

    EI01-BLIND-ID-ALGORITHM

discovered by:

    Task86C-v2-scientific-impl-R2R.

The frozen artifacts currently constrain blind-control construction
through both:

    G1V2-RNG-1

and:

    HMAC with a secret escrow key

without uniquely specifying their composition, exact truth-record
serialization, or HMAC message framing.

Multiple technically valid interpretations therefore produce
different:

    blind control_instance_id
        →
    concrete JobID
        →
    run-instance DAG identity.

Task85c-e must resolve this defect WITHOUT turning opaque execution
identifiers into scientific variables.

The task must establish a clean boundary between:

    SCIENTIFIC BLIND-CONTROL IDENTITY

and:

    OPAQUE EXECUTION IDENTIFICATION.

It must determine which properties must be frozen because they can
change scientific data or scientific verdict, and which properties
need only be deterministic, collision-safe, blind-safe and recorded
as implementation provenance.

This task is a narrow methodological repair.

It is NOT a new scientific design.

======================================================================
8. ESCROW ROLE
======================================================================

Explicitly determine the role of the escrow mechanism.

Escrow exists to:

    conceal truth during blind execution;
    commit the hidden truth;
    permit later authenticated recovery/unblinding.

Escrow MUST NOT determine the scientific content of the control
unless the existing scientific protocol explicitly requires that
behavior.


======================================================================
9. HMAC ROLE
======================================================================

Determine whether HMAC is scientifically normative or an
identity/blindness/integrity mechanism.

If changing only HMAC framing while preserving:

    identical scientific corpus;
    identical hidden truth;
    identical scientific RNG realization;
    identical blindness

cannot change scientific outcome, then HMAC framing MUST NOT be
classified as scientific semantics.


======================================================================
10. BLIND ID ROLE
======================================================================

Define:

    blind_id

as an opaque identifier unless contrary scientific necessity is
demonstrated.

The identifier must provide the properties actually required by the
protocol, such as:

    stable association;
    opacity;
    uniqueness/collision resistance;
    escrow lookup;
    auditability.

Its literal byte value must not itself carry scientific meaning.


======================================================================
11. SCIENTIFIC IDENTITY DECOUPLING
======================================================================

A scientific blind-control identity must be definable independently
of its opaque public identifier.

Conceptually:

    scientific_control
        =
    F(
        generator,
        parameters,
        scientific RNG identity,
        generated corpus,
        frozen scientific metadata
    )

while:

    blind_id
        =
    OPAQUE_ID(
        sealed truth / commitment material
    ).

Do not allow:

    blind_id → scientific RNG
    blind_id → generated corpus
    JobID → scientific RNG.


======================================================================
12. EXECUTION IDENTITY PRINCIPLE
======================================================================

Freeze the following methodological rule:

    Different opaque identifiers for otherwise scientifically
    identical run instances do not constitute different scientific
    experiments.

They MAY constitute different execution instances.

This distinction must be represented explicitly in provenance.


======================================================================
13. JOBID CONSEQUENCE
======================================================================

JobID is an execution identifier.

A change in JobID caused solely by:

    opaque blind ID;
    serialization;
    HMAC framing;
    run-instance materialization

does not constitute a scientific-result change if the underlying
scientific job identity is unchanged.

Therefore:

    concrete JobID set is RUN-INSTANCE PROVENANCE,

not a prerequisite scientific hypothesis.


======================================================================
14. JOBID SCIENTIFIC BINDING
======================================================================

JobID must nevertheless bind unambiguously to the underlying
scientific job for a concrete run.

For one materialized run:

    one job → one JobID.

Require:

    no collisions;
    no duplicate scientific job under different JobIDs inside the
    same frozen run;
    complete dependency closure.

These are execution-integrity requirements.


======================================================================
15. NO PRE-RUN CONCRETE JOBID REQUIREMENT
======================================================================

Remove any methodological requirement that the literal concrete
JobIDs of blind jobs be known before blind instances are
materialized.

What must be frozen beforehand is:

    scientific experiment;
    run-materialization procedure;
    JobID derivation procedure sufficient for execution integrity.

The resulting literal IDs are provenance of the materialized run.


======================================================================
16. BLIND-ID ALGORITHM
======================================================================

Define one implementation-level blind-ID algorithm sufficient for:

======================================================================
17. DEFAULT RESOLUTION
======================================================================

Unless contradicted by higher-precedence frozen scientific semantics,
use a simple explicit opaque-ID construction:

    truth_record =
        deterministic serialization of the minimum escrow lookup
        record required by the existing protocol

    blind_id =
        first 20 lowercase hex characters of
        HMAC-SHA256(
            escrow_key,
            domain_separator || framed_truth_record
        ).

The exact serialization/framing must be specified for
reproducibility of the run, but classified according to the
scientific-impact test.

23. REPRODUCIBILITY MODEL
======================================================================

Distinguish two kinds of reproducibility:

SCIENTIFIC REPRODUCIBILITY

    Another implementation can regenerate/evaluate the same
    scientific protocol and obtain statistically equivalent
    experiment behavior.

RUN REPRODUCIBILITY

    Given the archived run provenance and authorized escrow
    material, the exact concrete run can be reconstructed and
    audited.

Do not require the second to define the first.
