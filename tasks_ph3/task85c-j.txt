Task85c-j — G1-v2 M0 Additive-Smoothing Outcome-Space Resolution,
Scientific Golden Repair and Contract V1.2.x Refreeze


PURPOSE

Resolve the scientific-contract defect discovered by Task85c-h:

    H-SC03-M0-UNK-PROBABILITY-CONTRADICTION

and produce one complete, internally consistent and executable
scientific authority for M0 probability construction.

Task85c-h demonstrated that the currently frozen authorities cannot
simultaneously satisfy:

    M0-FIT

and:

    M0-UNSEEN

for the same M0 additive-alpha model.

For the frozen DEVELOPMENT fixture:

    tokens = ab, a
    alpha = 1

the mandatory inherited M0-FIT golden specifies:

    p(a)   = 0.375
    p(b)   = 0.250
    p(EOS) = 0.375

with:

    denominator = 8.

These probabilities sum to:

    1.000

and therefore leave:

    p(UNK) = 0.

At the same time:

    M0-UNSEEN

requires an unseen glyph mapped to UNK to have positive probability
when:

    alpha > 0.

The V1.2 M0 definition independently specifies the outcome space:

    {development glyphs, UNK, EOS}

and additive-alpha smoothing.

For the same fixture this gives:

    counts:
        a   = 2
        b   = 1
        UNK = 0
        EOS = 2

    number of outcomes = 4
    observed event count = 5

    denominator =
        5 + alpha * 4
        =
        9

and therefore:

    p(a)   = 3/9
    p(b)   = 2/9
    p(UNK) = 1/9
    p(EOS) = 3/9.

The two constructions cannot both be normative.

The choice changes:

    fitted-model bytes;
    predictive probabilities;
    RNG-to-symbol generation mapping;
    generated corpora;
    complexity inputs where dependent;
    candidate comparisons;
    potentially minimality and final verdict.

Therefore Task85c-j is a scientific-contract repair.

It MUST resolve and freeze the scientific semantics before
Task85c-h implementation resumes.

Task85c-j MUST NOT implement the production scientific executor.

Task85c-j MUST NOT perform production materialization.

Task85c-j MUST NOT inspect confirmatory outcomes or Voynich data.
