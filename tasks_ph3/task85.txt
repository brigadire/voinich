Task85 — Voynich Formal Grammar Experimental Design,
Baselines and Validation Contract

Цель

Подготовить и заморозить научный дизайн Line A Phase III:

    Voynich Generative Grammar
    and Information Residual.

Task85 НЕ должен строить окончательную грамматику Voynichese.

Task85 должен определить:

1. Что в Phase III операционально называется "grammar".

2. Какие уровни структуры должна уметь описывать grammar.

3. Какие model classes допустимо сравнивать.

4. Как corpus делится на discovery / validation / held-out
   без structural leakage.

5. По каким критериям grammar считается:
       predictive;
       structurally adequate;
       sufficient;
       minimal.

6. Как измеряется complexity grammar.

7. Какие baselines и null models необходимы.

8. Какие Fingerprint V2 metrics/families могут использоваться
   для независимой generative validation.

9. Как после freeze grammar будет определяться
   information residual.

10. Как будущие Task86–89 должны быть защищены
    от post-hoc tuning.

Финальный результат:

    GRAMMAR_EXPERIMENT_CONTRACT_FROZEN

или, если корректный экспериментальный дизайн
построить невозможно:

    GRAMMAR_EXPERIMENT_DESIGN_UNRESOLVED.

======================================================================
2. CENTRAL RESEARCH QUESTION
======================================================================

Основной вопрос Line A:

    Может ли наблюдаемая структура Voynichese
    быть описана компактной формальной
    генеративной системой, способной
    предсказывать ранее не использованные
    части корпуса?

Это НЕ вопрос:

    "Какова грамматика языка Войнича?"

и НЕ вопрос:

    "Что означает текст?"


======================================================================
3. OPERATIONAL DEFINITION OF GRAMMAR
======================================================================

Определить grammar G как:

    explicit generative model over observable
    transcription units and structural context

такой, что G задаёт вероятности и/или допустимость
наблюдаемых последовательностей и способен
генерировать новые последовательности.

Grammar должна иметь:

    formally specified representation;
    finite description;
    deterministic implementation given seed;
    computable likelihood/probability
        where model permits;
    generative sampling procedure;
    measurable complexity.

Запрещено определять grammar через
семантические предположения.


======================================================================
4. TERMINOLOGICAL NEUTRALITY
======================================================================

На этапе Task85 запрещено предполагать:

    glyph = character/letter;
    token = linguistic word;
    token component = morpheme;
    line = sentence;
    page = discourse unit;
    prefix = linguistic prefix;
    suffix = linguistic suffix.

Использовать нейтральные обозначения:

    GLYPH
    TOKEN
    COMPONENT
    POSITION
    CONTEXT
    STRUCTURAL_STATE.

Если используются термины prefix/suffix/stem,
явно маркировать их как формальные,
не семантические категории.


======================================================================
5. THREE GRAMMAR LEVELS
======================================================================

Зафиксировать три уровня будущего исследования.

G1 — TOKEN FORMATION

    P(token structure)

или эквивалентная generative representation.

G2 — CONTEXTUAL SEQUENCE

    P(token_i | local context, G1).

G3 — STRUCTURAL CONDITIONING

    P(token_i |
        local context,
        structural state,
        G1,
        G2).

Task85 должен определить,
какие observable variables разрешены
на каждом уровне.


======================================================================
6. G1 SCOPE
======================================================================

G1 должен исследовать минимум:

    glyph/component combinations;
    token length;
    internal position;
    formation constraints;
    edit-family relations;
    lexical paradigms;
    rare forms;
    unseen forms.

G1 не должен видеть:

    соседние tokens;
    line position;
    page;
    folio;
    section;

кроме информации, необходимой исключительно
для определения transcription unit.


======================================================================
7. G2 SCOPE
======================================================================

G2 может использовать:

    preceding tokens;
    following context only where prediction
        protocol makes this legitimate;
    local transition history;
    repetition state;
    short-range token context.

Не разрешать G2 использовать manuscript hierarchy,
иначе нельзя будет измерить incremental contribution G3.


======================================================================
8. G3 SCOPE
======================================================================

Candidate structural variables:

    position in physical line;
    line boundary;
    locus;
    page;
    folio;
    recto/verso;
    section;
    local regime;
    other Fingerprint V2 structural states.

Task85 должен провести applicability audit
и определить, какие из них допустимы
как conditioning variables.

Не включать variable только потому,
что она улучшает fit.


======================================================================
9. NESTED MODEL PRINCIPLE
======================================================================

Где возможно, обеспечить:

    G1 ⊂ G2 ⊂ G3

или определить строгий comparison mapping.

Это необходимо для измерения:

    Δ(G1 → G2)

и:

    Δ(G2 → G3).

Цель — понять, какой масштаб структуры
реально добавляет predictive information.


======================================================================
10. CORPUS AUTHORITY
======================================================================

Использовать только deterministic authoritative
Voynich corpora, утверждённые Task83b.

Минимум:

    ZL3b
    IT2a.

Все prepared corpora должны проходить
authoritative provenance verification.

Старые unresolved/invalid corpus artifacts
использовать запрещено.


======================================================================
11. TRANSCRIPTION POLICY
======================================================================

Одна transcription не должна использоваться
для выбора модели, а другая только для красивой проверки.

Task85 должен заранее определить роль:

    ZL3b
    IT2a

в discovery/replication protocol.

Предпочтительный принцип:

    model selection protocol одинаков
    для обеих transcription;

    primary conclusions require
    cross-transcription stability.

Определить статусы:

    TRANSCRIPTION_STABLE
    DIRECTION_STABLE
    TRANSCRIPTION_SENSITIVE.


======================================================================
12. DATA PARTITIONING
======================================================================

Random token split как единственный holdout запрещён.

Разработать hierarchical partition scheme.

Минимум рассмотреть:

    token holdout;
    line holdout;
    page holdout;
    folio holdout;
    section holdout.

Цель:

    предотвратить leakage локальных
    manuscript-specific patterns.


======================================================================
13. DISCOVERY / VALIDATION / CONFIRMATION
======================================================================

Разделить данные минимум на:

    DEVELOPMENT

    VALIDATION

    HELDOUT.

DEVELOPMENT:

    model construction;
    debugging;
    exploratory diagnostics.

VALIDATION:

    model-class selection;
    hyperparameter selection;
    complexity calibration.

HELDOUT:

    final confirmatory evaluation only.

HELDOUT нельзя открывать до model freeze.


======================================================================
14. STRUCTURAL SPLIT DESIGN
======================================================================

Task85 должен определить конкретный
детерминированный split manifest.

При split учитывать:

    Currier/section structure where authoritative;
    folio grouping;
    recto/verso pairing;
    page adjacency;
    local regimes;
    line adjacency.

Не допускать попадания почти идентичного
локального материала одновременно
в train и heldout через соседние loci.


======================================================================
15. SPLIT BALANCE
======================================================================

Проверить DEVELOPMENT / VALIDATION / HELDOUT на:

    token count;
    line count;
    folio count;
    section composition;
    token-length distribution;
    major transcription metadata;
    applicable F2 distributions.

Balance не должен достигаться
перестановкой individual tokens,
разрушающей manuscript structure.


======================================================================
16. SPLIT FREEZE
======================================================================

Создать:

    GRAMMAR_CORPUS_SPLIT.tsv
    GRAMMAR_CORPUS_SPLIT_MANIFEST.json

и marker:

    GRAMMAR_CORPUS_SPLIT_FROZEN.

После freeze запрещено менять split
по результатам grammar experiments.


======================================================================
17. MODEL-CLASS REGISTRY
======================================================================

До Task86 создать frozen registry
candidate model classes.

Минимум рассмотреть:

M0 — IID/token-frequency baseline

M1 — character/glyph n-gram

M2 — variable-order Markov

M3 — finite-state formation grammar

M4 — probabilistic finite-state grammar

M5 — component/rule formation grammar

M6 — contextual token model

M7 — hierarchical/state-conditioned model.

Конкретный состав должен быть обоснован Task85.

Не включать model class только потому,
что ожидается хороший fit на Voynich.


======================================================================
18. MODEL CLASS FAIRNESS
======================================================================

Для каждого class определить:

    inputs;
    accessible context;
    parameterization;
    training algorithm;
    hyperparameter space;
    generation algorithm;
    complexity measure;
    deterministic seed behavior;
    failure conditions.

Нельзя сравнивать модели,
если одна получает существенно больше
target information без явного учёта этого.


======================================================================
19. NEURAL MODEL POLICY
======================================================================

Neural language models могут использоваться
только как auxiliary predictive upper bound,
если это научно полезно.

Они не должны быть primary grammar,
если отсутствует заранее определённая:

    interpretable representation;
    comparable complexity measure;
    generation contract;
    residual accounting.

Цель Phase III — получить объяснимую
generative structure, а не максимальный predictor.


======================================================================
20. BASELINES
======================================================================

Определить обязательные baselines.

Минимум:

B0:
    IID glyph/token baseline.

B1:
    unigram token model.

B2:
    simple n-gram model.

B3:
    shuffled-token control.

B4:
    formation-preserving shuffled control,
    если может быть определён target-blind.

B5:
    natural-language controls.

Baselines должны позволять отличить:

    trivial frequency fit

от:

    genuine grammar structure.


======================================================================
21. NATURAL-LANGUAGE CONTROLS
======================================================================

Использовать уже provenance-valid controls,
где это возможно.

Если нужны дополнительные controls,
критерии их выбора должны быть
сформулированы до Voynich grammar comparison.

Контроли должны по возможности иметь
сопоставимый размер или использовать
scale-normalized protocol.


======================================================================
22. MESSAGE-FREE CONTROLS
======================================================================

Task85 должен определить baseline generators,
не содержащие сообщения:

    IID;
    Markov;
    constrained formation;
    shuffled grammar-like variants.

Это ещё НЕ Task89 message-free experiment.

Здесь они нужны для calibration:

    что означает "grammar detected"
    в корпусе, где известно,
    что семантического сообщения нет.


======================================================================
23. PRIMARY PREDICTIVE METRICS
======================================================================

Заморозить predictive metrics.

Рассмотреть минимум:

    held-out negative log likelihood;
    cross entropy;
    perplexity where meaningful;
    unseen-token probability;
    predictive calibration.

Не использовать только training likelihood.


======================================================================
24. STRUCTURAL VALIDATION METRICS
======================================================================

Grammar должна оцениваться также
по generative structural reproduction.

Провести applicability audit
Fingerprint V2.

Для каждой F2 metric определить:

    DIRECTLY_APPLICABLE_TO_G1
    DIRECTLY_APPLICABLE_TO_G2
    DIRECTLY_APPLICABLE_TO_G3
    GENERATION_APPLICABLE
    STRUCTURE_REQUIRED
    NOT_APPLICABLE.

Создать:

    GRAMMAR_F2_APPLICABILITY.tsv.


======================================================================
25. FAMILY-LEVEL VALIDATION
======================================================================

Не считать большое количество
коррелированных metrics независимыми доказательствами.

Evaluation должна агрегироваться
минимум на уровне:

    metric;
    family;
    structural scale.

Определить family-level success gates
до Task86.


======================================================================
26. GENERATIVE VALIDATION
======================================================================

Каждый candidate grammar,
допущенный до final validation,
должен уметь генерировать independent samples.

Для frozen model:

    G + seed_i → synthetic corpus_i.

Количество seeds/replicates определить Task85
по power/stability analysis,
не по Voynich fit.


======================================================================
27. GENERATED CORPUS SCALE
======================================================================

Определить правила размера synthetic corpus.

Не позволять модели получать преимущество
путём генерации удобного объёма данных.

Рассмотреть:

    matched-size generation;
    multiple corpus scales;
    convergence diagnostics.

Использовать опыт Task82a,
но не наследовать его параметры автоматически.


======================================================================
28. COMPLEXITY
======================================================================

Grammar complexity должна измеряться явно.

Рассмотреть:

    number of states;
    number of transitions;
    number of production rules;
    number of parameters;
    encoded model length.

Выбрать primary complexity measure
до grammar fitting.


======================================================================
29. DESCRIPTION LENGTH
======================================================================

Предпочтительно определить MDL-like accounting:

    L(G) + L(V | G).

Если используется MDL,
Task85 должен полностью определить:

    coding assumptions;
    parameter cost;
    model cost;
    residual cost;
    unseen-symbol handling.

Нельзя выбирать coding scheme
после получения grammar.


======================================================================
30. MINIMALITY
======================================================================

Определить operational criterion:

    GRAMMAR_MINIMAL.

Минимальность НЕ означает:

    модель с минимальным числом правил вообще.

Она должна означать:

    simplest model satisfying frozen
    predictive + structural adequacy gates.

Формально:

    G_min =
        argmin Complexity(G)

    subject to:

        PredictiveAdequacy(G)
        AND
        StructuralAdequacy(G).


======================================================================
31. SUFFICIENCY
======================================================================

Определить:

    GRAMMAR_SUFFICIENT.

Требовать минимум:

    held-out predictive improvement over baselines;
    cross-transcription robustness;
    generative reproduction of preregistered
        structural families;
    stability across seeds;
    stability across relevant held-out partitions.

Высокая likelihood сама по себе недостаточна.


======================================================================
32. OVERFITTING CONTROL
======================================================================

Обязательно измерять:

    train performance;
    validation performance;
    held-out performance;
    complexity.

Model с почти буквальным memorization corpus
не может считаться explanatory grammar.


======================================================================
33. LEXICON ACCOUNTING
======================================================================

Отдельно определить стоимость хранения lexicon.

Нельзя считать модель компактной,
если "grammar" мала,
но содержит огромный memorized vocabulary table.

Complexity должна включать:

    grammar
    +
    stored lexicon
    +
    exceptions.


======================================================================
34. EXCEPTION ACCOUNTING
======================================================================

Все special cases должны учитываться
как часть model complexity.

Запрещено:

    вручную добавлять исключения
    и не учитывать их стоимость.

Создать единый representation для:

    regular rules;
    lexical exceptions;
    structural exceptions.


======================================================================
35. UNSEEN FORMS
======================================================================

Grammar должна проверяться на способности:

    assign probability to unseen valid-like forms;

и:

    discriminate held-out observed forms
    from appropriate null/non-observed forms.

Task85 должен определить
target-blind negative-generation protocol.


======================================================================
36. NEGATIVE TOKEN CONTROLS
======================================================================

Создать метод генерации negative token sets.

Они должны быть matched минимум по:

    length

и по возможности:

    glyph frequency;
    component inventory.

Нельзя использовать очевидно невозможный random noise,
если он делает classification тривиальной.


======================================================================
37. EDIT-GRAPH VALIDATION
======================================================================

Использовать frozen edit-graph machinery
как один из structural validation channels.

Проверять:

    degree structure;
    neighborhood structure;
    family organization;
    paradigm organization;

где applicable.

Не оптимизировать grammar непосредственно
под final edit-graph score.


======================================================================
38. CONTEXTUAL GAIN
======================================================================

Для Task87 заранее определить:

    CONTEXT_INFORMATION_GAIN.

Например:

    predictive gain G2 over G1

при complexity adjustment.

Это позволит ответить:

    насколько token choice содержит информацию,
    не объяснимую одной token-formation grammar.


======================================================================
39. STRUCTURAL GAIN
======================================================================

Аналогично определить для Task88:

    STRUCTURAL_INFORMATION_GAIN

как преимущество G3 над G2
на held-out data с complexity adjustment.

Это ключевой тест того,
несёт ли manuscript position predictive information.


======================================================================
40. ABLATION CONTRACT
======================================================================

Определить обязательные ablations.

Минимум:

    remove token formation;
    remove local context;
    remove line position;
    remove hierarchy;
    remove lexical memory;
    remove state.

Конкретные ablations применяются
только к моделям, где имеют смысл.


======================================================================
41. INFORMATION RESIDUAL PREPARATION
======================================================================

Task85 НЕ вычисляет финальный residual.

Но должен определить,
что Task89 будет считать residual.

Предпочтительно:

    residual = information not predicted
               by frozen G_min.

Определить representation residual,
например через:

    surprisal sequence;
    coding residual;
    prediction errors;
    sampled-choice residual.

Не называть residual plaintext.


======================================================================
42. RESIDUAL ENTROPY CONTRACT
======================================================================

Определить candidate estimators:

    H(V | G)

или эквивалентную predictive/MDL quantity.

Estimator должен быть:

    applicable to held-out data;
    deterministic;
    bias-audited;
    scale-aware.

Final estimator freeze может произойти
до Task89, но его design должен быть
заложен Task85.


======================================================================
43. RESIDUAL STRUCTURE CONTRACT
======================================================================

Task89 должен иметь возможность проверить,
сохраняется ли структура в residual.

Task85 должен определить будущие tests минимум для:

    autocorrelation/dependence;
    local sequence;
    line position;
    page/folio;
    section;
    applicable F2 families.

Нужны matched residual nulls.


======================================================================
44. MESSAGE-FREE FUTURE EXPERIMENT
======================================================================

Определить boundary между:

    grammar fitting

и:

    message-free generation.

Task86–88 строят grammar.

Только после:

    G_min FROZEN

Task89 может выполнять:

    G_min + RNG → message-free corpora.

Нельзя выбирать G_min по тому,
насколько хорошо его message-free samples
совпадают с full Voynich target.


======================================================================
45. SEMANTICS FIREWALL
======================================================================

Никакие результаты Task85–89
не должны интерпретироваться через:

    proposed Voynich translations;
    candidate plaintext;
    semantic labels;
    presumed subject matter;
    illustrated page meaning.

Line A является structural experiment.


======================================================================
46. FONTANA FIREWALL
======================================================================

Не выбирать grammar representation
потому, что она напоминает Fontana mechanisms.

Task85–89 должны быть независимы
от того, поддерживает ли grammar
external-memory interpretation.

Fontana comparison происходит позднее,
после Line A freeze.


======================================================================
47. PHASE II MECHANISM FIREWALL
======================================================================

Не использовать:

    Task81/82 mechanism fit;
    Task83r distances;
    "natural closest";
    Fontana endpoint values;
    shorthand distances;
    extraction rankings

для выбора grammar class или thresholds.

Phase II может определять открытые вопросы,
но не target-fit design Line A.


======================================================================
48. HELDOUT SENTINEL
======================================================================

До первого доступа к HELDOUT создать:

    GRAMMAR_MODEL_SELECTION_FROZEN

и sentinel с:

    git commit;
    split manifest checksum;
    model registry checksum;
    metric registry checksum;
    complexity contract checksum;
    selected model/hyperparameters;
    generation settings;
    seed contract.

После sentinel model selection запрещён.


======================================================================
49. BUG POLICY
======================================================================

После heldout opening:

Implementation bug with unchanged
scientific semantics:

    document;
    fix;
    regression-test;
    recompute all affected models symmetrically.

Scientific-definition change:

    invalidate confirmatory run.

Не менять contract post-hoc.


======================================================================
50. DETERMINISM
======================================================================

Унаследовать требования Task83b.

При одинаковых:

    input;
    model;
    parameters;
    seed;
    code;

результат должен быть deterministic.

Проверить:

    process restart;
    map order;
    worker count;
    GOMAXPROCS;
    serialization order.


======================================================================
51. SEED CONTRACT
======================================================================

Для stochastic grammar training/generation
определить deterministic seed derivation.

Seed не должен зависеть от:

    job order;
    worker assignment;
    filesystem order;
    map iteration.

Запретить seed cherry-picking.


======================================================================
52. MODEL FAILURE
======================================================================

Заранее определить failure classes:

    TRAINING_FAILED
    NON_GENERATIVE
    NUMERICALLY_UNSTABLE
    HELDOUT_DEGENERATE
    COMPLEXITY_UNBOUNDED
    MEMORIZATION_DOMINATED
    STRUCTURAL_VALIDATION_FAILED.

Failed model нельзя тихо удалить
из comparison registry.


======================================================================
53. PILOT POLICY
======================================================================

Разрешены target-aware pilots только на DEVELOPMENT partition.

Их цель:

    runtime estimation;
    numerical stability;
    implementation validation;
    rough hyperparameter bounds.

Pilot results не могут использовать HELDOUT.

Все изменения design после pilots
должны произойти до design freeze.


======================================================================
54. POWER / STABILITY ANALYSIS
======================================================================

Определить:

    number of folds;
    number of seeds;
    number of generated corpora;
    corpus scale

на основании stability/convergence analysis.

Не выбирать количество replicates
по достижению желаемого p-value.


======================================================================
55. MULTIPLE TESTING
======================================================================

Если grammar validation включает
множественные hypothesis tests,
заранее определить correction policy
или family-level gate,
если correction неприменима.

Не принимать решение после просмотра p-values.


======================================================================
56. PRIMARY VS SECONDARY EVIDENCE
======================================================================

Разделить:

PRIMARY:

    held-out predictive performance;
    complexity-adjusted adequacy;
    preregistered structural families;
    cross-transcription robustness.
