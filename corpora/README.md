# Corpora

Task70 documents the four corpus-related directories in place; none of them
were physically moved, because `scripts/maintenance/run-full-analysis.sh` and
`run-normalization-analysis.sh` read them via hardcoded relative paths
(`data/ZL3b-n.txt`, `data_work/ZL3b-x7.txt`, `data_test/...`) and moving them
would have been pure churn for zero organizational benefit. This file is the
map; the bytes stay where the pipeline expects them.

All four directories are gitignored (`.gitignore`), so they exist only in
this working copy unless individually force-added — see
[docs/audit/TASK70_ISSUES.md](../docs/audit/TASK70_ISSUES.md) for why that
matters for reproducibility.

## `data/` — source corpus

Verbatim IVTFF (Intermediate Voynich Transliteration File Format)
transcriptions mirrored from `http://www.voynich.nu/data/000_README.txt`
(voynich.nu, René Zandbergen's project; `data/000_README.txt` is that exact
file). Contents: `CD2a-n.txt` (Currier–D'Imperio), `FG2a-n.txt` (FSG),
`GC2a-n.txt` (GC v101), `IT2a-n.txt` (Takahashi/Stolfi interlinear),
`RF1b-e.txt`/`RF1b-er.txt`, `VT0e-n.txt`, `ZL3b-n.txt` (the file the pipeline
actually consumes), `voyn_101.txt`, `AB.docx`.

- **Origin**: voynich.nu, IVTFF format version 2.0.
- **Transcription**: one file per transliteration scheme (Currier, FSG, v101,
  Takahashi/Stolfi, etc.); `ZL3b-n.txt` is Zandbergen's own.
- **Transformations**: none — these are the untouched source files. The
  pipeline's own derivative (`data_work/ZL3b-x7.txt`) is produced by the
  vendored `ivtt` tool, not by editing these.
- **Checksum**: none recorded in-repo. No per-file SHA256 exists for this
  directory; `docs/audit/PROVENANCE_AUDIT.tsv` marks corpus identity for
  early (pre-Task58) stages as UNKNOWN for this reason.
- **Licensing status**: **unknown** — `000_README.txt` documents provenance
  and format but bundles no license text. Real Task72 release blocker (see
  TASK70_ISSUES.md); not resolved here per Task70 §19.

## `data_test/` — control/comparison corpora

Non-Voynich corpora used as negative controls and comparative baselines by
`research/phase1/*` experiments and `research/phase1/corpus-transform`:

- `astafiev-1000-culinar-receipts*.txt` — Astafiev Russian culinary recipes
  (three variants: original, UTF-8, and a `codex_prepare`-normalized
  `-prepared.txt` with a `.prepare.json` provenance sidecar recording
  `input_sha256`, `tool_git_commit`, and `prepared_by`).
- `pg2097.txt` / `pg2097-2.txt` — Arthur Conan Doyle, *The Sign of Four*
  (Project Gutenberg, public domain; matches `experiments/doyle-sign-of-four-v1*`).
- `pg30795.txt` / `pg30795-mod.txt` — Longfellow, *The Song of Hiawatha*
  (Project Gutenberg, public domain; matches
  `experiments/longfellow-song-of-hiawatha-v1`).
- `msdos2.0.txt` — MS-DOS 2.0 manual text (matches `experiments/msdos-v2-0-v1`).
- `sa_viSNuzarman-paJcatantra*.txt`, `visnusahasranama*.txt` — Sanskrit
  Pañcatantra and Viṣṇusahasranāma texts.
- `transformed/` — corpus-transform output cache.

Per-file checksums live in the `.prepare.json` sidecars generated by
`cmd/codex_prepare`, not in a top-level manifest.

- **Licensing status**: Gutenberg texts (`pg2097*`, `pg30795*`) are public
  domain. Astafiev/Sanskrit texts have no license documentation in-repo —
  UNKNOWN, flagged in TASK70_ISSUES.md.

## `data_work/` — derived/working corpus

Pipeline-generated intermediates, not source material:

- `ZL3b-x7.txt` — the canonical corpus every Stage1-28 tool defaults to,
  produced by `./ivtt/ivtt -x7 data/ZL3b-n.txt data_work/ZL3b-x7.txt`
  (`scripts/maintenance/run-full-analysis.sh`).
- `ZL3b-x7.canonical.*` — `codex_orientation`/`codex_prepare` orientation
  variants (full-reverse, glyph-reverse, token-reverse), each with a
  `.transform.json` sidecar recording the exact transformation applied.
- `ivtt_output_*.txt`, `usage01.txt` — stray one-off tool-output files with
  no recorded provenance; LEGACY/SCRATCH per the repository inventory.

- **Transformations**: fully recorded per-file in the `.transform.json`/
  `.prepare.json` sidecars next to each output.
- **Checksum**: recorded per-file in those sidecars (`input_sha256`), not
  separately here.

## `ivtt/` — vendored transliteration tool

`ivtt.c` (C source) and a compiled `ivtt` binary — the IVTFF transliteration
tool from voynich.nu (`http://www.voynich.nu/software/`), vendored in-repo
and invoked directly by `scripts/maintenance/run-full-analysis.sh`.

- **Licensing status**: unknown — no license or copyright header found in
  `ivtt.c`. Same Task72 release-blocker category as `data/`.
