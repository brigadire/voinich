# Реализовать структурную нормализацию токенов

## Контекст

В проекте уже существуют следующие этапы анализа:

```text
исходный корпус
    → dictionary.yaml
    → tokens_analysis.yaml
    → structural_analysis.yaml

исходный корпус
    → sequence_analysis.yaml
```

`structural_analysis.yaml` содержит `equivalence_candidates` — пары токенов, сходство которых вычислено исключительно по структурному поведению:

* позиционное сходство;
* сходство распределения предшественников;
* сходство распределения последователей.

`sequence_analysis.yaml` является независимым baseline-анализом точных последовательностей исходных токенов.

Для raw-корпуса установлено:

```text
token_occurrences = 38887
lines             = 5371
transitions       = 33516
```

Точные межстрочные последовательности быстро исчезают:

```text
n=2: 2481 межстрочный повтор
n=3:  162
n=4:    1
n=5..8: 0
```

Цель следующего этапа — проверить гипотезу, что различные surface-токены могут занимать одну структурную позицию и поэтому скрывать повторяемость последовательностей.

Необходимо построить структурные классы токенов, создать нормализованный корпус и сравнить его последовательностные свойства с raw-корпусом и контрольными случайными нормализациями.

---

# 1. Новый инструмент

Создать отдельную программу:

```text
structural-normalize/
```

Основной запуск:

```bash
go run ./structural-normalize \
  -input data_work/ivtt_output_1786282555007.txt \
  -structural structural_analysis.yaml \
  -output normalized_corpus.txt \
  -classes structural_classes.yaml
```

Программа должна:

1. читать исходный корпус;
2. читать `equivalence_candidates`;
3. строить классы структурно эквивалентных токенов;
4. заменять соответствующие токены идентификаторами классов;
5. оставлять неклассифицированные токены неизменными либо заменять их отдельными singleton-ID в зависимости от режима;
6. сохранять карту нормализации.

---

# 2. Принципиальное ограничение

При построении классов запрещено использовать:

* n-граммы;
* `sequence_analysis.yaml`;
* сведения о повторяющихся последовательностях;
* edit distance;
* графическое сходство EVA;
* общие префиксы/суффиксы токенов;
* семантические предположения;
* сведения о страницах, иллюстрациях или разделах рукописи.

Классы должны строиться **только из структурного сходства, уже рассчитанного независимо в `structural_analysis.yaml`**.

Это необходимо, чтобы последующий рост повторяемости последовательностей являлся результатом эксперимента, а не частью процедуры построения классов.

---

# 3. Входные данные equivalence

Использовать поля каждого `equivalence_candidate`:

```yaml
token_a:
token_b:
similarity:
position_similarity:
left_context_similarity:
right_context_similarity:
```

Не считать pairwise similarity транзитивной эквивалентностью автоматически.

Из:

```text
A ~ B
B ~ C
```

не следует автоматически:

```text
A ~ C
```

---

# 4. Построение структурных классов

Не использовать простые connected components по графу `similarity >= threshold`.

Это может породить chaining effect:

```text
A ~ B = 0.82
B ~ C = 0.81
C ~ D = 0.83

A ~ D = 0.31
```

и ошибочно объединить все четыре токена.

Использовать консервативную кластеризацию.

Предпочтительный вариант первой реализации:

**complete-link clustering**.

Класс допустим только тогда, когда минимальное pairwise similarity внутри него не ниже заданного порога.

То есть:

```text
min(similarity(A,B) for all A != B in class) >= threshold
```

Если для пары токенов отсутствует рассчитанное similarity, считать такую пару несовместимой для complete-link объединения.

---

# 5. Пороговые режимы

Нельзя фиксировать единственный threshold.

По умолчанию выполнить анализ минимум для:

```text
0.70
0.75
0.80
0.85
0.90
```

CLI:

```text
-thresholds 0.70,0.75,0.80,0.85,0.90
```

Для каждого threshold строится независимый набор классов.

Это необходимо для анализа чувствительности результата к степени агрессивности нормализации.

---

# 6. Дополнительные component thresholds

Помимо общего `similarity`, позволить задавать минимумы отдельных компонентов:

```text
-min-position-similarity
-min-left-context-similarity
-min-right-context-similarity
```

По умолчанию не вводить дополнительных ограничений:

```text
0
```

Но сохранять значения в metadata.

Это понадобится для последующих экспериментов.

---

# 7. Минимальная частота токена

Не объединять слишком редкие токены без достаточной статистической поддержки.

Использовать тот же `min_token_count`, который применялся при построении equivalence candidates, либо прочитать его из metadata `structural_analysis.yaml`.

Если значение невозможно определить, default:

```text
10
```

Редкие токены остаются singleton.

---

# 8. Идентификаторы классов

Не использовать семантические имена.

Пример:

```text
C0001
C0002
C0003
...
```

ID классов должны быть детерминированными.

Например:

1. отсортировать классы по лексикографически минимальному токену;
2. присвоить номера по этому порядку.

Повторный запуск на тех же данных обязан давать те же ID.

---

# 9. Карта классов

Для каждого threshold создать:

```text
structural_classes_070.yaml
structural_classes_075.yaml
...
```

или один YAML с разделами по threshold.

Предпочтительно один файл:

```yaml
meta:
thresholds:

models:
  - threshold: 0.7

    stats:
      total_tokens: ...
      classified_tokens: ...
      singleton_tokens: ...
      classes: ...
      multi_member_classes: ...
      largest_class: ...
      token_occurrence_coverage: ...

    classes:
      - id: C0001
        members:
          - token: qokain
            count: ...
          - token: qokaiin
            count: ...

        size: 2

        min_similarity: ...
        mean_similarity: ...

        min_position_similarity: ...
        min_left_context_similarity: ...
        min_right_context_similarity: ...
```

Сохранять все исходные величины, позволяющие проверить создание класса.

---

# 10. Статистика нормализации

Для каждого threshold обязательно сохранять:

```yaml
raw_unique_tokens:
normalized_unique_symbols:

multi_member_classes:
tokens_in_multi_member_classes:

token_occurrence_coverage:
```

`token_occurrence_coverage`:

```text
число occurrences токенов, попавших в multi-member class
---------------------------------------------------------
общее число token occurrences
```

Это особенно важная величина.

Если normalisation затрагивает только 2% корпуса, отсутствие эффекта ничего не говорит.

Если затрагивает 80%, рост повторяемости может быть почти механическим.

---

# 11. Нормализованный корпус

Для каждого threshold создать корпус:

```text
normalized_070.txt
normalized_075.txt
normalized_080.txt
normalized_085.txt
normalized_090.txt
```

Сохранять:

* исходные границы строк;
* исходный порядок токенов;
* число строк;
* число token occurrences.

Должны выполняться:

```text
normalized token occurrences = raw token occurrences
normalized lines             = raw lines
normalized transitions       = raw transitions
```

Меняется только алфавит токенов.

---

# 12. Режим представления singleton-токенов

Добавить CLI:

```text
-singleton-mode preserve|class
```

Default:

```text
preserve
```

### preserve

Токены вне multi-member classes остаются исходными:

```text
qokedy C0017 daiin
```

### class

Каждому singleton присваивается собственный ID:

```text
C8123 C0017 C4421
```

Оба режима должны сохранять взаимно однозначную информацию.

Для основной серии использовать `preserve`.

# 13. Прогон sequence-analyze

После построения корпусов выполнить существующий `sequence-analyze` для каждого threshold.

Допускается:

* shell/helper script;

* небольшой orchestration command.

```text

sequence_analysis_080.yaml
sequence_analysis_085.yaml
sequence_analysis_090.yaml
```

Использовать совершенно одинаковые параметры `sequence-analyze`.

# 15. Основные измеряемые эффекты

Нас интересуют минимум четыре независимых эффекта.

## A. Межстрочная повторяемость

Изменение:

```text
cross_line_repeated_ngrams(n)
```

## B. Максимальная длина межстрочного повтора

```text
max_cross_line_sequence_length
```

## C. Coverage повторяющихся контекстов

Для каждого `k`:

```text
repeated_context_coverage
```

## D. Conditional entropy

Для каждого `k`:

```text
conditional_entropy
repeated_context_conditional_entropy
```

Не сводить эти показатели в один универсальный score на данном этапе.

---

# 16. Критически важный контроль: случайная нормализация

Сам факт объединения словаря автоматически увеличивает повторяемость.

Поэтому необходимо построить matched random baseline.

Для каждого structural threshold создать случайные модели, которые имеют:

* такое же число multi-member classes;
* те же размеры классов;
* то же число singleton;
* по возможности близкое распределение частот токенов внутри классов.

Не менять token occurrence counts.

---

# 17. Random baseline

Добавить параметры:

```text
-random-baselines 100
-random-seed 1
```

Default:

```text
100
```

Для каждого structural threshold создать 100 случайных вариантов группировки.

Не обязательно сохранять все нормализованные тексты, если анализ можно провести потоково или во временной директории.

Но результат каждого random run должен быть воспроизводим из:

```text
seed
threshold
run_number
```

---

# 18. Matching случайных классов

Простейшее полностью случайное перемешивание всех токенов недостаточно хорошее, потому что structural classes могут объединять токены схожей частоты.

Нужно как минимум контролировать частотный профиль.

Предлагаемый подход:

1. разбить eligible tokens на frequency bins;
2. при случайном формировании класса выбирать участников преимущественно из тех же bins, что и участники соответствующего structural class;
3. сохранять тот же размер каждого класса.

Допустимо использовать логарифмические bins по `count`, например:

```text
1–2
3–4
5–8
9–16
17–32
33–64
...
```

Но eligible tokens всё равно должны удовлетворять `min_token_count`.

Метод описать в output methodology.

---

# 19. Статистика относительно random baseline

Для каждой structural normalization и каждой метрики вычислить распределение 100 random baseline результатов.

Сохранять:

```yaml
structural_value:

random:
  mean:
  stddev:
  min:
  max:
  percentile_05:
  percentile_50:
  percentile_95:

z_score:
empirical_p:
```

Empirical p для эффекта "structural больше random":

```text
(number of random >= structural + 1)
------------------------------------
(random_runs + 1)
```

Для entropy, где интерес может представлять уменьшение, направление теста явно описать отдельно.

Не называть `p` доказательством какой-либо гипотезы о Войниче.

---

# 20. Особое внимание к уменьшению алфавита

Добавить простой baseline-индикатор:

```text
compression_ratio =
normalized_unique_symbols / raw_unique_tokens
```

При сравнении различных threshold всегда показывать его рядом с эффектами.

Это позволит видеть, насколько рост повторяемости объясним простым уменьшением числа различных символов.

---

# 21. Не использовать графическое сходство токенов

Очень важно:

```text
qokain
qokaiin
```

могут попасть в один класс только потому, что их structural similarity удовлетворяет алгоритму.

Нельзя использовать тот факт, что строки визуально похожи.

Иначе эксперимент перестанет быть независимым.

---

# 22. Не использовать sequence result при выборе threshold

Не выбирать "лучший threshold" по тому, при каком значении возникает больше длинных повторов.

Нужно выполнить заранее заданную сетку:

```text
0.70
0.75
0.80
0.85
0.90
```

и показать все результаты.

Иначе возникает selection bias.

---

# 23. Не оптимизировать классы под sequence metrics

После запуска sequence analysis запрещено:

* разбивать неудобные классы;
* объединять дополнительные классы;
* менять threshold;
* изменять similarity weights

для улучшения повторяемости.

Новый набор параметров в будущем должен считаться новым экспериментом и явно фиксироваться как таковой.

---

# 24. Валидация complete-link classes

Добавить проверки:

Для каждого multi-member класса:

```text
для каждой пары A,B:

similarity(A,B) >= threshold
```

Если нет — ошибка.

Также проверить:

* токен принадлежит максимум одному классу;
* все токены существуют в dictionary;
* member count совпадает с dictionary;
* классы детерминированы;
* ни один токен не теряется при нормализации.

---

Добавить unit tests минимум для:

1. двух токенов выше threshold;
2. двух токенов ниже threshold;
3. chaining case:

```text
A-B >= threshold
B-C >= threshold
A-C < threshold
```

A/B/C не должны автоматически оказаться одним complete-link классом;

4. класса из трёх взаимно совместимых токенов;
5. детерминированных class IDs;
6. сохранения числа tokens;
7. сохранения границ строк;
8. singleton preserve;
9. singleton class;
10. нескольких thresholds;
11. random classes с теми же class sizes;
12. deterministic random seed;
13. frequency-bin matching;
14. empirical p calculation;
15. сравнения raw/normalized sequence metrics.

После реализации:

```bash
go test ./...
go vet ./...
```

# 27. Что НЕ делать

На этом этапе не реализовывать:

* operator/operand inference;
* wildcard sequences;
* fuzzy n-grams;
* edit-distance grouping;
* EVA morphological grouping;
* semantic labels;
* ML;
* сравнение с программными языками;
* сравнение с естественными языками;
* визуальные карты страниц;
* оптимизацию clustering threshold по результатам sequence analysis.

# Цель эксперимента

Эксперимент должен ответить на вопрос:

> Приводит ли объединение токенов, выбранных исключительно по независимо измеренному структурному сходству, к более выраженной и воспроизводимой последовательностной структуре, чем объединение такого же количества токенов случайным образом при сопоставимом уменьшении алфавита?

Положительным результатом не считать просто увеличение числа повторяющихся n-грамм.

Интерес представляет только эффект, который:

1. существенно превышает matched random baseline;
2. устойчив при нескольких заранее заданных thresholds;
3. проявляется не только в количестве n-грамм, но и хотя бы в одном независимом показателе — например repeated-context coverage или conditional entropy;
4. не обусловлен одной строкой или одним локальным фрагментом корпуса.

Не делать семантических выводов независимо от результата.
