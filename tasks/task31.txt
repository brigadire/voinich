Task31 — Deterministic Parallel Execution for conditional-regime-analyze

Goal

Implement bounded local parallel execution inside conditional-regime-analyze using the replicate-index unit of work proven independent by Task30.

Scope: one process and a bounded goroutine worker pool only. No subprocesses, remote workers, network coordinator, GPU, or scientific/statistical changes.

Primary invariant

For the same corpus, parameters and seed, parallel execution must produce all persisted scientific outputs bit-for-bit identical to the current optimized sequential implementation.

Background

Task30 established that:
- replicate-index is the natural independent unit of work;
- replicateSeed is a deterministic pure function of base seed, salt and replicate index;
- there is no shared sequential RNG state preventing independent execution;
- floating-point reduction in completion order would break reproducibility;
- restoring results to canonical replicate-index order before existing reduction preserves deterministic semantics;
- revised production estimate is ~8.4–9.1 hours.

Phase 1 — Freeze sequential oracle

Before changing code, select a representative reduced workload exercising Part A, Part B, checkpoint/resume and final output generation.

Run the current implementation at least twice and record:
- exact command;
- wall time;
- CPU/allocation profiles;
- peak/live memory where practical;
- SHA256 of every output artifact.

Phase 2 — Internal job contract

Introduce the smallest abstraction for independently executable permutation work, conceptually:

JobID { Stage, MethodOrCombination, ReplicateIndex }
JobResult { JobID, ExistingPerReplicateResult }

Requirements:
- deterministic JobID;
- RNG derived exactly as before;
- no dependency on worker number, scheduling/completion order, GOMAXPROCS or wall clock;
- no replicateSeed semantic change.

Phase 3 — Bounded goroutine pool

Add an explicit -workers N flag.

-workers 1 must use the new architecture and remain identical to the frozen oracle.

Requirements:
- bounded number of active jobs;
- no unbounded goroutine creation;
- no shared mutable RNG;
- no races;
- avoid unnecessary copies of large read-only/dense structures;
- preserve progress/status reporting and cancellation;
- fatal job error terminates cleanly.

Phase 4 — Deterministic indexed reduction

Never reduce in completion order.

Place results into deterministic slots keyed by JobID/replicate index, then aggregate in the exact canonical order expected by the sequential implementation.

Preserve float accumulation order for meanFloat, sdFloat and every other order-sensitive reduction.

Byte-for-byte identity is mandatory; epsilon equivalence is not acceptable.

Phase 5 — Checkpoint/resume

Verify:
1. uninterrupted reference run;
2. uninterrupted parallel run;
3. interrupted parallel run + resume;
4. resume using a different worker count.

All must produce identical final artifacts.

Checkpoint identity must use JobID, never worker identity/completion sequence. Duplicate execution must not alter final results.

Phase 6 — Concurrency safety

Audit shared state, especially Task29 dense structures, reusable scratch buffers, package globals, caches, checkpoint writers and progress reporting.

Run race detection. Do not broaden the task to structuralprojection.

Phase 7 — Scaling benchmark

Benchmark the same workload with workers = 1,2,4,8,12 where hardware permits.

Report for each:
- wall time;
- CPU time if available;
- speedup vs workers=1;
- parallel efficiency;
- peak HeapAlloc/RSS;
- allocation volume;
- SHA256 equivalence.

Record CPU model, logical CPU count, physical cores if readily available and GOMAXPROCS.

Phase 8 — Production estimate

Using measured scaling and the Task30 ~8.4–9.1h sequential estimate, give conservative production estimates.

Identify serial fraction, scheduler/GC contention, memory-bandwidth effects, diminishing returns and recommended worker count.

Do not merely divide runtime by N.

Phase 9 — Documentation

Create/update DISTRIBUTED_EXECUTION_IMPLEMENTATION.md and update DISTRIBUTED_EXECUTION_AUDIT.md, PERFORMANCE_AUDIT.md and PERFORMANCE_REFACTOR_REPORT.md.

Include:

workers | wall time | speedup | efficiency | peak memory | SHA256 identical

Constraints

- conditional-regime-analyze only;
- one process;
- goroutine workers only;
- no subprocess/network/external queue;
- no scientific/statistical/RNG/output changes;
- no unrelated refactoring;
- no GPU;
- bit-for-bit compatibility mandatory.

Validation

go build ./...
go vet ./...
go test ./...
go test -race ./internal/conditionalregime
git diff --check

Add focused tests for deterministic JobID, worker-count independence, completion-order independence, deterministic reduction, checkpoint/resume with changed worker count, and error propagation/cancellation.

Definition of Done

Task31 is complete when bounded local parallel execution works; workers=1 and workers>1 share one scientific path; outputs are byte-identical; checkpoint/resume is deterministic; race tests are clean; scaling is measured; a production estimate is documented; and no subprocess/remote execution was introduced.
