Task41 — Experiment isolation and stale-output contamination prevention

Цель

Исправить критическую проблему pipeline-orchestrate: generic experiment
может содержать или использовать artifacts от предыдущего Voynich run.

Проблема обнаружена на реальном Doyle experiment.

В output, который должен относиться к:

    data_test/pg2097-2.txt

обнаружены одновременно:

Doyle artifacts:
    answered_said
    case_door
    house_room
    treasure_window
    ...

и Voynich artifacts, содержащие:

    input: data_work/ZL3b-x7.txt
    corpus: data_work/ZL3b-x7.txt
    token_occurrences: 39026
    Voynich corpus SHA256
    tokens: s, aiin, daiin, chol, ...

Примеры загрязнённых outputs:

    structural_validation.yaml
    structural_reliability.yaml
    global_distributional_regimes.yaml
    alignment_report.md
    transition_network_summary.yaml
    sequence_analysis.yaml

Это делает comparative experiment научно недействительным.

Критическое требование:

Каждый experiment должен быть полностью изолирован.

Ни одна стадия не должна:

- читать stale artifact от другого experiment;
- принимать artifact другого corpus;
- оставлять stale output в snapshot/freeze;
- случайно использовать общий workdir от предыдущего run.

--------------------------------------------------
1. Reproduce and root-cause first
--------------------------------------------------

До изменения кода воспроизвести проблему.

Использовать небольшой synthetic/generic corpus и заранее загрязнённый
workdir artifact'ами другого corpus.

Определить точный механизм contamination:

- shared workdir;
- hardcoded workdir paths;
- stage input paths;
- stage output paths;
- skipped/NOT_APPLICABLE stages;
- copy/freeze logic;
- resume logic;
- stale intermediate artifacts;
- либо комбинацию причин.

Не начинать с удаления файлов "на всякий случай".

Документировать точный data flow.

--------------------------------------------------
2. Audit all 27 stages
--------------------------------------------------

Для каждой стадии определить:

    stage
    executable
    input artifacts
    output artifacts
    current working directory
    hardcoded workdir dependencies
    experiment-local dependencies
    possibility of stale reads
    possibility of stale outputs

Особенно проверить corpus-generic 18 stages.

Искать:

    workdir/
    data_work/
    experiments/voynich-v1/
    fixed output paths
    default input paths

и случаи, когда orchestrator не передаёт явный path, поэтому analyzer
использует Voynich default.

Это особенно важно: generic stage не должна считаться generic только потому,
что принимает `-corpus`, если другие её inputs остаются Voynich-specific.

--------------------------------------------------
3. Experiment-local workspace

Каждый experiment должен получить собственный workspace.

Например:

    experiments/<experiment>/workspace/

или аналогичную архитектуру.

Все intermediate artifacts данного run должны находиться внутри
experiment-local namespace.

Предпочтительная модель:

    experiment/
        manifest.json
        run-state.json
        workspace/
        outputs/
        logs/
        ...

Конкретную структуру выбрать исходя из текущего кода.

Не использовать общий mutable `workdir/` как источник intermediate results
между независимыми experiments.

--------------------------------------------------
4. Explicit stage inputs

Каждый stage invocation должен получать все experiment-dependent inputs
явно.

Не полагаться на CLI defaults вроде:

    data_work/ZL3b-x7.txt
    workdir/...
    metadata-validation/...

если соответствующий artifact является частью experiment dependency graph.

Stage plan должен содержать реальные resolved paths.

Для generic experiment никакой stage не должна неявно обращаться к
Voynich corpus или Voynich workdir.

--------------------------------------------------
5. Artifact provenance

Добавить проверяемую provenance для experiment artifacts.

Минимально должна быть возможность определить:

    ExperimentID
    input corpus SHA256
    producing stage
    stage parameters

Не обязательно менять scientific output schemas всех analyzers, если это
потребует массового вмешательства.

Можно хранить provenance централизованно в orchestrator artifact manifest.

Например:

    artifacts.json

    artifact:
        path
        sha256
        stage
        experiment_id
        corpus_sha256

Главное — orchestrator должен иметь возможность доказать принадлежность
artifact текущему experiment.

--------------------------------------------------
6. Dependency validation

Перед запуском stage orchestrator должен проверять все её generated inputs.

Если stage требует artifact предыдущей стадии:

    artifact.experiment_id == current ExperimentID
    artifact.corpus_sha256 == current corpus SHA256

и artifact должен быть output завершённой dependency stage.

При несовпадении:

    HARD ERROR

Не использовать artifact.

Не делать fallback на общий workdir.

--------------------------------------------------
7. NOT_APPLICABLE handling

Особенно проверить generic experiments.

Если Voynich-specific stage:

    NOT_APPLICABLE

её старые outputs НЕ должны:

- копироваться;
- попадать в outputs;
- попадать во freeze;
- считаться dependencies;
- появляться в REPORT;
- сохраняться из предыдущего run.

NOT_APPLICABLE означает отсутствие scientific artifacts этой стадии.

--------------------------------------------------
8. Clean experiment semantics

Новый experiment должен создаваться в чистом namespace.

Если target experiment-dir уже содержит неизвестные/stale files:

предпочтительно отказаться от запуска с понятной ошибкой.

Не удалять пользовательские данные автоматически.

Если поддерживается resume, разрешать только artifacts, зарегистрированные
в run-state/artifact manifest данного ExperimentID.

--------------------------------------------------
9. Resume safety

Resume не должен определять completed stage только по существованию output.

Нужно доказать, что output принадлежит:

    этому experiment
    этому corpus
    этой stage invocation

Проверить сценарий:

1. run corpus A
2. сохранить artifacts
3. заменить corpus на B
4. попытаться resume

Ожидаемый результат:

    reject

а не reuse corpus-A artifacts.

--------------------------------------------------
10. Freeze safety

`freeze` должен включать только зарегистрированные artifacts текущего
experiment.

НЕ делать широкое копирование общего workdir/output tree.

Перед freeze:

- проверить provenance;
- проверить SHA256;
- проверить stage ownership;
- проверить corpus identity.

Stale unregistered file не должен попасть в frozen snapshot.

--------------------------------------------------
11. Verify extension

`verify` должен проверять не только checksum frozen files, но и consistency:

    manifest ExperimentID
    corpus SHA256
    artifact registry
    producing stages
    applicable/NOT_APPLICABLE state

Frozen experiment со смешанными corpus artifacts должен быть признан
INVALID.

--------------------------------------------------
12. Hardcoded-default guard

Добавить автоматический regression guard, аналогичный corpus-size audit.

Проверить production orchestration code на опасные references:

    data_work/ZL3b-x7.txt
    data/ZL3b-n.txt
    workdir/<Voynich artifacts>

Разрешить их только:

- как backward-compatible CLI defaults в Voynich mode;
- в tests/fixtures;
- в documentation;

но не как resolved stage dependencies generic experiment.

--------------------------------------------------
13. Contamination regression test

Обязательный тест:

Создать:

    corpus-A
    corpus-B

Сначала создать полный набор fake/intermediate artifacts для corpus-A.

Затем запустить generic orchestration для corpus-B в среде, где corpus-A
artifacts физически существуют.

Проверить:

    zero reads from corpus-A artifacts
    zero corpus-A outputs in experiment-B
    zero corpus-A files in freeze-B

Добавить sentinel artifact, чтение которого тест должен уметь обнаружить.

--------------------------------------------------
14. Real Doyle audit

После исправления НЕ запускать сразу полный production pipeline.

Сначала проверить существующий:

    experiments/doyle-sign-of-four-v1

и классифицировать каждый существующий artifact:

    VALID_DOYLE
    STALE_VOYNICH
    UNKNOWN

по:

- embedded input path;
- corpus SHA;
- token content where necessary;
- dependency provenance.

Создать:

    DOYLE_CONTAMINATION_AUDIT.md

с перечнем загрязнённых файлов и root cause.

Не пытаться "починить" существующий experiment удалением отдельных файлов.

Считать его scientifically invalid.

--------------------------------------------------
15. Fresh Doyle smoke run

Создать НОВЫЙ experiment directory, например:

    experiments/doyle-sign-of-four-v2-smoke

Не переиспользовать загрязнённый v1.

Запустить generic smoke pipeline с reduced computational parameters.

После завершения автоматически проверить:

    grep -R "ZL3b" experiment -> no scientific artifacts
    Voynich corpus SHA -> absent
    Voynich-specific token sentinels -> absent where meaningful
    all artifact provenance -> Doyle corpus SHA

NOT_APPLICABLE stages должны иметь zero outputs.

--------------------------------------------------
16. Voynich backward compatibility

Критическое требование:

    experiments/voynich-v1/

НЕ изменять.

Все 340 frozen checksums должны продолжить проходить.

Existing Voynich execution semantics должны остаться совместимыми.

Если новая isolation architecture требует migration для будущих Voynich
experiments, frozen v1 всё равно должен оставаться readable/verifiable.

--------------------------------------------------
17. Scientific invariance

НЕ менять:

- algorithms;
- formulas;
- thresholds;
- window sizes;
- permutations;
- RNG;
- normalization;
- tokenization;
- output numeric precision.

Для одного и того же корректного input новый isolated execution должен
давать те же scientific outputs, что старый execution без contamination.

--------------------------------------------------
18. Distributed execution

Проверить, что experiment-local paths корректно работают с существующим
remote executor.

Workers должны получать artifacts только текущего ExperimentID.

Remote JobID должен оставаться связан с правильным experiment/corpus
fingerprint.

Не заниматься новым распределением stages в Task41.

--------------------------------------------------
19. Logging

Каждый stage log должен начинаться orchestration header примерно с:

    ExperimentID:
    Input mode:
    Corpus:
    Corpus SHA256:
    Stage:
    Working directory:
    Inputs:
    Outputs:

Это orchestration metadata, а не scientific output.

Так даже пустой/долгий stage log позволяет сразу увидеть, какой corpus
реально анализируется.

22. Не делать

НЕ:

- продолжать загрязнённый Doyle v1 как scientific baseline;
- вручную копировать "правильные" файлы из него;
- удалять stale files и объявлять experiment исправленным;

- запускать полный production Doyle v2 до прохождения smoke validation;
- заниматься Task40/distributed structural-projection в рамках Task41.

--------------------------------------------------
Definition of Done

Невозможно создать, resume или freeze experiment, в котором scientific
artifact другого corpus/ExperimentID случайно используется как input или
попадает в snapshot.

Generic pipeline никогда не использует Voynich defaults как скрытые
dependencies.

Все intermediate artifacts изолированы по experiment.

Existing contaminated Doyle v1 идентифицирован как invalid.

Fresh Doyle smoke run содержит только Doyle-derived artifacts.

Voynich Baseline v1 остаётся неизменным и проходит verify.
