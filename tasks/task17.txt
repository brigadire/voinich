Задача: Blind Metadata Validation для frozen distributional discovery
с использованием существующего IVTT -x7 корпуса и минимального IVTFF metadata parser

Контекст

Все предыдущие статистические эксперименты выполнялись на уже подготовленном
plain-text корпусе, полученном внешним инструментом IVTT из ZL3b-n.txt
с preset:

    -x7 ASCII Full

Этот корпус является CANONICAL / FROZEN CORPUS.

Он уже использован для:

- словаря токенов;
- begin/end analysis;
- soft structural space;
- structural/graphemic analysis;
- pair decomposition;
- distance-context analysis;
- structural projection;
- property trajectory;
- local-regime analysis;
- global distributional regime discovery.

Поэтому НЕЛЬЗЯ создавать новую текстовую транслитерацию и заменять существующий
корпус результатом собственного преобразования IVTFF.

Цель текущей задачи:

1. прочитать metadata из исходного ZL3b-n.txt;
2. сопоставить loci/строки/страницы IVTFF с уже существующей frozen
   последовательностью токенов IVTT -x7;
3. после строгой проверки alignment выполнить blind metadata validation
   уже зафиксированных distributional results.

Ключевой принцип:

    IVTT отвечает за text transformation.
    Наш код отвечает только за metadata parsing + alignment + validation.


1. Что НЕ нужно реализовывать

Не реализовывать полный аналог IVTT.

Не создавать собственный новый:

    IVTFF -> plain text corpus

pipeline.

Не заменять существующий -x7 corpus.

Не пытаться улучшать или нормализовывать транслитерацию.

Не менять tokenization уже frozen corpus.


2. Входные данные

Использовать:

Именно последовательность токенов этого файла должна использоваться

    0 ... N-1

    38887 tokens

Если фактическое значение отличается — использовать фактическое, но
зафиксировать его и проверить совместимость с frozen discovery results.


B. Original IVTFF source

    ZL3b-n.txt

Исходный IVTFF используется ТОЛЬКО для извлечения metadata и структуры loci.

4. Минимальный IVTFF parser

Нужно реализовать только необходимый subset IVTFF.

Парсер должен уметь извлекать:

- folio/page identifier;
- locus identifier;
- locus type;
- line identifier;
- paragraph start markers;
- page variables;
- Currier ID $C;
- Lisa Fagin Davis hand ID $H;
- другие page variables, если они присутствуют и легко доступны;
- text content locus в форме, достаточной для alignment.

Не требуется поддерживать все функции IVTT.


5. Page variable inheritance

Важно:

$C, $H и другие page variables могут задаваться на уровне страницы,
а не каждой отдельной строки.

Нужно корректно наследовать active page variables для всех loci данной страницы.

Не угадывать metadata из token text.

Например:

page fXXX:
    $C = A
    $H = 3

все loci страницы получают:

    currier = A
    hand = 3

пока IVTFF явно не задаёт другое правило.


6. Quire metadata

Если quire identifier присутствует непосредственно или может быть
однозначно извлечён из IVTFF metadata — сохранить.

Если его нет:

НЕ выводить quire из номера folio эвристически.

Поле:

    quire = null

и явно сообщить отсутствие данных.

Никаких внешних таблиц quire на этом этапе без отдельного входного файла.


7. Alignment: основное правило

Frozen plain corpus является source of truth для token sequence.

IVTFF parser не должен создавать альтернативную последовательность токенов.

Нужно определить:

какой диапазон frozen token positions соответствует каждому IVTFF locus.


8. Минимальное text normalization для alignment

Разрешается реализовать только минимальное преобразование IVTFF text,
необходимое для сопоставления с существующим IVTT -x7 output.

Это НЕ новый corpus generator.

Для каждого locus:

    IVTFF text
        ↓
    alignment representation
        ↓
    compare against frozen tokens

Каждое такое правило должно быть:

- явно документировано;
- покрыто test;
- предназначено только для alignment.


9. -x7 semantics

Не пытаться самостоятельно реконструировать все semantics preset -x7,
если это не требуется.

Если в проекте доступен фактический output IVTT, именно он является expected
result.

Правильность нашего alignment определяется совпадением с этим output,
а не предположением о том, как "должен" работать -x7.


10. Special IVTFF symbols

Учитывать известные representation rules:

    @NNN;

является единым high-ASCII encoded transliteration sign в ASCII output.

Не разбивать:

    @135;

на отдельные токены/символы при grapheme-level parsing.

Но на текущем этапе grapheme parsing вообще желательно не выполнять,
если это не требуется для alignment.


11. Uncertain characters

    ?

сохранять в соответствии с frozen output.

Не удалять автоматически.


12. Word boundaries

Не переопределять word boundaries.

Если frozen -x7 output содержит определённую токенизацию, именно она является
canonical.

Нельзя:

- объединять frozen tokens;
- разделять frozen tokens;
- исправлять spaces;
- вводить alternative segmentation.


13. Strict alignment invariant

После alignment должна выполняться глобальная invariant:

    concatenation(aligned frozen token ranges in IVTFF order)
        ==
    frozen corpus token sequence

Посимвольно/потоково на уровне token identity.

Также:

    total aligned tokens == frozen corpus tokens


14. Никакого silent fuzzy matching

По умолчанию fuzzy alignment ЗАПРЕЩЁН.

Если locus невозможно сопоставить однозначно:

остановить validation или пометить run failed.

Не использовать:

- Levenshtein auto-correction;
- nearest approximate locus;
- token skipping;
- silent substitutions.


15. Alignment diagnostics

- global frozen token position;
- IVTFF folio;

- raw IVTFF locus text;

- produced/matched tokens;

...

20. Corpus compatibility check

Перед metadata validation проверить, что frozen discovery относится именно
к этому корпусу.

Минимум:

- token_count совпадает;
- first tokens совпадают;
- last tokens совпадают;
- если возможно, SHA256 frozen corpus сохранить в discovery metadata.

Если hash раньше не сохранялся — вычислить сейчас и добавить в report,
но не притворяться, что это исторически сохранённый hash.


21. Freeze discovery

После успешного alignment metadata validation использует существующие
stable boundaries и cluster assignments.

Запрещено:

- пересчитывать stable boundaries;
- менять window sizes;
- менять change-point thresholds;
- менять cluster K;
- менять discovery parameters по metadata.


22. Metadata boundary sets

Из token_metadata_map построить reference boundaries:

- line transitions;
- paragraph transitions;
- folio transitions;
- Currier transitions;
- hand transitions;
- quire transitions, если данные реально доступны.

Boundary = token position между двумя последовательными token records.


23. Unknown metadata

При переходе:

known -> unknown
unknown -> known

не считать это Currier/hand transition по умолчанию.

Currier transition:

A -> B

только если обе стороны known и labels различаются.

Аналогично hand.


24. Stable blind boundaries validation

stable_distributional_boundaries.tsv

- line boundary;

- hand transition;

28. Permutation controls

Минимум два null models.

A. Uniform boundary null

Случайно разместить такое же число blind boundaries среди допустимых
token positions.


B. Spacing-preserving circular shift

Сохранить взаимные расстояния между frozen blind boundaries и циклически
сдвигать весь boundary pattern по corpus.


29. Permutations

Для основных boundary tests:

    10000

CLI:

    --permutations

Все random operations deterministic:

    --seed


30. Physical folio validation

Проверить:

stable blind boundaries
vs

Raw match fraction без permutation baseline не интерпретировать.


31. Paragraph validation

Аналогично:

vs

32. Line validation

Line transitions очень часты.

Использовать их прежде всего как density sanity/control.

Не трактовать высокий raw overlap как meaningful без null.


33. Currier boundary validation

Проверить:

vs

Считать:

34. Hand boundary validation

То же для Lisa Fagin Davis hand transitions.


35. Regime assignment validation

Отдельно проверить frozen global clustering against metadata.

Использовать существующие:

global_distributional_cluster_assignments.tsv
global_distributional_clustering.tsv

Не пересчитывать clusters.


36. K sweep

Если frozen clustering содержит K=2..15:

для каждого frozen K посчитать metadata association.

Не выбирать K как "правильный" на основании metadata.


37. Currier vs cluster metrics

Для каждого K считать минимум:

- contingency table;
- Mutual Information;
- Normalized Mutual Information;
- Adjusted Rand Index;
- homogeneity;
- completeness.

Если AMI легко реализуема — добавить.


38. Hand vs cluster metrics

То же для hand IDs.


39. Mixed windows

Frozen windows могут пересекать metadata boundaries.

Для каждого window вычислить metadata composition.

Например:

Currier:
    A 0.80
    B 0.20

hand:
    H1 0.95
    H2 0.05

Сохранить:

majority_label
purity


40. High-purity subsets

Повторить association analysis для:

all windows
purity >= 0.8
purity >= 0.9

Но не использовать high-purity subset для изменения clusters.


41. Soft metadata comparison

Желательно не ограничиваться majority label.

Для каждого regime cluster построить expected metadata distribution.

Считать conditional entropy:

    H(Currier | regime)
    H(hand | regime)

и normalized entropy reduction относительно global metadata entropy.


42. K-sweep multiple comparison control

Если ищется maximum association across K=2..15:

для каждой metadata permutation:

- permute metadata blocks;
- рассчитать metric для всех frozen K;
- сохранить maximum metric.

Сравнить observed maximum с null distribution of maxima.

Это обязательно, если в отчёте упоминается "max NMI over K sweep".


43. Block-aware metadata permutation

Для Currier/hand не использовать только random token-label shuffle.

Нужно сохранять block structure.

Предпочтительно:

- shuffle labels между существующими contiguous metadata blocks;
или
- circularly shift metadata block sequence.

Сохранить block lengths.


44. Recurring regime consistency

Для unconstrained clusters определить contiguous runs.

Если один regime появляется в разных удалённых местах:

проверить metadata composition каждого run.

Считать:

within-regime Currier entropy
within-regime hand entropy
between-run metadata consistency


45. Contiguous vs unconstrained comparison

Сравнить frozen:

A. contiguous segmentation
B. unconstrained clustering

against metadata.

Это позволит различить:

distributional section boundaries
и
recurrent distributional regimes.

51. Validation categories

Финальный report может использовать три нейтральных категории:

A. Strong alignment

Большая часть blind distributional structure совпадает с tested metadata
существенно сильнее null.

B. Partial alignment

Часть blind structure объясняется metadata, но имеется устойчивый residual.

C. Weak alignment

Blind structure слабо связана с tested metadata.


52. Нельзя считать metadata ground truth

Currier, hand, paragraph и folio являются reference annotations/physical
metadata, а не "истинной структурой текста".

Поэтому использовать формулировку:

association with metadata

а не:

accuracy against metadata.

56. Fail-fast behavior

Validation НЕ запускать, если alignment failed.

Порядок:

parse metadata
    ↓
align against frozen corpus
    ↓
verify exact token invariant
    ↓
PASS?
    |
    +-- NO -> stop
    |
    +-- YES
         ↓
metadata validation


57. Никакой auto-repair

Если alignment не совпадает:

НЕ:

- пропускать token;
- менять token;
- объединять token;
- split token;
- fuzzy match;
- продолжать validation.

Сначала исправить alignment implementation и добиться exact match.

Главная цель

Не повторять IVTT.

Не создавать новую транслитерацию.

Использовать уже существующий IVTT -x7 output как frozen canonical token
sequence и лишь восстановить для каждого frozen token его происхождение
в IVTFF metadata.

После строгого exact alignment проверить:

какая часть ранее обнаруженной вслепую distributional structure независимо

часть остаётся ими необъяснённой.
