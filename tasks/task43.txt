Task43 — Audit IVTFF dependency of stages 19–27 and extend the generic-corpus pipeline

Цель

Провести научный и технический аудит стадий 19–27 pipeline-orchestrate,
которые сейчас целиком исключаются из generic-corpus experiments как:

    NOT_APPLICABLE: requires IVTFF metadata

Текущий список:

19 metadata-validate
20 cluster-metadata-global
21 conditional-regime-analyze
22 residual-diagnostic-analyze
23 token-relation-validate
24 replicated-local-structure-audit
25 higher-order-sequence-validate
26 positional-continuation-validate
27 transition-network-validate

На реальном generic experiment Doyle поэтому выполняются только стадии 1–18.

Это слишком грубая классификация.

Нужно определить для каждой стадии:

A. IVTFF metadata является частью научного определения анализа;
B. metadata используется только как технический источник segmentation/grouping;
C. metadata вообще не является принципиально необходимой, а зависимость —
   исторический артефакт реализации/pipeline.

Все стадии B/C, для которых можно определить научно нейтральный generic mode,
должны быть включены в generic pipeline.

==================================================
PHASE 1 — dependency audit
==================================================

Для каждой стадии 19–27 проследить полный data flow:

    CLI
      -> internal package
      -> input loaders
      -> metadata structures
      -> algorithms
      -> outputs

Для каждого metadata field определить:

    field
    source
    where consumed
    scientific meaning
    whether mathematically required
    whether generic substitute is possible

Особенно проверить:

    token_metadata_map.tsv
    $H / hand
    $C / Currier
    folio/page
    section
    quire
    paragraph/block identifiers
    line/locus information
    any derived grouping labels

Не делать вывод по имени файла или CLI argument.
Проследить фактическое использование значения в формулах.

==================================================
PHASE 2 — classification
==================================================

Создать таблицу:

stage | metadata used | role | class A/B/C | generic strategy

Определения:

CLASS A — intrinsically metadata-dependent

Исследование непосредственно проверяет связь текстовой структуры с
Voynich-specific external metadata.

Примеры потенциального смысла:

    hand dependence
    Currier language dependence
    manuscript section dependence

Такую стадию НЕ адаптировать искусственно.

Для generic corpus оставить:

    NOT_APPLICABLE

с конкретной причиной, а не общей фразой "requires IVTFF metadata".


CLASS B — metadata supplies generic segmentation/grouping

Алгоритм исследует текстовую структуру, но использует metadata для получения
блоков/групп/реплик.

Проверить возможность заменить это corpus-internal deterministic segmentation.


CLASS C — accidental implementation dependency

Сам алгоритм работает исключительно с token sequence/positions/edges,
а metadata dependency возникла из-за существующего API, shared loader,
historical pipeline structure или удобства реализации.

Такую зависимость удалить.

==================================================
PHASE 4 — generic segmentation specification
==================================================

Если Class B stages существуют, нужен ОДИН общий generic segmentation layer.

Не создавать отдельное разбиение для каждой стадии.

Требования:

    deterministic
    language-agnostic
    corpus-size-aware
    no Voynich constants
    no semantic knowledge
    no punctuation requirement
    reproducible
    independent of worker count
    independent of execution order

Не использовать hardcode:

    39026
    Voynich line count
    Voynich folio count
    Voynich block count

Segmentation должна масштабироваться с N корпуса.

Предпочтительно сохранять естественные строки corpus, если научный алгоритм
работает со строками.

Если требуются более крупные blocks — определить их из corpus structure/N
по явному алгоритму.

ВАЖНО:

не пытаться искусственно имитировать folios, hands или Currier languages.

Generic blocks — это statistical resampling units, а не fake manuscript
metadata.

==================================================
Definition of Done
==================================================

Для каждой стадии 19–27 известно, ПОЧЕМУ она требует metadata.

Зависимость классифицирована как scientific, segmentation-only или accidental.

Все scientifically legitimate corpus-only stages включены в generic pipeline.

Metadata-specific analyses остаются NOT_APPLICABLE с точной причиной.

Generic implementation остаётся полностью language-agnostic.

Voynich execution semantics и frozen baseline не изменены.

После smoke-run известно новое фактическое число применимых generic stages
из 27.
