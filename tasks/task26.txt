Задача: оптимизировать memory/data representation hot path
transition-network-validate по результатам pprof.

ВАЖНО:
Это исключительно performance refactoring.

Не менять:
- статистические определения;
- eligibility rules;
- permutation/null models;
- thresholds;
- smoothing;
- randomization semantics;
- seed behavior;
- output schemas;
- scientific results.

Текущий baseline pprof для короткого diagnostic run:

CPU:
- permutedStatistics: 77.6% cumulative
- mapaccess1_faststr: 24.3%
- mapassign_faststr: 18.8%
- GC: ~18%
- collectEffectVectors: 26.0%
- averageVectors: 23.4%
- collectEntropyEffects: 19.6%
- profileLOBOStats: 27.7%

Allocations:
- total: ~13.2 GB
- collectEffectVectors: 6.60 GB (49.9%)
- averageVectors: 3.71 GB (28.1%)
- vectorCorrelation: 706 MB
- collectEntropyEffects: 601 MB

Цель первого этапа:

1. Encode token strings once at input into compact integer TokenID.

Prefer:

    type TokenID uint16

if vocabulary <= 65535.

Keep reversible:

    token -> TokenID
    TokenID -> token

Strings must remain only at parsing/reporting boundaries.
No string-keyed maps should remain in permutation hot paths
where an indexed representation is possible.

2. Replace map-based dense effect/profile vectors with indexed slices.

Where vector dimensions are known/frozen, use:

    []float64
    []uint32
    []int

instead of:

    map[string]...
    map[TokenID]...

Do not blindly replace sparse structures with huge V×V matrices.
Choose dense representation only where memory size is reasonable.

3. Reuse scratch buffers across permutations.

Avoid repeated:

    make(...)
    make(map...)

inside permutation loops.

Preallocate and clear/reuse buffers.

4. Inspect specifically:

    collectEffectVectors
    averageVectors
    collectEntropyEffects
    vectorCorrelation
    profileLOBOStats
    incomingOpp
    effect

for repeated allocation and repeated calculation of values invariant
across permutations.

Precompute invariant quantities where mathematically identical.

5. DO NOT add parallel permutation execution yet.

First eliminate allocation/map overhead and establish a new
single-thread performance baseline.

6. Add benchmarks for the major hot functions where practical.

Use representative synthetic/frozen inputs.

Report:

    ns/op
    B/op
    allocs/op

before and after.

7. Scientific equivalence is mandatory.

Run the existing deterministic test dataset through old and optimized
implementations and verify that all scientific output values are identical
(or differ only by documented floating-point roundoff below 1e-12).

In particular compare:
- eligible edges;
- observed effects;
- permutation exceedance counts;
- p-values/q-values;
- replicated edges/profiles;
- LOBO statistics;
- final diagnosis.

8. After implementation run:

    go test ./...
    go vet ./...

Then repeat the same profiling run and provide:

    go tool pprof -top CPU
    go tool pprof -top -alloc_space memory

Also report:
- wall-clock before/after;
- total allocation before/after;
- peak RSS if available.

Do not perform unrelated refactoring.
Do not parallelize yet.
