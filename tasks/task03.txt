# Реализовать анализатор последовательностей токенов `sequence-analyze`

В репозитории уже существует конвейер:

```text
исходный текст
    → dictionary.yaml
    → tokens_analysis.yaml
    → structural_analysis.yaml
```

Необходимо добавить четвёртый независимый анализатор:

```text
исходный текст
    → sequence_analysis.yaml
```

Новый анализатор должен исследовать **реально наблюдавшиеся последовательности токенов** в исходном корпусе. Он не должен восстанавливать последовательности из `dictionary.yaml`, поскольку агрегированная статистика непосредственных соседей не позволяет установить существование конкретных триграмм и более длинных цепочек.

На этом этапе не выполнять семантическую интерпретацию, не вводить категории `operator`, `operand`, `modifier` и т. п.

## 1. Расположение и запуск

Создать:

```text
sequence-analyze/
    main.go
```

Пример запуска:

```bash
go run ./sequence-analyze \
  -input data_work/ivtt_output_1786282555007.txt \
  -output sequence_analysis.yaml
```

Параметры по умолчанию:

```text
-input                    data_work/ivtt_output_1786282555007.txt
-output                   sequence_analysis.yaml
-min-n                    2
-max-n                    8
-min-count                2
-max-items                200
-context-limit            10
```

`-max-items 0` должен отключать ограничение количества записей.

## 2. Токенизация

Использовать те же правила, что и генератор `dictionary.yaml`:

```go
strings.Fields
```

Одна непустая строка входного файла является одной самостоятельной последовательностью.

N-граммы не должны пересекать границу строки.

Пустые строки игнорировать.

Не изменять регистр, пунктуацию и содержимое токенов.

В частности, такие элементы, как:

```text
?
@135;
yko?n
@135;odaiin
```

не нормализовать и не удалять.

## 3. Контроль корпуса

Анализатор должен самостоятельно посчитать:

```yaml
meta:
  token_occurrences: 38887
  lines: 5371
  transitions: 33516
```

Для текущего dataset эти числа должны совпасть с существующим конвейером.

Проверять инвариант:

```text
token_occurrences - lines = transitions
```

Если позднее корпус изменится, программа не должна требовать именно эти конкретные числа, но должна проверять внутренний инвариант.

## 4. Точные n-граммы

Посчитать все реально наблюдавшиеся n-граммы для:

```text
n = min-n ... max-n
```

По умолчанию:

```text
2..8
```

Для каждой n-граммы хранить:

```yaml
- tokens:
    - qokedy
    - daiin
    - chedy
  n: 3
  count: 7
  line_count: 7
  start_count: 2
  end_count: 1
  start_probability: 0.285714
  end_probability: 0.142857
```

Где:

* `count` — общее число появлений;
* `line_count` — число различных строк, в которых она встречается;
* `start_count` — сколько раз n-грамма начинается с первого токена строки;
* `end_count` — сколько раз заканчивается последним токеном строки;
* вероятности рассчитываются относительно `count`.

Если одна n-грамма встречается дважды в одной строке:

```text
count = 2
line_count = 1
```

## 5. Распределение n-грамм по длинам

Добавить сводный раздел:

```yaml
ngram_summary:
  - n: 2
    total_occurrences: ...
    unique: ...
    repeated: ...
    hapax: ...
    max_count: ...
  - n: 3
    ...
```

Где:

* `unique` — количество различных n-грамм;
* `repeated` — число различных n-грамм с `count >= 2`;
* `hapax` — число различных n-грамм с `count == 1`;
* `max_count` — максимальная наблюдаемая частота.

Этот раздел должен учитывать все n-граммы, независимо от `min-count` и `max-items`.

## 6. Повторяющиеся точные последовательности

Создать:

```yaml
repeated_ngrams:
  2:
    ...
  3:
    ...
  4:
    ...
```

В этот раздел включать только n-граммы:

```text
count >= min-count
```

Сортировка:

1. `count` по убыванию;
2. затем лексикографически по последовательности токенов для детерминированного результата.

`max-items` применять отдельно для каждого значения `n`.

Нужно сохранять raw `count`; не вводить составной `score`.

## 7. Продолжения последовательностей

Для каждой повторяющейся n-граммы определить токены, реально наблюдавшиеся непосредственно после неё.

Например:

```text
A B C X
A B C Y
A B C X
```

должно дать:

```yaml
continuations:
  - prefix:
      - A
      - B
      - C
    prefix_count: 3
    observed_continuations: 3
    unique_continuations: 2
    entropy: ...
    normalized_entropy: ...
    predictability: ...
    next:
      - token: X
        count: 2
        probability: 0.666667
      - token: Y
        count: 1
        probability: 0.333333
```

Появления prefix в конце строки не являются наблюдением продолжения и не должны входить в `observed_continuations`.

При этом хранить:

```yaml
line_end_count: ...
```

чтобы потеря контекста была видима.

Формула:

```text
predictability =
    1 - entropy / log2(unique_continuations)
```

только если:

```text
unique_continuations > 1
```

Если продолжение всегда одно:

```text
predictability = 1
entropy = 0
normalized_entropy = 0
```

Если нет наблюдаемых продолжений, запись в этот рейтинг не включать.

## 8. Предшествующий контекст

Симметрично построить анализ токенов непосредственно перед повторяющимися последовательностями:

```yaml
predecessor_contexts:
  - suffix:
      - ...
    suffix_count: ...
    observed_predecessors: ...
    line_start_count: ...
    unique_predecessors: ...
    entropy: ...
    normalized_entropy: ...
    predictability: ...
    previous:
      ...
```

## 9. Расширяемость последовательностей

Для повторяющихся n-грамм определить, насколько они являются частью более длинной устойчивой последовательности.

Например:

```yaml
extensions:
  - sequence:
      - A
      - B
      - C
    count: 12

    left:
      unique: 3
      dominant:
        token: X
        count: 10
        probability: 0.833333

    right:
      unique: 1
      dominant:
        token: D
        count: 11
        probability: 1.0

    line_start_count: 1
    line_end_count: 1
```

Этот раздел нужен для последующего поиска границ устойчивых конструкций.

Пока не объединять автоматически:

```text
A B C
```

и

```text
A B C D
```

в одну конструкцию. Сохранять наблюдения отдельно.

## 10. Максимальные повторяющиеся точные последовательности

Добавить отдельный раздел:

```yaml
maximal_repeated_sequences:
```

Под максимальной повторяющейся последовательностью понимать последовательность с `count >= min-count`, которую нельзя расширить одинаковым токеном слева или справа без уменьшения числа её появлений.

Пример:

```text
X A B C Y
X A B C Y
```

Если:

```text
count(A B C) = 2
count(X A B C) = 2
count(X A B C Y) = 2
```

то в максимальные последовательности должна попасть:

```text
X A B C Y
```

а не все три вложенных варианта.

Это позволит убрать большое количество тривиально вложенных повторов.

Не искать последовательности длиннее `max-n` на этой итерации.

## 11. Координаты

Нужно обеспечить возможность вернуться от результата к исходному корпусу.

Для каждой записи из `maximal_repeated_sequences` хранить координаты всех появлений:

```yaml
occurrences:
  - line: 172
    token_offset: 3
  - line: 864
    token_offset: 5
```

Нумерацию определить явно в `methodology`, предпочтительно:

```text
line: 1-based
token_offset: 0-based
```

Для обычного `repeated_ngrams` координаты можно не сохранять, чтобы не раздувать YAML.

## 12. Что пока НЕ реализовывать

На данной итерации сознательно не делать:

* wildcard-шаблоны `A * C`;
* edit distance между последовательностями;
* объединение похожих EVA-токенов;
* использование `equivalence_candidates` из `structural_analysis.yaml`;
* кластеризацию;
* оператор/операнд-классификацию;
* попытки определить смысл токенов;
* ML;
* сравнение с естественными или программными языками;
* зависимости через несколько токенов с произвольным расстоянием;
* переходы через границы строк.

Нужен чистый baseline точных последовательностей.

## 13. Формат результата

Выход:

```text
sequence_analysis.yaml
```

Предлагаемая верхнеуровневая структура:

```yaml
meta:
parameters:
methodology:

ngram_summary:

repeated_ngrams:

continuations:

predecessor_contexts:

extensions:

maximal_repeated_sequences:
```

В `methodology` явно описать:

* что строка является границей последовательности;
* способ токенизации;
* определения `count` и `line_count`;
* формулу entropy;
* формулу normalized entropy;
* формулу predictability;
* определение maximal repeated sequence;
* систему координат.

## 14. Производительность

Корпус небольшой (~39 тыс. вхождений), поэтому преждевременная оптимизация не нужна.

Однако не использовать алгоритм, перебирающий все возможные пары произвольных подстрок корпуса.

Для `n <= 8` достаточно однопроходного подсчёта n-грамм с hash map.

Результат должен быть детерминированным при повторном запуске.

## Цель

Результат этой итерации должен дать ответ только на формальные вопросы:

* какие точные последовательности повторяются;
* как быстро исчезают повторы при увеличении `n`;
* какие последовательности имеют устойчивое продолжение;
* какие имеют устойчивый предшествующий контекст;
* существуют ли длинные повторяющиеся конструкции;
* где именно они расположены в корпусе.

Не делать выводов о языке, семантике или назначении документа.
