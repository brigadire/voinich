Task58 — Independent Rozanova–Temerev Metric Replication

Цель

Создать независимый исследовательский модуль, реализующий ключевые
статистические estimands Rozanova & Temerev (2026), прежде всего:

    1. adjacent-token dependency / token-order MI;
    2. glyph-edge coupling MI;

и применить их к:

    canonical Voynich;
    natural-text controls;
    уже существующим homophonic transformed controls.

Основной вопрос:

    Подтверждаются ли наблюдения Rozanova–Temerev на нашей транскрипции
    Voynich и наших независимых controls?

Вторичный вопрос:

    Воспроизводит ли homophonic transformation именно те свойства Voynich,
    которые измеряются Rozanova–Temerev, а не только похожие свойства
    нашего собственного pipeline?

Task58 является независимым исследованием.

НЕ встраивать новые metrics в Stages 1–28.
НЕ использовать Task52 fingerprint/distance как optimization target.
НЕ менять существующие scientific stages.

======================================================================
1. PRIMARY SOURCE
======================================================================

Перед реализацией получить и изучить первичный текст:

    Rozanova & Temerev (2026)
    "A Glyph Is Not a Letter, a Token Is Not a Word, a Space Is Not a Space"

Использовать:

    paper/preprint;
    supplementary material;
    официальный repository/code, если существует.

Task56 использовать только как навигационный материал.

Математические определения брать из первичного источника.

Создать:

    ROZANOVA_TEMEREV_METHOD.md

с точными:

    definitions;
    formulas;
    normalization;
    preprocessing;
    controls;
    sample restrictions;
    randomization;
    uncertainty treatment.

======================================================================
2. REPLICATION BEFORE EXTENSION
======================================================================

Разделить исследование на:

    Phase A — methodological replication;
    Phase B — independent control experiment.

Сначала реализовать максимально точные аналоги R&T metrics.

Только после этого применять их к нашим homophonic corpora.

Не модифицировать estimands для получения лучшего разделения
Voynich/controls.

======================================================================
3. TOKEN-ORDER DEPENDENCY
======================================================================

Реализовать exact R&T adjacent-token dependency estimand.

Если paper определяет его как mutual information:

    I(T_i ; T_{i+1})

использовать именно их estimator, включая:

    probability estimation;
    vocabulary restrictions/capping;
    bias correction;
    shuffle correction;
    normalization;

если эти элементы присутствуют в paper.

Не заменять его:

    Stage 27 transition metrics;
    higher-order CMI Stage 25;
    network statistics.

Это отдельный estimand.

======================================================================
4. SHUFFLE CORRECTION
======================================================================

Если R&T используют shuffled-token baseline, воспроизвести процедуру
максимально точно.

Фиксировать:

    number of shuffles;
    seed generation;
    whether line boundaries are preserved;
    whether token frequencies are preserved;
    averaging/median procedure.

Выводить отдельно:

    MI_raw
    MI_shuffle_mean
    MI_shuffle_sd
    MI_corrected

или точные аналоги терминологии paper.

======================================================================
5. VOCABULARY CAP / RARE TYPES
======================================================================

Особенно внимательно воспроизвести treatment редких tokens.

Если R&T используют:

    top-N vocabulary;
    frequency threshold;
    OTHER bucket;
    vocabulary cap;

реализовать именно эту процедуру.

Voynich имеет чрезвычайно высокий hapax fraction, поэтому различия
rare-token handling способны существенно изменить MI.

Не выбирать cap на основании результатов наших корпусов.

======================================================================
6. GLYPH-EDGE COUPLING
======================================================================

Реализовать второй основной estimand R&T:

    dependency between

        final glyph of token i

    and

        initial glyph of token i+1.

Условно:

    I(last(T_i); first(T_{i+1}))

но использовать точное определение paper.

Это НЕ token-transition metric.

======================================================================
7. GLYPH DEFINITION
======================================================================

До расчётов зафиксировать, что считается glyph в:

    R&T corpus;
    нашем canonical Voynich corpus.

Проверить:

    EVA multi-character conventions;
    uncertain glyphs;
    ligatures;
    transcription operators;
    punctuation/markers.

Не считать автоматически Unicode character == Voynich glyph.

Создать явный tokenizer/parser, если это требуется используемой
транскрипцией.

======================================================================
14. CRITICAL GLYPH-EDGE CONTROL
======================================================================

Наши Task46/55 transformations работают на token level.

Поэтому существует важное предсказание:

    они могут менять token-order MI,

но их эффект на glyph-edge MI может оказаться искусственным следствием
способа генерации cipher-token labels.

Нельзя рассчитывать glyph-edge MI непосредственно по служебным labels:

    x000001
    x000002
    ...

и интерпретировать это как содержательный результат.

======================================================================
15. SYNTHETIC GLYPH PROBLEM
======================================================================

До Phase B определить, имеют ли Task46 synthetic tokens осмысленную
внутреннюю glyph structure.

Если нет:

    glyph-edge MI для этих corpora = NOT_APPLICABLE.

НЕ изобретать post-hoc glyph encoding специально для получения
Voynich-like edge coupling.

Это принципиальный safeguard.

Следовательно возможно, что:

    token-order experiment

может быть выполнен на всех transformed corpora,

а:

    glyph-edge experiment

только на Voynich + естественных textual controls,
если representations сопоставимы.

25. RELATION TO OUR STAGE 25
======================================================================

Аналогично сравнить R&T token-order MI с:

    higher-order sequence validation.

Не ожидать совпадения.

R&T metric может помочь определить, к какой стороне этого расхождения
относится их "weak token order".

======================================================================
27. RESULT CLASSIFICATION
======================================================================

Для TOKEN-ORDER результата:

REPLICATED:
    canonical Voynich qualitatively/quantitatively воспроизводит
    опубликованный R&T effect относительно comparable controls.

PARTIAL:
    направление совпадает, magnitude/protocol differs.

NOT_REPLICATED:
    expected effect отсутствует.

INCOMPARABLE:
    transcription/preprocessing incompatibility не позволяет сравнение.

Для homophonic extension:

SUPPORTS_FORWARD_HOMOPHONY_EFFECT:
    homophonic dose-response систематически движется к Voynich
    по exact R&T estimand.

MIXED:
    часть models/H движется, часть нет.

NEGATIVE:
    homophony не приближает exact R&T metric к Voynich.

======================================================================
28. GLYPH-EDGE RESULT CLASSIFICATION
======================================================================

Glyph-edge анализ классифицировать независимо.

Особенно важен возможный результат:

    token-order becomes Voynich-like
    BUT
    glyph-edge coupling does not.

Это будет свидетельством, что homophony воспроизводит только один
уровень организации Voynich.

Не усреднять эти результаты в один score.
