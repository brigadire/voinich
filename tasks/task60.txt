Task60 — Voynich Exact Runs, Near-Repetitions and Illustration Labels Analysis

Цель

Независимо и количественно проверить несколько часто описываемых
свойств текста Voynich:

1. необычную частоту непосредственных повторов одинаковых tokens;
2. наличие длинных exact runs одного token;
3. необычную частоту соседних tokens, отличающихся одним glyph;
4. структуру этих near-repetitions:
       substitution
       insertion
       deletion;
5. низкую повторяемость illustration labels;
6. совместимость наблюдаемых эффектов с простой
   position-independent homophonic substitution.

Task60 должен проверить сами утверждения количественно, а не принимать
их из литературы/Wikipedia как установленные факты.

Исследование выполняется отдельно от Stages 1–28.

НЕ добавлять новый stage.
НЕ использовать Task52 distance как optimization criterion.

======================================================================
1. PRIMARY QUESTIONS
======================================================================

Q1.

    Имеет ли Voynich избыток соседних одинаковых tokens:

        w w

    относительно естественных controls и frequency-preserving null?

Q2.

    Имеет ли Voynich избыток runs:

        w w w
        w w w w
        w w w w w

    и насколько статистически необычны такие runs?

Q3.

    Имеет ли Voynich избыток соседних near-identical tokens:

        edit_distance(w_i, w_i+1) = 1?

Q4.

    Какие операции создают такие пары:

        substitution
        insertion
        deletion?

Q5.

    Сохраняется ли эффект после контроля:

        token frequency
        token length
        vocabulary size
        hapax fraction?

Q6.

    Что происходит с exact/near repetition при увеличении
    homophonic load?

Q7.

    Отличаются ли illustration labels от running text по repetition,
    vocabulary и token-neighborhood structure?

======================================================================
7. RUN LENGTH DISTRIBUTION
======================================================================

Вычислить:

    P(run length >= k)

для разумного диапазона k.

Не ограничиваться maximum observed run.

Сравнивать полное распределение с controls/nulls.

======================================================================
8. TOKEN FREQUENCY CONDITIONING
======================================================================

Exact repetitions сильно зависят от unigram frequency.

Поэтому нельзя сравнивать только raw run counts.

Для каждого frequent token оценить ожидаемое число adjacent repeats
при независимом размещении с той же частотой.

Основной null должен сохранять unigram counts.

======================================================================
9. NULL A — GLOBAL TOKEN SHUFFLE
======================================================================

Перемешать token sequence, сохраняя:

    N
    V
    exact token frequencies.

Если line boundaries являются частью primary analysis:

    выполнить отдельные варианты:

        global shuffle
        within-line shuffle.

Не смешивать их.

Минимум 1000 permutations, если computationally приемлемо.

======================================================================
10. NULL B — LINE-PRESERVING
======================================================================

Основной conservative null для run analysis:

    shuffle tokens внутри каждой строки.

Он сохраняет:

    line lengths
    line-specific vocabulary/frequencies приблизительно лучше,
    чем global shuffle.

Если строки слишком короткие для части estimands,
это документировать.

======================================================================
11. EXPECTED HOMOPHONIC EFFECT ON RUNS
======================================================================

Для position-independent random homophony:

    plaintext token A
        ->
    {a1 ... aH}

при independent uniform selection.

Если plaintext содержит run длины k:

    A A ... A,

то вероятность, что после первого выбора весь ciphertext run
останется exact:

    P(exact ciphertext run | plaintext run)
        = (1/H)^(k-1)

для uniform H.

Это является theoretical prediction Task60.

Для non-uniform selection использовать соответствующую:

    sum_j p_j^k

или эквивалентную точную вероятность.

======================================================================
13. RUN DOSE-RESPONSE
======================================================================

Для каждой homophonic series проверить:

    R2(H)
    runs>=3(H)
    runs>=4(H)
    runs>=5(H)
    maximum run(H).

Главный вопрос:

    разрушает ли увеличение H exact repetitions так, как предсказывает
    независимый homophonic selection?

Сравнить empirical decay с theoretical expectation.

======================================================================
14. IMPORTANT FREQUENCY-V1 HANDLING
======================================================================

Для frequency-v1 один H не применим ко всем plaintext types.

Поэтому theoretical expected run survival рассчитывать per source token:

    P_survival(w,k)

из фактической allocation/selection model Task55,

а затем агрегировать.

Не подставлять Hmax как H каждого token.

======================================================================
15. NEAR-REPETITION DEFINITION
======================================================================

Для каждой соседней пары:

    (T_i, T_i+1)

вычислить glyph-level Levenshtein distance:

    d(T_i,T_i+1).

Использовать EVA glyph units Task58/59, а не bytes/runes,
если они различаются.

Основной интерес:

    d = 0
    d = 1
    d = 2
    d >= 3.

======================================================================
16. DISTANCE-1 OPERATION TYPE
======================================================================

Для d=1 классифицировать операцию:

    SUBSTITUTION
    INSERTION
    DELETION.

Для substitution дополнительно сохранить:

    position of changed glyph.

Для insertion/deletion:

    position of inserted/deleted glyph.

======================================================================
17. NORMALIZED EDIT DISTANCE
======================================================================

Raw edit distance зависит от token length.

Дополнительно вычислить:

    normalized_distance =
        d(a,b) / max(len(a),len(b)).

Но primary "one glyph difference" claim проверять именно через:

    raw d = 1.

======================================================================
18. NEAR-REPETITION RATE
======================================================================

Вычислить минимум:

    P(d=0)
    P(d=1)
    P(d<=1)
    P(d<=2).

Отдельно:

    conditional P(d=1 | same length)
    substitution-only rate.

======================================================================
19. NEAR-REPETITION NULL
======================================================================

Token shuffle сохраняет:

    token vocabulary
    token frequencies
    token forms

и поэтому является естественным null.

Сравнить observed adjacent edit-distance distribution с:

    global token shuffle
    within-line shuffle.

Это отвечает на вопрос:

    соседствуют ли похожие формы чаще, чем ожидалось только из-за
    состава vocabulary?

======================================================================
20. FREQUENCY/LENGTH MATCHED NULL
======================================================================

Добавить более строгий control для d=1.

Для каждого observed adjacent pair построить random comparison pairs
сопоставимые по:

    token frequencies
    token lengths.

Цель:

    исключить эффект, когда несколько очень частых коротких tokens
    автоматически создают много edit-distance-1 pairs.

======================================================================
21. EDIT OPERATION POSITION
======================================================================

Для d=1 substitutions/insertions/deletions вычислить относительное
положение изменения:

    BEGIN
    MIDDLE
    END

или normalized position.

Это особенно важно вместе с Task59.

Проверить, концентрируются ли изменения:

    в начале token;
    в конце token;
    внутри.

======================================================================
22. GLYPH TRANSFORMATION MATRIX
======================================================================

Для substitution d=1 построить:

    source glyph -> target glyph

counts.

Поскольку направление соседства существует:

    T_i -> T_i+1,

матрица должна быть directional.

Также создать symmetric version для descriptive analysis.

======================================================================
23. MORPHOLOGICAL-LIKE FAMILIES
======================================================================

Использовать нейтральный термин:

    edit family.

Можно построить graph:

    token type = node
    edge if edit distance = 1.

Вычислить:

    connected components
    component sizes
    degree distribution

Это exploratory analysis.

24. ADJACENCY ENRICHMENT OF EDIT FAMILIES

Для каждой edit-distance-1 pair type:

Это отделяет:

======================================================================
40. RESULT CLASSIFICATION — EXACT RUNS
======================================================================

NORMAL:

    Voynich exact repetition/run distribution находится в диапазоне
    controls/null expectation.

ENRICHED:

    significant/effect-size meaningful excess exact repetitions.

STRONGLY_ENRICHED:

    excess сохраняется после frequency-preserving null и
    frequency conditioning, включая long runs.

======================================================================
41. RESULT CLASSIFICATION — NEAR REPETITION
======================================================================

NORMAL:

    d=1 adjacency объясняется vocabulary/frequency/length composition.

ENRICHED:

    d=1 adjacency выше matched null.

STRUCTURED_ENRICHMENT:

    enrichment дополнительно имеет устойчивую структуру:
        operation type
        operation position
        directional pairs
        mutation chains.

======================================================================
42. RESULT CLASSIFICATION — HOMOPHONY
======================================================================

Для simple random homophony:

COMPATIBLE:

    observed Voynich repetition profile находится в диапазоне,
    создаваемом/сохраняемом tested homophonic controls.

PARTIAL:

    weak token-order effect воспроизводится, но exact/near repetition
    profile воспроизводится лишь частично.

INCOMPATIBLE_WITH_SIMPLE_RANDOM_HOMOPHONY:

    homophony систематически разрушает свойства, которые Voynich
    демонстрирует с сильным enrichment.

Последнее НЕ отвергает:

    structured homophony
    context-dependent homophony
    token formation rules
    natural-language morphology
    copying/generative processes.

======================================================================
43. RESULT CLASSIFICATION — LABELS
======================================================================

SAME_PROCESS_COMPATIBLE:

    labels выглядят как size-matched sample running Voynich.

LEXICALLY_DISTINCT:

    labels значительно отличаются по vocabulary/repetition,
    но сохраняют общую glyph/token structural organization.

STRUCTURALLY_DISTINCT:

    отличаются также positional/edit-neighborhood properties.

INCONCLUSIVE:

    sample size недостаточен.

Не интерпретировать автоматически как "labels are names".
