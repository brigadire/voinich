Task67 — Recoverability and Information-Loss Analysis:
Can Voynich-Like Constrained Encoding Preserve a Recoverable Message?

Цель

Проверить фундаментальный вопрос, возникший после Task66:

    Может ли transformation architecture, создающая Voynich-like
    constrained token structure, одновременно сохранять достаточно
    информации исходного текста для обратного восстановления?

И отдельно:

    Может ли изначально recoverable encoding стать практически или
    математически необратимым после небольшого количества ошибок
    шифрования, переписывания, segmentation или transcription?

Task67 НЕ является попыткой дешифровать Voynich.

Voynich используется только как statistical target / structural reference.

Основные эксперименты выполняются на synthetic known-plaintext corpora,
где ground truth известен.

======================================================================
1. MOTIVATION FROM TASK66
======================================================================

Task66 показал:

    CONSTRAINED_FORMATION_REQUIRED

как единственный явно необходимый operation class.

Одновременно лучшие complex candidates M10/M11 имеют относительно
слабую measurable dependence output от plaintext.

Возникает альтернатива:

A. ENCODING-LIKE

    plaintext существенно определяет ciphertext,
    и сообщение recoverable;

B. INPUT-CONDITIONED GENERATOR

    plaintext влияет на output,
    но основную информацию определяет собственная token grammar,
    и исходное сообщение практически теряется.

Task67 должен количественно разделить эти случаи.

======================================================================

Исследовать цепочку:

    P

      v

      v
    C

======================================================================
3. THREE DISTINCT QUESTIONS
======================================================================

Task67 должен строго разделять:

Q1. CLEAN RECOVERABILITY

    Сколько информации сохраняет сам transformation?

Q2. ERROR ROBUSTNESS

    Насколько быстро падает recoverability при повреждении ciphertext?

Q3. IDENTIFIABILITY

    Если exact plaintext восстановить нельзя,
    насколько велико множество plausible preimages?

Не смешивать эти три понятия в одну метрику.

======================================================================
4. NO VOYNICH DECRYPTION
======================================================================

Запрещено:

    обучать decoder на Voynich;
    искать plaintext Voynich;
    оптимизировать decoder под Voynich;
    выбирать key/state по Voynich;
    интерпретировать recovered synthetic strings как
    "модель расшифровки Voynich".

Task67 исследует только свойства классов механизмов.

======================================================================
11. DECODER CLASSES
======================================================================

Для каждого mechanism использовать максимально честный decoder.

Минимум:

A. EXACT INVERSE

    если transformation математически обратим.

B. KEY/STATE-AWARE DECODER

    decoder знает algorithm + key/state initialization.

C. OPTIMAL LOCAL DECODER

    выбирает наиболее вероятный input unit для output.

D. SEQUENCE DECODER

    использует допустимую последовательную структуру plaintext.

Допустим:

    dynamic programming
    Viterbi
    beam search

если они естественно следуют из known encoder.

======================================================================
12. DECODER KNOWLEDGE LEVELS
======================================================================

Разделить минимум:

LEVEL 0:

    ciphertext only.

LEVEL 1:

    encoder family known.

LEVEL 2:

    encoder parameters known.

LEVEL 3:

    key / initial state known.

LEVEL 4:

    plaintext language model additionally known.

Это позволит различить:

    cryptographic secrecy

от:

    irreversible information loss.

======================================================================
13. PRIMARY CLEAN METRICS
======================================================================

Минимум:

    exact glyph recovery rate

    exact token recovery rate

    sequence edit distance

    normalized character edit distance

    word error rate

    recovered plaintext entropy

    conditional entropy H(P|C)

    mutual information I(P;C)

где корректно вычислимо/оцениваемо.

======================================================================
14. INFORMATION RETENTION RATIO
======================================================================

Ввести:

    R_I = I(P;C) / H(P)

или хорошо обоснованный estimator analogue.

Отдельно сообщать estimator bias/limitations.

Не использовать R_I как единственную recoverability metric.

======================================================================
15. EXACT MESSAGE RECOVERY
======================================================================

Для коротких blocks дополнительно измерять:

    P(P_hat == P).

Использовать несколько block sizes:

    8
    16
    32
    64
    128 input units

где computationally feasible.

Это покажет accumulation ambiguity с длиной сообщения.

======================================================================
16. PREIMAGE MULTIPLICITY
======================================================================

Для lossy/ambiguous mechanisms оценить:

    N(C) = number of plausible plaintext preimages

для коротких blocks.

Если exact counting невозможен:

    lower bound
    upper bound
    beam-based estimate

с явным статусом.

======================================================================
17. AMBIGUITY GROWTH
======================================================================

Главная характеристика:

    log2 N(C) / input_length.

Если:

    N(C)

экспоненциально растёт с длиной,

это сильный признак intrinsic ambiguity.

======================================================================
18. EQUIVOCATION
======================================================================

Где возможно оценить:

    H(P | C).

Интерпретация:

    ≈0      clean recoverable

    >0      ambiguity

    large   substantial information loss.

Не смешивать с uncertainty из-за неизвестного key.

======================================================================
19. KEY-UNKNOWN VS INFORMATION-LOST
======================================================================

Критический тест.

Если:

    decoder без key плох,

но:

    decoder с exact key/state восстанавливает P,

классификация:

    SECRET_BUT_RECOVERABLE.

Если даже exact key/state недостаточно:

    INTRINSICALLY_AMBIGUOUS

или:

    LOSSY.

======================================================================
20. ERROR CHANNELS
======================================================================

После clean baseline вносить corruption только в ciphertext.

Минимум:

A. GLYPH_SUBSTITUTION

B. GLYPH_DELETION

C. GLYPH_INSERTION

D. TOKEN_BOUNDARY_INSERTION

E. TOKEN_BOUNDARY_DELETION

F. TOKEN_MERGE

G. TOKEN_SPLIT.

======================================================================
21. TRANSCRIPTION CONFLATION
======================================================================

Отдельный важный error channel:

    GLYPH_CONFLATION.

Выбрать случайные пары output glyph classes:

    a,b -> x.

Это моделирует ситуацию, когда два функционально различных знака
современная transcription system считает одним знаком.

Проверить несколько conflation fractions.

======================================================================
22. TRANSCRIPTION SPLITTING
======================================================================

Обратный control:

    GLYPH_SPLITTING.

Один functional glyph случайно транскрибируется как:

    a1 / a2

по frozen stochastic rule.

Это моделирует искусственное различение вариантов одного знака.

======================================================================
23. SEGMENTATION ERRORS
======================================================================

Особое внимание boundary errors.

Для constrained token systems проверить:

    delete one boundary
    insert one boundary
    shift boundary ±1 glyph.

Измерять не только global rate, но последствия ОДНОЙ ошибки.

======================================================================
24. SINGLE-ERROR PROPAGATION
======================================================================

Для каждого mechanism:

внести ровно одну ошибку в позицию i.

Измерить:

    number of incorrectly recovered units after i

и:

    distance until resynchronization.

Создать:

    ERROR_PROPAGATION.tsv.

======================================================================
25. RESYNCHRONIZATION LENGTH
======================================================================

Определить:

    L_sync

= число output/input units после ошибки до восстановления
correct decoder alignment/state.

Если recovery больше не происходит до конца block:

    CATASTROPHIC_DESYNC.

======================================================================
26. STATEFUL CATASTROPHE TEST
======================================================================

Особенно для G+S / M+S+G:

если decoder state зависит от ciphertext:

    S_{i+1}=F(S_i,C_i),

проверить, приводит ли одна ошибка к:

    permanent state divergence.

Сравнить с:

    state depends only on position
    state depends on plaintext
    explicit reset points.

    5%

если corpus size позволяет.

Не считать процент единственным экспериментом:

28. ERROR REPLICATES

    screening >= 30

29. ERROR LOCATION

    token-initial

======================================================================
30. VALID-FORM ERROR
======================================================================

Для constrained formation разделить ошибки:

A. DETECTABLE

    corruption создаёт invalid output form.

B. UNDETECTABLE

    corruption превращает один valid token в другой valid token.

Создать:

    ERROR_DETECTABILITY.tsv.

======================================================================
31. D=1 NETWORK CONNECTION
======================================================================

Использовать Task60 insight:

    dense edit-distance-one structure.

Для synthetic candidates измерить:

    probability that one-glyph corruption maps
    valid token -> another valid token.

Сравнить с Voynich edit geometry как structural reference.

Не утверждать реальную Voynich error rate.

======================================================================
32. ERROR CORRECTION POTENTIAL
======================================================================

Измерить минимальные расстояния между valid output forms.

Оценить:

    detectable error capacity

и:

    uniquely correctable single-error fraction.

Это coding-theory diagnostic,
не утверждение о deliberate error-correcting code.

======================================================================
33. RESET / CHECKPOINT EXPERIMENT
======================================================================

Для stateful candidates проверить synthetic variants:

    no reset

    reset every token

    reset every line-sized block

    reset every page-sized block

    reset every N units.

Это единственное разрешённое modification family Task67,
поскольку оно исследует robustness, а не Voynich fit.

Не выбирать N по Voynich target.

======================================================================
34. PURPOSE OF RESET TEST
======================================================================

Ответить:

    требуется ли периодическая resynchronization,
    чтобы механизм был практически usable?

Если без reset:

    one error -> catastrophic remainder corruption,

а с reset recovery локализуется:

    RESET_REQUIRED_FOR_ROBUSTNESS.

35. SCRIBAL ERROR MODEL
======================================================================

Не заявлять реальные medieval error rates.

Task67 использует synthetic error channels.

Назвать:

    scribal-like corruption

а не:

    historical scribal error model.

======================================================================
36. CASCADE MODEL
======================================================================

Проверить композицию:

    clean ciphertext
        ->
    scribal-like corruption
        ->
    transcription conflation/splitting
        ->
    segmentation errors.

То есть:

    C -> C1 -> C2 -> C3.

Это моделирует накопление нескольких независимых damage layers.

37. DAMAGE ORDER
======================================================================

Где операции некоммутативны, проверить минимум:

    corruption -> transcription

и:

    transcription -> segmentation.

Не перебирать все permutations без необходимости.

43. GENERATOR CONTROL
======================================================================

Обязательный negative control:

создать output generator с той же constrained grammar,
но plaintext заменить random/shuffled input.

Проверить recoverability.

Он должен демонстрировать:

    Voynich-like form possible

при:

    near-zero message recovery.

Это calibrates INPUT-CONDITIONED_GENERATOR class.

44. SAME-FINGERPRINT / DIFFERENT-RECOVERY TEST
======================================================================

Искать пары mechanisms с похожим Task58–65 fingerprint,
но разной recoverability.

Это один из центральных результатов Task67.

Если найдены:

    statistical similarity to Voynich does NOT determine decryptability.

======================================================================
45. FINGERPRINT VS INFORMATION FRONTIER
======================================================================

Для candidates построить двумерное пространство:

    X = Voynich fingerprint compatibility
    Y = plaintext recoverability/information retention.

Создать:

    FINGERPRINT_INFORMATION_FRONTIER.tsv.

Нас интересует наличие верхнего правого региона:

    Voynich-like
        +
    recoverable.

======================================================================
46. PARETO ANALYSIS
======================================================================

Candidate A dominates B, если:

    fingerprint compatibility >= B

и:

    recoverability >= B

с хотя бы одним strict improvement.

Не сворачивать всё в один arbitrary weighted score.

======================================================================
47. CRITICAL OUTCOME A
======================================================================

Если существует mechanism:

    high Voynich compatibility
    +
    high clean recoverability
    +
    reasonable error robustness,

вердикт:

    RECOVERABLE_VOYNICH_LIKE_ENCODING_EXISTS.

Это не означает, что Voynich использует этот mechanism.

======================================================================
48. CRITICAL OUTCOME B
======================================================================

Если:

    Voynich compatibility растёт
    только при резком падении recoverability,

вердикт:

    FORMATION_INFORMATION_TENSION.

Это означает экспериментальный trade-off:

    constrained formation vs message retention.

======================================================================
49. CRITICAL OUTCOME C
======================================================================

Если clean candidate recoverable:

    R_clean high

но небольшая corruption вызывает:

    R_error -> collapse,

вердикт:

    FRAGILE_RECOVERABLE_ENCODING.

Это непосредственно поддерживает возможность:

    original encoding recoverable,
    surviving copy potentially not.

Не утверждать, что именно это произошло с Voynich.

======================================================================
50. CRITICAL OUTCOME D
======================================================================

Если даже при:

    exact encoder
    exact parameters
    exact key/state
    zero errors

plaintext плохо recoverable:

    INTRINSIC_INFORMATION_LOSS.

Это принципиально отличается от cryptanalytic difficulty.

======================================================================
51. CRITICAL OUTCOME E
======================================================================

Если clean transformation ambiguous,
но language prior восстанавливает большую часть plaintext:

    CONTEXT_RECOVERABLE_ENCODING.

Это особенно интересный класс для несовершенной historical-like
manual system, но исторических выводов Task67 не делает.

======================================================================
52. CRITICAL OUTCOME F
======================================================================

Если:

    one boundary/glyph error

уничтожает recovery до reset/end:

    DESYNCHRONIZATION_FRAGILITY.

Отдельно сообщить, спасают ли periodic resets.

======================================================================
53. MATHEMATICAL VS PRACTICAL IRREVERSIBILITY
======================================================================

Для каждого mechanism классифицировать отдельно:

MATHEMATICALLY_REVERSIBLE

    unique inverse exists given required secrets.

AMBIGUOUS_BUT_DECODABLE

    multiple inverses, context often resolves.

PRACTICALLY_FRAGILE

    clean inverse exists, realistic synthetic corruption destroys recovery.

INTRINSICALLY_LOSSY

    information destroyed during encoding.

GENERATOR_LIKE

    output largely independent of plaintext.

Не объединять категории.

======================================================================
54. TRANSCRIPTION-LEVEL IRREVERSIBILITY
======================================================================

Отдельно определить случаи:

    encoder reversible

но:

    glyph conflation
    или
    segmentation collapse

делает observed representation many-to-one.

Классификация:

    REPRESENTATION_INDUCED_INFORMATION_LOSS.

======================================================================
55. RAW GLYPH VS EVA-LIKE REPRESENTATION
======================================================================

Если implementation позволяет:

хранить synthetic "physical glyph identities"
до transcription mapping.

Сравнить recovery:

    raw synthetic ciphertext

vs

    EVA-like conflated transcription.

Это напрямую моделирует потерю distinction на уровне transcription.

======================================================================
56. DO NOT ASSUME EVA IS WRONG
======================================================================

Synthetic conflation experiment НЕ является утверждением,
что EVA действительно объединяет разные cipher symbols.

Формулировка только:

    если такое conflation существует,
    каков потенциальный ущерб recoverability?

======================================================================
57. TOKENIZATION ABLATION
======================================================================

Для candidates с explicit token grammar проверить recovery:

    correct boundaries

    boundaries removed

    boundaries corrupted

    boundaries reconstructed algorithmically.

Это покажет, являются ли spaces необходимой частью decoding key.

======================================================================
58. BOUNDARY RECOVERY
======================================================================

Если boundaries удалены:

попытаться восстановить их из constrained grammar без plaintext.

Измерить:

    boundary precision
    recall
    F1.

Если grammar сама позволяет почти идеально восстановить boundaries,
segmentation errors менее опасны.

======================================================================
59. ERROR LOCALIZATION
======================================================================

Для corrupted ciphertext decoder должен по возможности выдавать:

    suspected error positions.

Измерить:

    precision
    recall

error detection.

Это отдельно от plaintext recovery.

======================================================================
60. CONFIDENCE
======================================================================

Если decoder probabilistic:

сохранять posterior/confidence.

Проверить calibration:

    high-confidence wrong recovery

особенно опасна.

======================================================================
61. SILENT CORRUPTION
======================================================================

Определить:

    decoder returns valid plaintext candidate
    with high confidence
    but candidate != original.

Метрика:

    SILENT_ERROR_RATE.

Для dense valid-form spaces это потенциально важнее detected failure.

======================================================================
62. SHORT-BLOCK EXHAUSTIVE ANALYSIS
======================================================================

Для маленьких alphabet/block settings, где feasible:

полностью перебрать plaintext space.

Это даст ground-truth:

    collision count
    preimage distribution
    exact conditional entropy.

Использовать для проверки approximate estimators.

======================================================================

Разрешить отдельные diagnostics:

    oracle key
    oracle state
