Задача: реализовать reliability-aware soft structural space токенов.

Контекст

Уже реализованы:

- dictionary / dict-analyze;
- structural-analyze;
- sequence-analyze;
- structural-normalize;
- normalization-compare;
- structural-validate;
- structural-profile-stability;
- structural-reliability.

Последний этап дал эмпирические reliability curves для компонентов
structural profile:

    R_position(n)
    R_left(n)
    R_right(n)

Получено также, что:

- position profile стабилизируется значительно быстрее;
- left/right context требуют существенно больше observations;
- hard threshold classes нестабильны;
- недостаток данных нельзя интерпретировать как низкое similarity.

Поэтому необходимо отказаться от hard classes как основного
представления и построить continuous soft structural space.

Принцип:

    similarity != reliability

Нельзя использовать:

    adjusted_similarity = similarity * reliability

потому что низкая reliability означает "не знаем", а не
"токены различны".


============================================================
1. Новый инструмент
============================================================

Создать:

    soft-structural-space/

Предпочтительная структура:

    soft-structural-space/main.go
    internal/softstructural/...

Пример запуска:

    go run ./soft-structural-space \
      -dictionary dataset/dictionary.yaml \
      -analysis dataset/tokens_analysis.yaml \
      -reliability structural_reliability.yaml \
      -output soft_structural_space.yaml


============================================================
2. Не менять исходную structural similarity
============================================================

Переиспользовать существующие component similarities:

    position_similarity
    left_context_similarity
    right_context_similarity

Нельзя переписывать их независимо.

Использовать те же функции/internal packages, что и structural-analyze.

Для каждой пары A/B вычислить:

    position_similarity
    left_similarity
    right_similarity

и существующий:

    raw_structural_similarity

Raw similarity должна в точности совпадать с текущей моделью.


============================================================
3. Reliability компонентов
============================================================

Из structural_reliability.yaml загрузить:

    R_position(n)
    R_left(n)
    R_right(n)

Использовать уже реализованную interpolation logic.

Для token A:

    Rp(A) = R_position(countA)
    Rl(A) = R_left(countA)
    Rr(A) = R_right(countA)

Для пары A/B:

    Rp_pair
    Rl_pair
    Rr_pair

Использовать geometric mean:

    Rp_pair = sqrt(Rp(A) * Rp(B))

аналогично для left/right.

Это measure evidence support, а не similarity.


============================================================
4. Representation пары
============================================================

Для каждой pair сохранять минимум:

    token_a

    counts:
        a:
        b:

    similarities:

        left_context:
        right_context:

        ...

Не выдавать пока один новый "final similarity".


============================================================
5. Evidence-supported similarity
============================================================

Нужно подготовить representation для последующего sequence matcher.

Для каждой component хранить пару:

    value
    reliability

Например:

    position:
        similarity: 0.98
        reliability: 0.94

    left:
        similarity: 0.75
        reliability: 0.43

Это основной output.

Дополнительно разрешается вычислить diagnostic:

    weighted_evidence_mean =
        Σ(sim_i * rel_i) / Σ(rel_i)

НО:

- назвать именно diagnostic;
- не заменять им raw_structural_similarity;
- не использовать пока для clustering;
- не применять threshold.

Если Σrel_i = 0 -> null.


============================================================
6. Evidence strength
============================================================

Для пары определить:

    total_evidence_weight =
        Rp_pair + Rl_pair + Rr_pair

и normalized:

    evidence_strength =
        total_evidence_weight / 3

Диапазон [0,1].

Это мера качества наблюдений.

Она не должна зависеть от similarity values.


============================================================
7. Confidence categories только для вывода
============================================================

Допускается вспомогательная classification evidence_strength:

    very_low
    low
    medium
    high
    very_high

Но только presentation field.

Не использовать её в расчётах.

Пороговые значения явно задать в methodology.

Можно вообще не добавлять, если это не нужно.


============================================================
8. Candidate set
============================================================

Полный all-pairs для 8349 токенов слишком велик и мало полезен.

Нужно определить eligible token set.

По умолчанию:

    min-token-count = 10

Это даст около текущих 537 eligible tokens.

Для всех eligible tokens вычислить полный pairwise matrix.

При ~537 токенах это порядка 144k pairs — допустимо.

Не использовать старый ограниченный equivalence_candidates как вход.

Pairwise similarities должны вычисляться заново из полного structural
profile, чтобы soft space был полным.

============================================================
10. Nearest neighbors
============================================================

Для каждого token построить несколько neighbor rankings.

A. raw similarity:

    top_raw_neighbors

B. evidence-aware diagnostic:

    top_supported_neighbors

где ranking key может быть:

    diagnostic_weighted_similarity

но рядом обязательно сохранять:

    evidence_strength

C. high-evidence raw similarity:

например pairs с:

    evidence_strength >= configurable threshold

и внутри сортировать по raw similarity.

Добавить:

    -min-evidence-strength 0.7

только как presentation/filtering option, не как model threshold.


============================================================
11. Не смешивать "similar" и "well measured"
============================================================

Output должен позволять различать:

CASE A:

    similarity = 0.90
    evidence = 0.25

CASE B:

    similarity = 0.78
    evidence = 0.95

Не ранжировать автоматически A ниже B как универсальное правило.

Сохранять обе величины независимо.


============================================================
12. Soft neighborhood graph
============================================================

Построить диагностический graph representation.

Node:

    token

Edge:

    pair

Для edge хранить:

    raw similarity
    evidence strength

Но не threshold-cluster.

В YAML summary сохранить только edges, например:

    raw_similarity >= 0.60

или configurable:

    -graph-min-similarity 0.60

Это только для размера output.

Не использовать graph edges для inference.


============================================================
13. Mutual nearest neighbors
============================================================

Добавить diagnostic section:

    mutual_nearest_neighbors

Pair A/B включается, если:

    B входит в top-K A
    A входит в top-K B

Отдельно для:

    raw ranking
    supported ranking

Default:

    K=5

Это может дать более устойчивые локальные отношения без hard classes.

============================================================
18. Проверка symmetry
============================================================

Все pairwise quantities должны быть symmetric:

    sim(A,B) == sim(B,A)
    reliability(A,B) == reliability(B,A)

Хранить pair только один раз:

    token_a < token_b

лексикографически.


============================================================
19. Determinism
============================================================

Все:

- pair order;
- nearest-neighbor rankings;
- summary;
- TSV;

должны быть deterministic.

При равном score:

    lexicographic token ordering.

============================================================
24. Главный результат
============================================================

Инструмент должен дать для каждой пары токенов две независимые вещи:

    HOW SIMILAR ARE THEIR OBSERVED STRUCTURAL PROFILES?

и

    HOW RELIABLE IS THE EVIDENCE FOR THAT COMPARISON?

Это representation будет входом следующего эксперимента —
soft sequence matching.


============================================================
25. Исследовательский вопрос следующего этапа

Не реализовывать сейчас.

После построения soft structural space следующий эксперимент будет
проверять:

    существуют ли последовательности, которые редко совпадают
    token-for-token, но повторяются как устойчивые цепочки
    structurally similar tokens,

и превышает ли такой эффект matched random controls.
