Задача: frequency/reliability analysis структурных профилей токенов
и подготовка reliability model для последующего soft structural analysis.

Контекст

В проекте реализован structural-profile-stability.

Текущий результат:

eligible tokens: 537
candidate pairs: 9496
CV folds: 5
bootstrap runs: 200

Self-profile TRAIN–TRAIN similarity:

    position      0.940
    left context  0.812
    right context 0.815

Nearest-neighbor stability:

    top-1 recovery  0.562
    top-5 overlap   0.525
    top-10 Jaccard  0.431

Средний fold-level pair similarity stddev:

    0.0245

Hard-class stability:

    mean same-class fraction: 0.417
    always same class:        5 / 23
    never reproduced:         7 / 23

Bootstrap P(similarity >= 0.70) >= 0.95:

    chedy / shedy       1.000
    qokedy / qokeedy    0.955

Наблюдается выраженная зависимость nearest-neighbor stability
от частоты токена:

    count 10–19:
        top10 Jaccard 0.340
        top1 recovery 0.523

    count 160+:
        top10 Jaccard 0.688
        top1 recovery 0.824

При этом TRAIN→TEST context similarity значительно ниже TRAIN→TRAIN.

Необходимо определить:

1. насколько систематически stability зависит от количества наблюдений;
2. существует ли диапазон частот, после которого structural profiles
   становятся достаточно устойчивыми;
3. насколько различается зависимость от sample size для position,
   left-context и right-context;
4. можно ли на основании эмпирических данных построить reliability
   каждой компоненты structural profile.

На этом этапе НЕ изменять существующую similarity model и НЕ запускать
sequence normalization.


============================================================
1. Новый инструмент
============================================================

Создать:

    structural-reliability/

Максимально переиспользовать код:

Не создавать независимую копию формул similarity.


============================================================
2. Основной принцип
============================================================

Текущую structural similarity НЕ менять.

Использовать существующие:

    position_similarity
    left_context_similarity
    right_context_similarity

Новый анализатор измеряет reliability этих величин как функцию числа
наблюдений.

Reliability здесь означает только статистическую воспроизводимость
измеренного structural profile.

Это НЕ вероятность семантической эквивалентности.


============================================================
3. Частотные thresholds
============================================================

Провести анализ минимум для:

    count >= 10
    count >= 20
    count >= 40
    count >= 80
    count >= 160

Дополнительно:

    count >= 320

если токенов достаточно для осмысленной статистики.

Thresholds задавать:

    -count-thresholds 10,20,40,80,160,320

Это cumulative thresholds, а не bins.


============================================================
4. Frequency bins
============================================================

Одновременно сохранить независимые интервалы:

    10–19
    20–39
    40–79
    80–159
    160–319
    320+

Они нужны для локализации изменений stability.

Не смешивать cumulative thresholds и frequency bins.

============================================================
6. Nearest-neighbor stability
============================================================

Для каждого min_count:

    mean_top1_recovery
    median_top1_recovery

    mean_top3_overlap
    mean_top5_overlap
    mean_top10_jaccard

ВАЖНО:

При каждом threshold nearest neighbors должны выбираться только среди
токенов, eligible при данном threshold.

Иначе низкочастотные кандидаты продолжат влиять на геометрию
высокочастотного подпространства.


============================================================
7. Pair similarity stability
============================================================

Для каждого min_count использовать пары, у которых:

    count(A) >= threshold
    count(B) >= threshold

Сохранять:

    pairs

    similarity_stddev:
        mean
        median
        percentile_90
        percentile_95

    threshold_crossing_070_fraction

    bootstrap_probability_above_070_ge_095_fraction

Последняя метрика вычисляется только среди candidate pairs,
для которых bootstrap statistics доступны.


============================================================
8. Bootstrap CI width
============================================================

Для каждой pair:

    CI_width =
        percentile_975 - percentile_025

Для каждого frequency threshold:

    mean_ci_width
    median_ci_width
    percentile_90_ci_width

Ожидание:

если проблема преимущественно статистическая, CI width должен
систематически уменьшаться при росте count.

9. Continuous frequency relationship

Для каждого token сохранить:

    full_count

============================================================
10. Correlation with frequency
============================================================

Вычислить Spearman correlation между:

    log2(count)

и:

    TRAIN–TRAIN position stability
    TRAIN–TRAIN left stability
    TRAIN–TRAIN right stability

    TRAIN→TEST position stability
    TRAIN→TEST left stability
    TRAIN→TEST right stability

    top1 recovery
    top10 Jaccard

Сохранять:

    rho
    observations

Если в проекте уже есть реализация rank correlation — переиспользовать.

Не делать выводов только по p-value.

Если p-value реализовать просто и корректно — можно сохранить,
но он не обязателен.


============================================================
11. Pair-level frequency
============================================================

Для pair использовать несколько характеристик sample size:

    min_count = min(countA, countB)

    geometric_mean_count =
        sqrt(countA * countB)

Проверить Spearman correlation:

    log2(min_count)
        vs similarity_stddev

    log2(min_count)
        vs bootstrap_CI_width

    log2(geometric_mean_count)
        vs similarity_stddev

Ожидаем отрицательную корреляцию при frequency-limited instability.


============================================================
12. Subsampling experiment
============================================================

Это ключевой раздел.

Bins показывают разные токены, а нам нужно проверить причиноподобную
зависимость sample size -> stability на ОДНИХ И ТЕХ ЖЕ токенах.

Выбрать sufficiently frequent tokens, например:

    full count >= 160

Добавить параметр:

    -subsample-min-full-count 160

Для каждого такого token искусственно ограничивать число его
наблюдений до:

    10
    20
    40
    80
    160

если исходных occurrences достаточно.


============================================================
13. Как делать subsampling
============================================================

Subsampling unit — occurrence токена вместе с его наблюдаемым:

    line position
    predecessor
    successor

Не создавать искусственных текстов.

Нужно строить structural profile токена из случайно выбранного
подмножества его реальных occurrences.

Для каждого sample size выполнить, например:

    100 repetitions

CLI:

    -subsample-runs 100
    -subsample-seed 1


============================================================
14. Reference profile
============================================================

Для каждого frequent token:

    reference_profile =
        profile from all full-corpus occurrences

Для каждого subsample:

    compare:
        subsampled position profile
            vs reference position profile

        subsampled left profile
            vs reference left profile

        subsampled right profile
            vs reference right profile

Сохранять similarity.

Значение — средняя similarity subsampled profile к full reference.


============================================================
18. Интерполяция reliability
============================================================

Дополнительно реализовать простую функцию:

    reliability(component, n)

Правила:

- exact sample size -> lookup value;
- между точками -> linear interpolation по log2(n);
- ниже минимальной точки -> reliability минимальной точки;
- выше максимальной -> reliability максимальной точки.

Не экстраполировать reliability > observed maximum.

Эту функцию вынести в reusable internal package, поскольку она
понадобится следующему soft structural analyzer.


============================================================
19. Pair reliability
============================================================

Подготовить, но пока НЕ использовать для изменения similarity.

Для пары A/B определить component reliability, например:

    R_position_pair =

            R_position(countA),
            R_position(countB)

Аналогично:

    R_left_pair
    R_right_pair

Сохранить эти значения для candidate pairs.

============================================================

Но НЕ объединять их сейчас в новую structural similarity.

Не строить classes.

Не запускать normalization.

Цель — только посмотреть, насколько сильно reliability потенциально
меняет вклад компонентов.


============================================================
21. Component reliability comparison
============================================================

Особенно проверить гипотезу:

    position requires fewer observations
    than left/right context.

Для каждого component определить минимальный tested n, при котором:

    mean reliability >= 0.80
    mean reliability >= 0.90
    mean reliability >= 0.95

Если уровень не достигнут:

Пример результата:

============================================================
22. Token heterogeneity
============================================================

Средняя reliability может скрывать сильные различия между токенами.

Для каждого sample size сохранить distribution across tokens:

    percentile_10
    percentile_25
    median
    percentile_75
    percentile_90

отдельно для position/left/right.

Это позволит увидеть, например, что при n=80 средняя reliability
высока, но четверть токенов всё ещё крайне нестабильна.


============================================================
23. Context diversity
============================================================

Частота сама по себе может быть недостаточной.

Для каждого token сохранить full-corpus:

    unique_predecessors
    unique_successors

    left_entropy
    right_entropy

Проверить correlation stability также с:

    unique predecessors
    unique successors
    left entropy
    right entropy

Например, токен с count=200 и 150 различными successors может
требовать намного больше observations, чем токен с count=50 и
тремя successors.


============================================================
24. Effective observations diagnostic
============================================================

Не вводить новую production formula.

Но сохранить для исследования:

    count / max(1, unique_predecessors)

    count / max(1, unique_successors)

и проверить их correlation с соответствующей context stability.

Это может оказаться лучшим predictor reliability, чем raw count.

============================================================
32. Основные исследовательские вопросы
============================================================

Результат должен позволить ответить:

1. Является ли зависимость structural stability от frequency
   систематической?

2. Воспроизводится ли эта зависимость при subsampling одних и тех же
   высокочастотных токенов?

3. Сколько наблюдений приблизительно требуется для устойчивого
   positional profile?

4. Сколько наблюдений требуется для устойчивого left/right context
   profile?

5. Объясняет ли context diversity остаточную нестабильность лучше,
   чем raw token count?

6. Можно ли получить эмпирическую reliability(component, n),
   пригодную для следующего независимого эксперимента?


============================================================
33. Критерий дальнейшего решения
============================================================

Не вводить автоматический PASS/FAIL.

Но результат определит следующий шаг.

Если subsampling показывает явное улучшение position/left/right
reliability с ростом n:

    переходить к reliability-aware soft structural model.

Если position стабилизируется, а contexts остаются нестабильными
даже при больших n:

    рассмотреть отдельную роль position и context components.

Если даже frequent-token profiles нестабильны при controlled
subsampling:

    пересмотреть structural profile methodology до создания soft model.
