Task59 — Voynich Glyph Positional Specialization Analysis

Цель

Количественно проверить утверждение о сильной позиционной специализации
глифов в токенах Voynich:

    некоторые glyphs преимущественно или исключительно встречаются
    в начале token;
    некоторые — внутри;
    некоторые — в конце.

Определить:

1. насколько силён этот эффект;
2. ограничен ли он редкими glyphs или наблюдается у частых;
3. является ли эффект необычным относительно естественных текстов;
4. может ли он возникать при простой position-independent homophonic
   substitution;
5. как positional specialization связана с обнаруженным Task58
   glyph-edge coupling.

Task59 является независимым исследованием.

НЕ добавлять новый stage в основной pipeline.
НЕ использовать Task52 distance как optimization criterion.

======================================================================
1. PRIMARY HYPOTHESIS
======================================================================

Проверить гипотезу:

    Voynich glyph inventory имеет статистически выраженные
    positional classes:

        INITIAL
        MEDIAL
        FINAL
        FLEXIBLE

которые невозможно объяснить только частотой редких glyphs.

Особенно важно отличить:

    glyph observed 5 times, all FINAL

от:

    glyph observed 500 times, 495 FINAL.

======================================================================
2. INPUT
======================================================================

Основной корпус:

    ZL3b-x7.canonical.txt

Использовать тот же canonical corpus и EVA parsing conventions,
которые были зафиксированы в Task58.

Зафиксировать:

    corpus path
    SHA256
    token count
    token-type count
    glyph inventory
    parser/version.

Не создавать новую несовместимую EVA tokenization.

======================================================================
3. GLYPH DEFINITION
======================================================================

Переиспользовать Voynich EVA composite handling из Task58.

Не считать автоматически:

    Unicode character == glyph.

Явно документировать:

    EVA composites;
    uncertain glyphs;
    transcription markers;
    malformed/unknown tokens;
    singleton tokens.

Создать:

    GLYPH_POSITION_METHOD.md

с точным описанием parsing rules.

======================================================================
4. POSITION CLASSES
======================================================================

Для каждого occurrence glyph g определить положение:

    INITIAL
    MEDIAL
    FINAL
    SINGLETON

где SINGLETON означает token, состоящий из одного glyph.

Для двухглифового token:

    first  = INITIAL
    second = FINAL.

Не считать INITIAL/FINAL одновременно MEDIAL.

======================================================================
5. BASIC COUNTS
======================================================================

Для каждого glyph g вычислить:

    N(g)

    N_initial(g)
    N_medial(g)
    N_final(g)
    N_singleton(g)

и:

    P(initial | g)
    P(medial | g)
    P(final | g)
    P(singleton | g).

Output:

    GLYPH_POSITION_COUNTS.tsv

======================================================================
6. POSITIONAL SPECIALIZATION
======================================================================

Для каждого glyph вычислить минимум:

    dominant_position
    dominant_position_share

где:

    dominant_position_share =
        max(P(initial|g),
            P(medial|g),
            P(final|g))

SINGLETON анализировать отдельно.

Также вычислить entropy:

    H(position | glyph=g)

и normalized positional entropy:

    H_norm(g) = H(position|g) / log(K)

где K — число применимых positional categories.

Низкая entropy означает сильную specialization.

======================================================================
7. FREQUENCY STRATIFICATION
======================================================================

Результаты обязательно разделить по frequency.

Минимальные strata:

    N >= 5
    N >= 10
    N >= 30
    N >= 100
    N >= 300

или более подходящие thresholds, если они задаются ДО просмотра
результатов.

Основной вывод нельзя строить на extremely rare glyphs.

Отдельно вывести:

    high-frequency positional specialists.

======================================================================
8. STRICT SPECIALISTS
======================================================================

Отдельно найти glyphs, для которых:

    P(position|g) = 1.0

то есть glyph наблюдается только в одной позиции.

Но обязательно показывать N.

Output:

Glyph | N | Initial | Medial | Final | Dominant | Share

Никакого утверждения "exclusive glyph" без frequency count.

======================================================================
9. NEAR-STRICT SPECIALISTS
======================================================================

Также проверить thresholds:

    dominant share >= 0.90
    dominant share >= 0.95
    dominant share >= 0.99.

Это позволит отличить абсолютно запрещённую позицию от очень сильного
предпочтения.

======================================================================
10. POSITIONAL EXCLUSION
======================================================================

Для каждого glyph определить не только preferred, но и avoided positions.

Например:

    N(g) >= 100
    N_final(g) = 0.

Такие случаи особенно важны.

Создать:

    GLYPH_POSITION_EXCLUSIONS.tsv

с:

    glyph
    frequency
    excluded position
    expected count under null
    observed count
    significance/effect size.

======================================================================
11. NULL MODEL A — WITHIN-TOKEN SHUFFLE
======================================================================

Основной null:

Для каждого token occurrence сохранить:

    token length
    multiset of glyphs

но случайно переставить glyph order внутри token.

Это сохраняет:

    token boundaries
    token lengths
    glyph frequencies
    glyph co-occurrence within tokens

и уничтожает positional ordering.

Повторить достаточное число раз, например:

    1000 permutations

если computationally разумно.

Seed фиксировать.

======================================================================
12. NULL MODEL B — GLOBAL GLYPH SHUFFLE
======================================================================

Дополнительный null:

сохранить:

    token-length sequence
    global glyph frequencies

и перераспределить glyph occurrences по token slots.

Это более сильное разрушение структуры.

Не смешивать результаты Null A и Null B.

======================================================================
13. EFFECT SIZE
======================================================================

Не ограничиваться p-values.

Для каждого glyph сравнить observed positional concentration с null:

    observed dominant share
    null mean
    null SD
    z-score

и/или empirical percentile.

Также вычислить corpus-level statistic:

    mean/weighted mean positional entropy

и его положение относительно null distribution.

======================================================================
14. MULTIPLE TESTING
======================================================================

При per-glyph significance tests применять FDR correction.

Фиксировать:

    raw p
    q-value
    effect size
    N.

Не классифицировать glyph как specialist только по p-value.

======================================================================
15. NATURAL LANGUAGE CONTROLS
======================================================================

Использовать минимум:

    Doyle
    Longfellow
    Astafiev

если glyph representation корректно определена.

Для natural language:

    glyph = character

после явно документированной normalization.

Проверить:

    lowercase/case folding
    punctuation removal
    Unicode normalization
    encoding.

Для Astafiev сначала доказать корректную Cyrillic decoding.

Если encoding не подтверждена:

    NOT_APPLICABLE.

======================================================================
16. IMPORTANT NATURAL-LANGUAGE INTERPRETATION
======================================================================

Наличие positional specialization в natural language ожидаемо.

Причины могут включать:

    morphology;
    orthography;
    phonotactics;
    final letter forms;
    prefix/suffix structure.

Поэтому задача НЕ состоит в доказательстве:

    positional specialization => cipher.

Вопрос:

    отличается ли magnitude/profile Voynich от comparable natural texts?

======================================================================
17. POSITION-INDEPENDENT HOMOPHONY CONTROL
======================================================================

Это центральный mechanistic control Task59.

Создать glyph-level synthetic homophonic transformations естественного
текста, в которых:

    plaintext glyph
        ->
    one of H ciphertext glyphs

и выбор homophone:

    НЕ зависит от token position.

Минимально:

    H2
    H4
    H8.

Cipher glyphs должны быть настоящими atomic synthetic symbols,
а не opaque multi-character IDs x000001.

Например internal representation:

    integer glyph IDs

с корректной serialization.

======================================================================
18. HOMOPHONY PREDICTION
======================================================================

Для position-independent homophony ожидается:

если plaintext glyph встречается в нескольких positions,
его homophones должны приблизительно наследовать это positional
distribution.

То есть simple homophony сама по себе не должна систематически создавать
новые сильные positional classes.

Это является проверяемой гипотезой, а не предположением.

======================================================================
19. HOMOPHONY EXPERIMENT
======================================================================

Для каждого natural corpus:

    plaintext
    H2
    H4
    H8

сравнить:

    positional entropy
    dominant-position share
    number of strict specialists
    number of >=0.95 specialists
    exclusions
    corpus-level specialization.

Проверить dose-response.

======================================================================
20. RARE-HOMOPHONE SAFEGUARD
======================================================================

Homophony увеличивает число редких glyph types.

Следовательно она может искусственно увеличить число apparent strict
specialists просто из-за малых N.

Поэтому сравнение обязательно выполнять:

    frequency-stratified

и/или:

    frequency-matched.

Основной mechanistic вывод строить минимум на glyphs с достаточным N.

======================================================================
21. POSITIONAL HOMOPHONY POSITIVE CONTROL
======================================================================

Создать отдельный POSITIVE CONTROL:

    position-dependent homophony.

Например:

    plaintext glyph a

может иметь разные homophone pools:

    INITIAL: {a_i1, a_i2}
    MEDIAL:  {a_m1, a_m2}
    FINAL:   {a_f1, a_f2}.

Этот control должен демонстрировать, что analyzer действительно способен
обнаружить искусственно созданные positional classes.

Это НЕ модель Voynich и НЕ кандидат на дешифрование.

Это validation control инструмента.

======================================================================
22. STRUCTURED TOKEN POSITIVE CONTROL
======================================================================

Опционально, но желательно создать второй synthetic positive control:

    Token = Prefix + Core + Suffix

с разными glyph inventories:

    Prefix alphabet
    Core alphabet
    Suffix alphabet.

Analyzer должен обнаружить:

    initial specialists
    medial specialists
    final specialists.

Это проверяет чувствительность к structured token formation.

======================================================================
23. CONNECTION TO TASK58
======================================================================

Для каждого корпуса, где это содержательно применимо, вычислить также
Task58:

    glyph-edge MI.

Не переимплементировать metric.

Использовать существующий independent/rozanova-temerev implementation.

Основной вопрос:

    связана ли сильная positional specialization с высоким
    cross-token glyph-edge coupling?

======================================================================
24. IMPORTANT DISTINCTION
======================================================================

Не смешивать:

A.

    P(position | glyph)

— внутритокенную positional specialization;

и B.

    I(last(T_i); first(T_i+1))

— межтокенную boundary dependency.

Это разные свойства.

Task59 должен проверить их связь эмпирически.

======================================================================
25. CORRELATION ANALYSIS
======================================================================

    positional specialization statistic

    glyph-edge MI.

Если structured-token positive control создаёт specialization,
но не edge coupling, это важный результат.

Если для edge coupling требуется дополнительное boundary rule,
это также зафиксировать.

26. OPTIONAL LINE-POSITION CHECK

Не использовать exploratory результат как primary evidence.

======================================================================
29. RESULT CLASSIFICATION
======================================================================

Для simple position-independent homophony:

COMPATIBLE:

    homophonic controls способны воспроизводить magnitude/profile
    Voynich positional specialization после frequency matching.

PARTIAL:

    часть эффекта воспроизводится, но high-frequency exclusions или
    corpus-level specialization остаются существенно сильнее Voynich.

INCOMPATIBLE_WITH_SIMPLE_HOMOPHONY:

    simple homophony систематически не создаёт Voynich-like positional
    specialization, особенно среди frequent glyphs.

Последняя классификация означает только:

    simple position-independent homophony insufficient.

Она НЕ отвергает:

    position-dependent homophony;
    structured token encoding;
    natural language;
    constructed writing system;
    other cipher systems.

DEFINITION OF DONE
======================================================================

Task59 завершён, когда:

1. positional specialization Voynich измерена количественно;

2. rare и frequent glyph effects разделены;

3. strict и near-strict specialists перечислены с N;

4. эффект проверен минимум против within-token null;

5. выполнено сравнение с natural-language controls;

6. выполнены H2/H4/H8 position-independent homophony controls;

7. устранён rare-homophone confound;

8. position-dependent homophony использована как positive control;

9. желательно проверен structured-token positive control;

10. positional specialization сопоставлена с Task58 glyph-edge MI;

11. Wikipedia claim независимо подтверждён, уточнён или опровергнут;

12. сделан отдельный вывод о совместимости с SIMPLE
    POSITION-INDEPENDENT HOMOPHONY;

13. результат не интерпретирован как доказательство конкретного языка,
    шифра или дешифровки;

14. никаких изменений Stage 1–28 не сделано.
