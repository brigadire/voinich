Task44 — Distributed execution for generic stages 23–27

Цель

Добавить существующий deterministic remote executor к:

23. token-relation-validate
24. replicated-local-structure-audit
25. higher-order-sequence-validate
26. positional-continuation-validate
27. transition-network-validate

Не менять scientific algorithms, null models, RNG semantics, permutations,
thresholds, windows, folds, statistics или output schemas.

Перед реализацией для каждой стадии провести dependency/parallelism audit:

stage | expensive loop | natural work unit | RNG dependency | reduction order | distributable

Определить минимальную независимую единицу работы:
- permutation replicate;
- LOBO fold;
- block;
- candidate/relation;
- либо другую фактически существующую единицу.

Не распределять цикл, если независимость work units не доказана.

Использовать существующую инфраструктуру remote executor Task31–35:
- mTLS;
- coordinator/worker protocol;
- deterministic JobID;
- retry/reassignment;
- checkpoint/resume;
- worker elasticity;
- deterministic result reduction.

Критическое требование:

local/process/remote execution с одинаковыми scientific parameters и seed
должны давать byte-for-byte identical scientific outputs.

Если floating-point reduction зависит от порядка результатов:
сначала восстановить исходный deterministic logical order work units,
и только затем выполнять reduction.

Не заменять это tolerance-based equivalence.

CLI

Для distributable stages добавить стандартные параметры:

-executor goroutine|process|remote
-workers N
-remote-listen
-tls-cert
-tls-key
-client-ca
-remote-timeout
-remote-retries
-checkpoint   (где применимо)

По возможности использовать тот же общий код/config, который уже применяется
normalization-compare / structural-projection / conditional-regime.

Orchestrator

После реализации stages.go должен помечать реально распределяемые 23–27
как Executor=true.

При:

    pipeline-orchestrate manifest ... -executor remote ...

manifest должен передавать им remote executor + mTLS arguments.

Если какая-либо из 23–27 по результатам аудита не имеет безопасного
independent work unit, НЕ создавать фиктивную distribution:
оставить её local и документировать причину.

Performance

До изменения снять reduced-scale profile каждой стадии.

После реализации провести scaling study:

    local
    remote 1 worker
    remote 2 workers
    remote 5 workers
    remote 10 workers

Использовать реальный generic corpus:

    data_test/pg2097-2.txt

но reduced scientific scale, достаточный для profiling/scaling,
НЕ считать эти результаты научными.

Зафиксировать отдельно:
- total wall time;
- distributed section wall time;
- coordinator overhead;
- worker utilization;
- speedup;
- efficiency.

Не требовать ускорения там, где профиль показывает, что стадия слишком мала
или serial fraction доминирует.

Correctness oracle

Для каждой распределённой стадии:

1. local reference run;
2. remote run;
3. interrupted remote + resume;
4. worker disappearance/retry хотя бы на synthetic/reduced fixture.

Scientific outputs должны быть SHA256-identical.

Generic production run НЕ запускать в рамках Task44.

Definition of Done

При создании generic manifest с -executor remote все стадии 23–27,
для которых аудит доказал безопасную независимую декомпозицию,
действительно получают remote executor configuration и используют workers.

Распределение не меняет ни одного научного результата.
