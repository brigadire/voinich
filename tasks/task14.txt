Задача: Property-Trajectory Analysis для корпуса Voynich

Контекст

Предыдущие этапы показали:

1. В корпусе существуют пары токенов с аномально похожими distance-context distributions на расстояниях +1…+20.

Примеры:

- chedy / qokeey
- chol / daiin
- ol / y
- chey / ol
- dar / ol
- or / s
- r / s

Для многих из них mean JS similarity на +1…+5 существенно выше frequency-matched baseline.

2. Exact suffix similarity длины 2–3 почти нулевая.

Следовательно, после структурно близких токенов обычно НЕ следуют одинаковые конкретные последовательности.

3. Попытка объяснить дальний эффект через soft structural projection не дала специфического gain относительно random-space / smoothing controls.

Следовательно, следующая задача — не строить новые классы токенов, а проверить, сохраняются ли после разных исходных токенов сходные ТРАЕКТОРИИ СВОЙСТВ последующих токенов.

Основной исследовательский вопрос:

Если A и B имеют сходные дальние context distributions, появляются ли после них на одинаковых расстояниях токены со сходными формальными свойствами, даже если сами токены различны?


1. Общий принцип

Не заменять токены классами.

Не выполнять smoothing.

Не использовать structural projection.

Каждый наблюдаемый последующий токен X остаётся самим собой, но вместо его identity анализируется набор заранее определённых числовых свойств.

Для каждой исходной пары A/B строится:

property_vector(+1)
property_vector(+2)
...
property_vector(+N)

и сравниваются trajectory(A) и trajectory(B).


2. Источники данных

Использовать существующие данные проекта:

- исходный линейный корпус;
- словарь токенов;
- soft_structural_space.yaml;
- pair_decomposition / structural analyses;
- distance_context_pairs.yaml.

Не изменять существующие результаты.

Новый анализ должен быть отдельным модулем.


3. Набор свойств токена

Для каждого токена X сформировать fixed property vector.

Минимальный набор:

A. Frequency properties

- global_count
- log_global_count
- global_frequency_probability
- frequency_rank
- normalized_frequency_rank

B. Graphemic properties

- grapheme_length
- unique_grapheme_count

Не использовать graphemic similarity с исходным токеном.

Нужна только длина и простые формальные характеристики самого X.

C. Positional properties

- line_start_probability
- line_end_probability
- mean_position
- median_position
- normalized_mean_position, если доступна длина строки
- positional_entropy
- positional_specialization

D. Immediate-context properties

- predecessor_entropy
- successor_entropy
- effective_predecessor_count
- effective_successor_count
- unique_predecessor_count
- unique_successor_count

E. Directional restriction properties

- max_predecessor_probability
- max_successor_probability
- top3_predecessor_mass
- top3_successor_mass
- top5_predecessor_mass
- top5_successor_mass

F. Existing structural-space properties

Можно использовать только свойства самого токена, не projection.

Например:

- mean_structural_similarity_to_all
- max_structural_similarity
- structural_degree_above_0_5
- structural_degree_above_0_6
- structural_degree_above_0_7
- structural_centrality, если уже существует прозрачная метрика

Не использовать class/family membership как числовой признак основного режима.


4. Нормализация

Все свойства должны быть приведены к сопоставимому масштабу.

Для тяжёлых хвостов:

count → log1p(count)

Затем желательно z-score по всем eligible tokens.

Сохранять и raw, и normalized values.

Не нормализовать отдельно для каждой пары.


5. Eligible tokens

Сделать configurable minimum frequency:

--min-token-frequency

По умолчанию использовать тот же разумный порог, что и в structural-space analysis, например 10.

Редкие токены ниже порога:

- либо исключать из property-vector aggregation;
- либо учитывать отдельной категорией missing/low-reliability.

Решение должно быть явно документировано.


6. Exact-distance property distributions

Для исходного токена A и расстояния d собрать все X:

A ... X
      d

Для каждого свойства f вычислить distribution / summary:

E[f(X) | A, d]

А также желательно:

- median
- stddev
- p25
- p75

Минимально обязательна средняя normalized property value.

Получается вектор:

V(A,d) =
[
 mean(log_frequency),
 mean(grapheme_length),
 mean(successor_entropy),
 mean(positional_specialization),
 ...
]


7. Property trajectory

Для каждого token A построить:

V(A,1)
V(A,2)
...
V(A,N)

По умолчанию:

N = 20

CLI:

--max-distance


8. Pair comparison

Для каждой target pair A/B сравнивать:

V(A,d)
V(B,d)

на каждом exact distance.

Считать минимум:

- cosine similarity;
- Euclidean distance в normalized space;
- Manhattan distance;
- correlation между property vectors.

Основной показатель желательно сделать cosine similarity.

Но не заменять полный набор одним score.


9. Per-property difference

Для каждой пары и distance сохранять:

delta_f(d) =
    mean_f(A,d) - mean_f(B,d)

Это критически важно.

Нужно иметь возможность увидеть, какие именно свойства совпадают, а какие расходятся.


10. Trajectory similarity

Для пары считать:

mean_property_similarity_1_5
mean_property_similarity_6_10
mean_property_similarity_11_20

Также отдельно для каждого свойства:

trajectory_correlation(property)

Например:

frequency trajectory correlation
successor entropy trajectory correlation
grapheme length trajectory correlation
positional specialization trajectory correlation


11. Основные target pairs

Обязательно анализировать:

chedy / qokeey
chol / daiin
ol / y
chey / ol
dar / ol
ar / ol
dal / ol
qokain / qol
aiin / ar
or / s
r / s
or / r

и все 28 пар из предыдущего distance-context анализа.

CLI:

--pair A,B
--top N


12. Baseline

Для каждой target pair подобрать frequency-matched control pairs.

Использовать существующую логику matching:

- сходные counts;
- сходная reliability;
- при возможности сходное graphemic distance.

Но property trajectory не должна использовать graphemic distance как входной признак.

Для каждой target pair сравнить:

target trajectory similarity
vs
control distribution


13. Random baseline

Дополнительно построить baseline по большому числу случайных frequency-matched pairs.

Для каждой distance d и aggregated trajectory metric вывести:

median
P90
P95
P99

Для target pair вывести percentile rank.


14. Shuffled corpus control

Обязательный контроль.

Повторить property-trajectory analysis после:

- global shuffle;
- line-preserving shuffle.

Частоты токенов должны сохраняться.

Если trajectory similarity вызвана последовательным порядком корпуса, эффект должен уменьшаться после shuffle.


15. Property ablation

Чтобы понять источник эффекта, сделать analysis по группам признаков.

Минимум:

frequency-only
graphemic-form-only
position-only
context-complexity-only
structural-centrality-only
all-properties

Важно:

graphemic-form-only означает только intrinsic token properties вроде length, а не сходство написания A/B.


16. Leave-one-group-out

Для полного property vector сделать:

all minus frequency
all minus position
all minus context
all minus graphemic
all minus structural-centrality

Это позволит увидеть, не определяется ли весь эффект одной группой свойств.


17. PCA / low-dimensional diagnostic

Опционально, но желательно.

Построить PCA по property vectors всех токенов.

Не использовать PCA как основной анализ.

Для каждого target pair можно затем сравнить trajectories в PC1..PCk.

Это диагностическая визуализация.


18. Property trajectory plots

Для каждой сильной пары создать SVG.

Например:

plots/property_trajectory_or_s.svg
plots/property_trajectory_chol_daiin.svg

Не пытаться показать 20 свойств на одном графике.

Предпочтительно:

A. общий cosine similarity vs distance;

B. отдельные маленькие графики для наиболее информативных свойств.


19. Automatic informative-property ranking

Для каждой target pair определить свойства, которые:

- наиболее похожи между A и B;
- наиболее отличаются;
- наиболее устойчиво совпадают по distance.

Например:

property:
  successor_entropy
trajectory_correlation: 0.91
mean_absolute_difference: 0.12

Не интерпретировать семантически.


20. State-like trajectory diagnostic

Отдельно проверить, существует ли дискретное чередование профилей.

Например:

+1 high-frequency / low-entropy
+2 medium-frequency / high-entropy
+3 low-frequency / restricted
...

Не вводить HMM на этом этапе.

Но можно выполнить unsupervised clustering самих property vectors V(A,d).

Например k-means / hierarchical clustering для diagnostic purposes.

Если используется clustering, сделать sweep:

K = 2..10

и не выбирать "правильное" K вручную.


21. Transition between property states

Если diagnostic clustering реализован, можно построить:

state(d) → state(d+1)

Но этот результат считать предварительным.

Главный анализ остаётся continuous property trajectory.


22. Family-level analysis

Для existing structural families построить:

mean property trajectory
within-family dispersion
matched random-group dispersion

Особенно проверить family 2.

Но family-level анализ вторичен по отношению к pair-level.

25. Critical null question

Главная проверка:

Высокая ли property-trajectory similarity у target pairs по сравнению с:

- frequency-matched pairs;
- shuffled corpus;
- random pairs?

Если нет — результат отрицательный и должен быть явно зафиксирован.


26. Не использовать

Не использовать:

- semantic labels;
- operator / operand;
- command;
- grammar;
- morphology;
- part of speech;
- page categories;
- manuscript illustrations.

Не утверждать наличие state machine.


27. Возможные результаты

A. Strong positive result

Если target pairs сохраняют необычно похожие property trajectories относительно controls, это будет означать:

различные конкретные токены могут занимать сходные позиции относительно последовательности формальных состояний корпуса.

B. Group-specific result

Если совпадает только одна property group, например frequency/entropy, это сузит объяснение дальнего context similarity.

C. Negative result

Если target pairs не отличаются от controls, гипотеза property trajectories не подтверждается.

Это полноценный и полезный результат.


28. Главные исследовательские вопросы

Анализ должен ответить:

1. Имеют ли дальние контексты сильных structural pairs сходные формальные свойства?

2. Какие именно свойства создают это сходство?

3. Сохраняется ли сходство на +2, +3, +5, +10 и дальше?

4. Отличается ли эффект от frequency-matched controls?

5. Исчезает ли он после shuffle?

6. Можно ли объяснить ранее найденный long-range JS эффект небольшим числом устойчивых property trajectories?

7. Есть ли основания после этого переходить к latent-state моделям?
