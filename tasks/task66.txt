Task66 — Mechanism-Space Search I:
Minimal Transformation Families and Voynich Fingerprint

Цель

Перейти от описания статистических свойств Voynich к экспериментальному
поиску минимальной архитектуры преобразования, способной породить эти
свойства из обычного текста.

Tasks 58–65 дают рабочую совокупность ограничений:

1. слабая global token-order dependence;

2. сильная token-internal structure;

3. выраженная positional specialization glyphs;

4. низкая character conditional entropy;

5. плотное пространство близких token forms / giant d=1 family;

6. простой random homophonic substitution несовместим с полной
   совокупностью наблюдаемых свойств;

7. strong sequential copy/mutate mechanism не требуется;

8. существует broader local regime примерно на масштабе десятков tokens;

9. physical line boundary не является особой границей;

10. local structural similarity постепенно уменьшается с distance;

11. Currier/Hand/Section/Page объясняют только часть local structure;

12. sub-page distance decay сохраняется;

13. topology лучше описывается как MIXED_DRIFT_AND_STATES;

14. отдельный слабый adjacency residual остаётся возможным.

Task66 должен ответить:

    Какие минимальные классы преобразований обычного текста способны
    двигать его одновременно в направлении fingerprint Voynich?

Это НЕ задача дешифровки.

Это НЕ поиск исторически известных шифров.

Это НЕ попытка подобрать один сложный "Voynich cipher".

======================================================================
1. CENTRAL PRINCIPLE
======================================================================

Не начинать с конкретных исторических cipher families.

Исследовать свойства transformation architecture:

    memoryless vs stateful

    fixed vs evolving state

    deterministic vs stochastic output

    plaintext boundaries preserved vs regenerated

    unconstrained vs constrained output forms

    one-to-one vs one-to-many representation

    stationary vs macro-state switching.

Главный объект исследования:

    transformation family,

а не название шифра.

======================================================================
2. PRIMARY QUESTION
======================================================================

Для каждого механизма F:

    Plaintext P
        |
        v
       F
        |
        v
    transformed corpus C

измерить:

    fingerprint(C)

и сравнить:

    fingerprint(P)
    fingerprint(C)
    fingerprint(Voynich).

Главный вопрос:

    какие свойства F необходимы для движения нескольких
    независимых metric families одновременно к Voynich?

======================================================================
3. NO HISTORICAL PLAUSIBILITY FILTER
======================================================================

НЕ отбрасывать механизм потому, что:

    неизвестен исторический аналог;
    неизвестно соответствующее устройство;
    механизм кажется сложным для XV века.

Task66 исследует математическую/алгоритмическую совместимость.

Historical feasibility является отдельным будущим вопросом.

======================================================================
4. NO DECRYPTION
======================================================================

Не применять inverse transformations к Voynich.

Не искать plaintext.

Не оптимизировать key/state непосредственно по Voynich sequence.

Voynich используется только как target statistical fingerprint.

======================================================================
5. DEVELOPMENT / TEST SEPARATION
======================================================================

Критически важно избежать механизма, специально подогнанного под Voynich.

Использовать:

    DEVELOPMENT metrics
    HELD-OUT metrics.

До mechanism search зафиксировать:

    TASK66_DESIGN.md
    FINGERPRINT_DEVELOPMENT.tsv
    FINGERPRINT_HELDOUT.tsv
    DESIGN_FROZEN.

Held-out metrics запрещено использовать:

    для выбора mechanism family;
    parameter tuning;
    threshold tuning.

Открыть held-out fingerprint только после freeze выбранных candidates.

======================================================================
6. PLAINTEXT CORPORA
======================================================================

Минимум:

    Doyle
    Longfellow
    Astafiev.

Все transformation families должны применяться независимо
к каждому корпусу.

Механизм, работающий только на Doyle:

    CORPUS_SPECIFIC

и не считается общим объяснением.

======================================================================
7. LENGTH NORMALIZATION
======================================================================

Для сравнений использовать corpus sizes, сопоставимые с Voynich.

Если corpus больше:

    deterministic blocks / matched samples.

Не позволять различию sample size определять entropy,
vocabulary graph или local-regime metrics.

======================================================================
8. AUTHORITATIVE VOYNICH TARGET
======================================================================

Использовать только frozen authoritative artifacts Tasks58–65.

Не пересчитывать Voynich новым альтернативным способом,
если authoritative metric уже существует.

Для каждой target metric хранить:

    source task
    artifact
    field
    value
    status.

Создать:

    VOYNICH_TARGET_MANIFEST.tsv.

======================================================================
9. METRIC FAMILIES
======================================================================

Fingerprint разделить минимум на независимые conceptual families:

A. TOKEN ORDER

    authoritative Task58 metrics.

B. POSITIONAL STRUCTURE

    authoritative Task59 metrics.

C. REPETITION / EDIT GEOMETRY

    authoritative Task60 metrics.

D. CHARACTER ENTROPY

    authoritative Task61 metrics.

E. TOKEN FORMATION

    authoritative Task62 metrics.

F. LOCAL TRANSITION

    authoritative Task63 metrics.

G. LOCAL REGIME TOPOLOGY

    authoritative Tasks64–65 metrics.

Не заменять целую family одним удобным proxy.

======================================================================
10. METRIC STATUS
======================================================================

Сохранить семантику Task52:

    VALUE
    COMPLETED_EMPTY
    NOT_APPLICABLE
    NOT_COMPUTED
    MISSING_ARTIFACT
    FAILED/INVALID.

Не превращать missing metrics в zero.

======================================================================
11. BASELINE
======================================================================

Каждый plaintext corpus сначала прогнать без transformation:

    IDENTITY.

Это baseline:

    M0 = IDENTITY.

Все improvements измерять относительно M0.

======================================================================
12. FAMILY M1 — MEMORYLESS SUBSTITUTION
======================================================================

Контрольный механизм:

    output symbol depends only on current plaintext symbol.

Минимум:

    monoalphabetic deterministic substitution.

При relabeling без structural changes fingerprint должен
в основном сохраняться.

Это sanity control.

======================================================================
13. FAMILY M2 — MEMORYLESS HOMOPHONY
======================================================================

Использовать corrected authoritative Task59-style
position-independent homophony.

Проверить минимум несколько H:

    H=2
    H=4
    H=8

или уже frozen comparable settings.

Task66 не должен повторно интерпретировать Task59;
это calibration mechanism.

======================================================================
14. FAMILY M3 — CONSTRAINED OUTPUT FORMATION
======================================================================

Ввести mechanism, который преобразует входные units в output tokens
через ограниченную grammar-like систему формирования token forms.

Критически:

    mechanism должен быть обучен/определён БЕЗ Voynich target tuning.

Разрешено использовать generic synthetic grammar.

Не разрешено просто использовать Task62 model,
обученную на Voynich, как доказательство преобразования plaintext.

M3 должен проверять сам принцип:

    constrained output token space.

======================================================================
15. M3 MINIMAL FORM
======================================================================

Например, output token генерируется как:

    START -> CORE* -> END

с небольшим набором position-dependent symbol classes.

Параметры выбирать:

    заранее
    или
    по plaintext-independent synthetic design.

Проверить несколько frozen complexity levels.

======================================================================
16. FAMILY M4 — STATEFUL SUBSTITUTION
======================================================================

Ввести внутреннее состояние:

    S_i.

Transformation:

    C_i = G(P_i, S_i)

    S_{i+1} = F(S_i, P_i, C_i)

Минимальная версия должна быть максимально простой.

Например:

    finite cyclic state.

Не добавлять constrained token grammar.

Цель:

    изолировать эффект памяти.

======================================================================
17. STATE UPDATE VARIANTS
======================================================================

Минимум проверить отдельно:

A.

    S_{i+1}=F(S_i)

B.

    S_{i+1}=F(S_i,P_i)

C.

    S_{i+1}=F(S_i,C_i)

Не смешивать варианты в один mechanism.

======================================================================
18. FAMILY M5 — SLOW STATE DRIFT
======================================================================

Создать механизм, где state изменяется медленно относительно
output units.

Например:

    S changes every N units

или:

    small deterministic transition per unit.

Проверить заранее заданные characteristic scales,
включая приблизительно:

    5
    20
    80 tokens/units

но НЕ подбирать scale по Task65 optimum.

Цель:

    проверить способность evolving state создавать
    local distance decay.

======================================================================
19. FAMILY M6 — DISCRETE MACRO-STATES
======================================================================

Добавить небольшой набор:

    M ∈ {M1 ... MK}

где M изменяет параметры transformation.

Использовать заранее фиксированные:

    K=2
    K=5

как structural probes.

Не утверждать, что K=5 соответствует пяти Voynich regimes.

======================================================================
20. FAMILY M7 — MIXED STATE
======================================================================

Комбинация:

    macro-state M
        +
    evolving local state S_i.

То есть:

    C_i = G(P_i, M_i, S_i).

Это minimal analogue Task65:

    MIXED_DRIFT_AND_STATES.

Не добавлять constrained token formation на этом этапе.

======================================================================
21. FAMILY M8 — GENERATED TOKEN BOUNDARIES
======================================================================

Критический отдельный механизм.

Не считать plaintext word == output token.

Вход рассматривать как continuous sequence of units.

Transformation самостоятельно создаёт output grouping:

    plaintext stream
        ->
    transformed units
        ->
    generated token boundaries.

======================================================================
22. BOUNDARY GENERATION
======================================================================

Проверить минимум:

A. fixed output group length;

B. random length from frozen distribution;

C. state-dependent group termination.

Не использовать empirical Voynich token-length sequence напрямую.

Допустимо использовать broad matched mean/variance только в
отдельном explicitly TARGET_INFORMED control, который не участвует
в blind model selection.

======================================================================
23. FAMILY M9 — CONSTRAINED GROUP FORMATION
======================================================================

Объединить:

    generated grouping
        +
    constrained output forms.

Это проверяет гипотезу:

    Voynich token является единицей encoding algorithm,
    а не plaintext word.

======================================================================
24. FAMILY M10 — STATEFUL CONSTRAINED FORMATION
======================================================================

Только после анализа M1–M9 разрешить:

    evolving state
        +
    constrained output token formation.

Архитектура:

    plaintext stream
         |
         v
       S_i
         |
         v
    token-form generator
         |
         v
    Voynich-like tokens.

======================================================================
25. FAMILY M11 — MIXED STATEFUL CONSTRAINED FORMATION
======================================================================

Наиболее сложный допустимый механизм Task66:

    macro-state M
         |
         v
    local state S_i
         |
         v
    constrained token generator G
         |
         v
    output tokens.

Не добавлять дополнительные layers сверх этого.

======================================================================
26. COMPOSITIONAL ABLATION
======================================================================

Для M10/M11 обязательно сравнить:

    G only

    S only

    M only where applicable

    G + S

    M + S

    M + G

    M + S + G.

Цель:

    определить marginal contribution каждого operation class.

======================================================================
27. TOKEN INPUT QUESTION
======================================================================

Проверить два режима отдельно:

WORD_PRESERVING:

    plaintext word -> output token(s).

STREAM:

    plaintext word boundaries игнорируются.

Не смешивать результаты.

Это один из центральных вопросов Task66.

======================================================================
28. INFORMATION PRESERVATION
======================================================================

Каждый механизм классифицировать:

    REVERSIBLE

    REVERSIBLE_WITH_KEY_STATE

    LOSSY

    AMBIGUOUS.

Task66 допускает все четыре.

Не исключать lossy/ambiguous transformations.

======================================================================
29. DECRYPTION AMBIGUITY
======================================================================

Для lossy/ambiguous mechanisms оценить:

    average preimage multiplicity

или другую простую меру ambiguity,
если она вычислима.

Это descriptive metric.

Не требовать однозначной дешифровки.

======================================================================
30. OUTPUT SIZE
======================================================================

Для каждого механизма фиксировать:

    input symbols
    output glyphs
    input words
    output tokens
    expansion ratio.

Механизм не должен получать хороший fingerprint просто ценой
неограниченного expansion.

======================================================================
31. COMPLEXITY ACCOUNTING
======================================================================

Для каждого mechanism считать structural complexity:

    number of states
    number of symbol classes
    number of free transition parameters
    number of output rules
    number of stochastic distributions.

Создать:

    MECHANISM_COMPLEXITY.tsv.

Не требуется универсальная Kolmogorov complexity.

======================================================================
32. NO FREE PER-TOKEN PARAMETERS
======================================================================

Запрещены:

    token-specific keys
    page-specific fitted tables
    Voynich-token lookup tables
    parameter per observed Voynich form.

Mechanism должен быть компактнее output corpus и переноситься
между plaintext corpora.

======================================================================
33. PARAMETER GRID
======================================================================

Для каждой family определить небольшой frozen grid параметров.

Не использовать continuous optimization against Voynich.

Например:

    state count = 2,4,8

    drift scale = 5,20,80

    grammar complexity = LOW/MEDIUM/HIGH.

Полный grid зафиксировать до запуска.

======================================================================
34. PARAMETER SELECTION
======================================================================

На DEVELOPMENT fingerprint разрешено:

    выбрать Pareto candidates.

Не сворачивать всё сразу в единственный weighted score.

Candidate должен улучшать несколько independent families.

======================================================================
35. DIRECTIONAL IMPROVEMENT
======================================================================

Для каждой metric определить заранее:

    target value
    baseline value
    desired direction.

Измерить normalized progress:

    Progress =
        (candidate - baseline) /
        (Voynich - baseline)

с корректной обработкой direction.

Не использовать без clipping diagnostics.

======================================================================
36. OVERSHOOT
======================================================================

Отдельно фиксировать:

    UNDERSHOOT
    TARGET_RANGE
    OVERSHOOT.

Механизм, который делает структуру гораздо сильнее Voynich,
не считать автоматически хорошим.

======================================================================
37. FAMILY-LEVEL SCORE
======================================================================

Для каждой conceptual metric family вычислить robust aggregate:

    median normalized progress

или другой preregistered robust statistic.

Не позволять сотне коррелированных dimensions одной family
доминировать над остальными.

======================================================================
38. PARETO FRONT
======================================================================

Основной model selection проводить по Pareto dominance.

Механизм A dominates B, если:

    A не хуже B по всем primary families

и:

    лучше хотя бы по одной.

Создать:

    MECHANISM_PARETO.tsv.

======================================================================
39. DEVELOPMENT GATE
======================================================================

Механизм проходит DEVELOPMENT gate, если:

1. улучшает минимум 4 independent fingerprint families;

2. не ухудшает катастрофически ни одну уже объясняемую family;

3. эффект переносится минимум на 2 из 3 plaintext corpora;

4. не зависит от одного seed;

5. не требует corpus-specific fitted parameters.

Exact thresholds preregister.

======================================================================
40. REPLICATES
======================================================================

Для stochastic mechanisms:

    минимум 30 replicates на DEVELOPMENT.

Для финальных candidates:

    минимум 100 replicates.

Хранить:

    mean
    median
    CI
    seed sensitivity.

Использовать authoritative Task58 token-order metrics.

Проверить:

    к слабой global token-order dependency Voynich.

Не использовать adjacent exact-repeat proxy.

======================================================================

Проверить positional glyph specialization.

Это один из главных discriminators constrained formation.

    d=1 giant component.

Особенно:

======================================================================
48. TASK62 TARGET
======================================================================

Проверить compatibility с token-formation fingerprint.

Не использовать Task62 Voynich-trained generator как candidate
transformation.

Task62 здесь является target characterization.

======================================================================
49. TASK63 TARGET
======================================================================

Проверить:

    adjacent near rate
    matched non-adjacent rate
    residual adjacency effect.

Механизм не должен создавать сильный copy/mutate signature,
которого нет в Voynich.

======================================================================
50. TASK64 TARGET
======================================================================

Проверить:

    broader local regime

и отсутствие специальной physical-line boundary,
где layout позволяет comparable test.

======================================================================
51. TASK65 TARGET
======================================================================

Минимум:

    local profile distance decay
    characteristic scale
    line boundary discontinuity
    page boundary discontinuity
    clustering/state evidence
    within-state drift.

Не требовать буквального K=5 reproduction.

Цель:

    topology class.

======================================================================
52. TOPOLOGY CLASSIFICATION
======================================================================

Для transformed corpora применять тот же classifier:

    STATIONARY
    CONTINUOUS_DRIFT
    DISCRETE_REGIMES
    MIXED_DRIFT_AND_STATES
    UNRESOLVED.

M7/M11 должны доказать, что способны породить MIXED topology
без прямого копирования Voynich parameters.

======================================================================
53. LAYOUT ISSUE
======================================================================

Natural plaintext corpora не имеют Voynich page/line layout.

Использовать два режима:

A. native/artificial neutral layout;

B. layout matched only по coarse counts:
       tokens per line
       lines per page

без использования token identities.

Результаты хранить отдельно.

======================================================================
54. LAYOUT-MATCHED RESULT IS SECONDARY
======================================================================

Основной mechanism result не должен зависеть только от
Voynich-matched artificial layout.

Если effect появляется только после layout matching:

    LAYOUT_DEPENDENT.

======================================================================
55. NULL — RANDOM STATE
======================================================================

Для stateful models создать control:

    same state frequencies

но state assignments shuffled.

Это отличает эффект state distribution от state trajectory.

======================================================================
56. NULL — FAST STATE
======================================================================

Для slow-drift mechanism:

    random/fast-changing state

с теми же marginal states.

Если local regime исчезает:

    evidence, что persistence state действительно создаёт topology.

======================================================================
57. NULL — FIXED STATE
======================================================================

Зафиксировать S constant.

Это показывает contribution именно evolution state.

======================================================================
58. NULL — RANDOM BOUNDARIES
======================================================================

Для generated grouping:

    randomized grouping

с той же output-length distribution.

Это отделяет:

    boundary distribution

от:

    state-dependent boundary rule.

======================================================================
59. CRITICAL TEST — STATE WITHOUT FORM GRAMMAR
======================================================================

Проверить:

    способен ли stateful mechanism без constrained token grammar
    воспроизвести Task59/60/61?

Ожидание не задавать.

Если нет:

    FORM_CONSTRAINT_REQUIRED.

======================================================================
60. CRITICAL TEST — FORM GRAMMAR WITHOUT STATE
======================================================================

Проверить:

    constrained token formation без evolving state.

Если воспроизводит Tasks59–62,
но не Tasks64–65:

    STATE_REQUIRED_FOR_LOCAL_TOPOLOGY.

Это потенциально очень важный decomposition result.

======================================================================
61. CRITICAL TEST — STATE + FORM
======================================================================

Если:

    G reproduces token-internal fingerprint

и:

    S reproduces local topology

а:

    G+S reproduces оба без разрушения Task58/63,

получаем сильную минимальную architecture candidate:

    STATEFUL_CONSTRAINED_ENCODING.

======================================================================
62. CRITICAL TEST — MACRO STATE
======================================================================

Проверить, нужен ли M сверх S.

Если:

    S alone -> CONTINUOUS_DRIFT

а:

    M+S -> MIXED_DRIFT_AND_STATES,

и остальные metrics сохраняются:

    MACRO_STATE_ADDS_TOPOLOGY.

Если K/state clustering возникает естественно без M:

    EXPLICIT_MACRO_STATE_NOT_REQUIRED.

======================================================================
63. CRITICAL TEST — TOKEN BOUNDARIES
======================================================================

Сравнить:

    WORD_PRESERVING

vs

    STREAM + GENERATED_BOUNDARIES.

Если только второй способен одновременно получить:

    positional specialization
    low h2
    dense edit geometry

без разрушения global metrics:

    GENERATED_ENCODING_UNITS_SUPPORTED.

Это НЕ означает, что Voynich tokens доказанно не являются словами.

======================================================================
64. INFORMATION RETENTION
======================================================================

Добавить простые tests зависимости output от plaintext.

Например:

    mutual information between coarse input/output features

или recovery accuracy там, где mechanism reversible.

Цель:

    отличить преобразование текста от генератора,
    который фактически игнорирует plaintext.

======================================================================
65. PLAINTEXT ABLATION
======================================================================

Критический control:

тот же mechanism запустить на:

    shuffled plaintext symbols/tokens

при сохранении marginal frequencies.

Если output fingerprint практически не меняется:

    PLAINTEXT_INSENSITIVE.

Такой mechanism нельзя считать свидетельством encoding natural text;
он скорее является independent generator.

======================================================================
66. PLAINTEXT SENSITIVITY CLASSIFICATION
======================================================================

Классифицировать:

    STRONG_INPUT_DEPENDENCE
    PARTIAL_INPUT_DEPENDENCE
    WEAK_INPUT_DEPENDENCE
    INPUT_INDEPENDENT.

Это обязательный результат каждого advanced mechanism.

======================================================================
67. ERROR ROBUSTNESS
======================================================================

Для лучших DEVELOPMENT candidates провести отдельный secondary test:

внести в transformed corpus случайные scribal-like errors:

    glyph substitution
    glyph deletion
    glyph insertion
    token boundary insertion/deletion.

Уровни, например:

    0.1%
    0.5%
    1%
    2%
    5%.

Проверить degradation fingerprint.

Не использовать robustness для model selection.

======================================================================
68. WHY ERROR TEST MATTERS

    объясняет только один conceptual family.

PARTIAL_MULTI_FAMILY

    улучшает несколько independent families.

BROAD_COMPATIBILITY

    улучшает большинство primary families и проходит transfer.

FINGERPRINT_OVERFIT

    development проходит, held-out нет.

PATHOLOGICAL

    приближается к Voynich ценой collapse/overshoot/expansion.

       REQUIRED / SUPPORTED / NOT_REQUIRED /
       DISFAVORED / UNRESOLVED;

26. явно перечислены свойства Voynich,
    которые ни один tested mechanism не объяснил;

27. никакой inverse/decryption search по Voynich не выполнялся;

30. никаких заявлений о дешифровке или найденном
    "шифре Войнича" не сделано.

Computational execution must support the existing distributed/process executor infrastructure. Every screening/development/final replicate must be representable as an immutable self-contained job (experiment_id, corpus, mechanism, config_hash, seed, evaluation_set). Workers MUST NOT perform model selection, parameter adaptation, Pareto selection, or access held-out targets. Aggregation/model selection remains coordinator-side. Local and distributed execution of the same manifest must produce statistically and artifact-equivalent results.
