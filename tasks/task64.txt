Task64 — Line-Level Form Regimes and Local Mixture Structure

Цель

Проверить гипотезу, возникшую из Tasks 60–63:

    основная локальная похожесть Voynich tokens может определяться
    не последовательным преобразованием

        T_i -> T_i+1,

    а существованием локального скрытого режима R, внутри которого
    выбираются token forms:

        R_line -> {T1, T2, ..., Tn}

    где при фиксированном R_line непосредственная зависимость
    соседних tokens может быть слабой.

Task63 показал:

    adjacent near rate       ≈ 0.05855
    matched non-adjacent     ≈ 0.05663

то есть residual adjacency effect после matching мал.

Одновременно Tasks 60–63 указывают на сильную line/local structure.

Основной вопрос Task64:

    Являются ли tokens внутри одной строки систематически более
    похожими по форме и распределению glyph features, чем matched
    tokens из других строк?

И если да:

    объясняет ли line-level regime большую часть локальной структуры,
    ранее наблюдавшейся как adjacent repetition / near-repetition?

НЕ предполагать, что line является семантической единицей.
НЕ делать выводов о предложениях, стихах, рецептах и т.п.
НЕ добавлять Stage29.
НЕ изменять Stages 1–28.

======================================================================
1. CORE HYPOTHESIS
======================================================================

Сравнить две модели локальной организации.

SEQUENTIAL:

    T_i depends materially on T_i-1.

LINE_REGIME:

    T_i ~ P(T | R_line),

    где tokens внутри строки имеют общее распределение форм,
    но conditional dependence соседних tokens после учета R_line
    невелика.

Также проверить альтернативу:

LOCAL_REGIME:

    режим существует, но его масштаб не совпадает с физической строкой.

======================================================================
7. WITHIN-LINE PAIR DISTANCE
======================================================================

Для каждой строки оценить расстояния между всеми или эффективно
выбранными парами tokens внутри строки.

Основные metrics:

    P(d=0)
    P(d=1)
    P(d<=1)
    mean edit distance
    normalized edit distance.

Не ограничиваться adjacent pairs.

======================================================================
8. BETWEEN-LINE MATCHED CONTROL
======================================================================

Для каждой within-line pair подобрать control pair из разных строк.

Matching минимум по:

    token length A
    token length B.

Предпочтительно также:

    same folio/page.

Основное сравнение:

    within same line

vs

    different line, same page.

Это PRIMARY TEST Task64.

9. GLOBAL MATCHED CONTROL
======================================================================

Дополнительно:

    different line, arbitrary page

с тем же length matching.

Это отделяет:

    line effect

от:

    manuscript-wide vocabulary geometry.

======================================================================
10. ADJACENCY STRATIFICATION
======================================================================

Within-line pairs разделить:

    separation = 1
    separation = 2
    separation = 3+
    all non-adjacent.

Главный вопрос:

    остаётся ли similarity внутри строки после исключения adjacent
    pairs?

Если:

    same-line non-adjacent >> between-line

это сильный аргумент за line regime.

======================================================================
11. PRIMARY CONTRAST
======================================================================

Вычислить:

    Δ_line =
        P(d<=1 | same line, non-adjacent)
        -
        P(d<=1 | different line, same page, matched).

Это primary estimand.

Не использовать adjacent pairs в основном Δ_line.

======================================================================
12. DISTANCE MATRIX VIEW
======================================================================

Для каждой достаточно длинной строки построить conceptual pairwise
distance matrix.

Не обязательно сохранять огромные matrices.

Агрегировать по:

    |i-j|.

Проверить:

    constant within-line similarity

против:

    decay with separation.

LINE_REGIME ожидает более плоский профиль.

SEQUENTIAL ожидает сильнейший эффект при k=1 с быстрым decay.

Не использовать exact token identity как основной feature.

14. FEATURE HOMOGENEITY

======================================================================
15. PSEUDO-LINE NULL
======================================================================

Создавать synthetic pseudo-lines той же длины.

Variant B:

    sample tokens from same page.

Variant C:

    preserve empirical token-length sequence.

Это позволит определить, насколько line clustering превосходит
ожидаемое из page vocabulary и length structure.

======================================================================
16. WITHIN-LINE SHUFFLE
======================================================================

Перемешивание tokens внутри строки сохраняет:

    line membership
    line token multiset

и уничтожает:

    order.

Сравнить authoritative Task60/63 metrics до/после shuffle.

Если большая часть local form effect сохраняется:

    line membership важнее order.

======================================================================
17. LINE-MEMBERSHIP SHUFFLE
======================================================================

Создать более сильный null:

    сохранить:
        number of lines
        tokens per line
        global token multiset

    разрушить:
        actual token-to-line assignment.

Это ключевой complementary null к within-line shuffle.

Если эффект исчезает:

    actual line membership содержит информацию.

======================================================================
18. PAGE-CONDITIONAL LINE SHUFFLE
======================================================================

Особенно важный null:

    перераспределять tokens между строками ТОЛЬКО внутри той же page,

сохраняя:

    page token multiset
    line lengths.

Он отделяет:

    LINE EFFECT

от:

    PAGE EFFECT.

38. POSITIVE LINE-REGIME CONTROL
======================================================================

Создать synthetic control:

    для каждой линии выбрать latent regime R;

    tokens внутри линии независимо генерировать из
    regime-specific distribution;

    между линиями менять R.

Важно:

    tokens должны быть conditionally independent given R.

Этот control должен создавать:

    same-line similarity

без обязательного:

    adjacent > non-adjacent same-line.

======================================================================
40. PHASE A–C CLASSIFICATION
======================================================================

NO_LINE_REGIME:

    same-line non-adjacent similarity не превосходит
    same-page matched control.

LINE_ASSOCIATED:

    same-line similarity выше same-page control,
    но real lines не отличаются от arbitrary local blocks.

PHYSICAL_LINE_REGIME:

    real physical lines устойчиво сильнее:
        same-page shuffled lines
        shifted blocks
        matched fixed windows.

BROADER_LOCAL_REGIME:

    clustering существует,
    но оптимальный/устойчивый масштаб шире строки.

Не строить глобальную O(N²) матрицу всех token pairs.

Использовать:

    line buckets
    page buckets
    length buckets
    Task60 edit indices
    deterministic sampling.

Permutation/replicate workloads отправлять через существующую
distributed/process executor infrastructure.

Не создавать новый scheduler.

======================================================================
68. DETERMINISM
======================================================================

При одинаковых:

    corpus
    design
    seed
    split

statistical artifacts должны быть byte-for-byte deterministic
кроме явно исключённых provenance timestamps.

70. TESTS
======================================================================

Минимум:

1. physical line extraction correct;
2. same-line pairs never cross line boundary;
3. non-adjacent excludes k=1;
4. same-page control never uses same line;
5. length matching exact where required;
6. global pseudo-lines preserve requested line sizes;
7. same-page pseudo-lines preserve page membership;
8. line-membership shuffle preserves global multiset;
9. within-page shuffle preserves page multiset;
10. within-line shuffle preserves line token multiset;
11. shifted-block boundaries deterministic;
12. distance metrics reproduce Task60;
13. Task63 adjacent rate reproduced;
14. discovery/replication pages do not overlap;
15. G-only negative control has no injected line regime;
16. synthetic line-regime positive control detected;
17. copy/mutate control distinguished from line regime;
18. same seed => identical artifacts;
19. insufficient line size => excluded/NOT_APPLICABLE, not crash;
20. preservation metrics reproduce authoritative Tasks58–62.

Выполнить:

    go build ./...
    go vet ./...
    go test ./...
    go test -race ./...
    git diff --check

======================================================================
DEFINITION OF DONE
======================================================================

Task64 завершён, когда:

1. same-line similarity измерена независимо от adjacency;

2. выполнен different-line/same-page matched control;

3. выполнен different-page matched control;

4. token-length confound контролируется;

5. within-line order и line membership экспериментально разделены;

6. выполнен page-conditional line-membership shuffle;

7. physical lines сравнены с shifted blocks;

8. physical lines сравнены с fixed local windows;

9. line/page/local-block scales непосредственно сопоставлены;

10. discovery effect проверен на independent replication blocks;

11. line-position/start/end effects проверены;

12. regime persistence между строками измерена;

13. Task62 G-only и Task63 copy/mutate controls обработаны тем же
    pipeline;

14. результат классифицирован:

        NO_LINE_REGIME /
        LINE_ASSOCIATED /
        PHYSICAL_LINE_REGIME /
        BROADER_LOCAL_REGIME;

15. adjacency residual повторно измерен после учета regime;

16. если regime подтверждён — frozen G+R проверена generatively;

17. проверено сохранение Tasks58–62 fingerprint;

18. определено, остаётся ли необходимость в отдельном S-process;

19. Stages 1–28 не изменены;

20. никаких выводов о семантике, языке, cipher key или дешифровке
    не сделано.
