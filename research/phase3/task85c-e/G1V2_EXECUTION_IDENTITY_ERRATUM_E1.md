# G1-v2 execution identity erratum E1

Scope: execution identity, blindness, escrow integrity, and run provenance only. V1.1 scientific semantics remain authoritative and unchanged.

## Boundary

G1V2-RNG-1 `CONTROL_GENERATE` determines each blind scientific corpus from the frozen generator, parameters, root/counters, and token count. Corpus bytes and `content_sha256` are computed before and independently of escrow, HMAC, `blind_id`, and JobID.

The scientific control identity is the G1V2-CJ-1 object containing exactly `generator_id`, `model_class`, `generator_parameters`, `scientific_rng_identity`, `token_count`, and `content_sha256`, hashed as `SHA256(ASCII "G1V2-SCIENTIFIC-CONTROL" || NUL || canonical_bytes)`. Its value is independent of escrow key and opaque ID bytes.

Escrow conceals and authenticates truth. `blind_id` is only an opaque execution identifier and escrow lookup key. JobID is a concrete run execution identifier bound one-to-one to the underlying scientific job inside that run. Different valid escrow keys may change blind IDs and JobIDs without changing the scientific experiment.

## Truth record and opaque ID

The closed truth record has schema ID `g1v2.blind-truth-record.e1` and exactly: `generator_id`, `model_class`, `generator_parameters`, `scientific_rng_identity`, positive integer `token_count`, lowercase `content_sha256`, and lowercase `scientific_control_identity_sha256`. `blind_id` is forbidden from its own HMAC input.

Serialize with G1V2-CJ-1. Let `R` be those canonical LF-terminated bytes. The HMAC message is:

`ASCII "G1V2-BLIND-ID" || NUL || u64be(len(R)) || R`.

The key is exactly 32 bytes generated by the operating system CSPRNG, independently of G1V2-RNG-1. `blind_id` is the first 20 lowercase hexadecimal characters of HMAC-SHA256. Store the full HMAC digest only in sealed escrow. If distinct canonical records collide after truncation, abort the entire blind-set materialization; never suffix or regenerate an ID.

Visible metadata contains only `blind_id`, `content_sha256`, and `token_count`. Sealed escrow binds the ID, full HMAC, truth record, and content hash.

## Errata preservation

R2-G01 remains closed: JobID binds scientific baseline `G1_V2_EXECUTABLE_CONTRACT_V1_1`. R2-G02 remains closed: `dependency_job_ids` is canonical. The historical `BLIND_ID` RNG row cannot influence scientific generation; it is retained as provenance and may only be used as an explicitly recorded non-normative diagnostic.

For execution-identity questions precedence is: V1.1 scientific semantics, then E1, then implementation, then historical conflicting examples. E1 cannot override scientific semantics.
